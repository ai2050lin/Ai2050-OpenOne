# CLT-20261117-v1 预注册：独立条件查找表

本设计在读取新模型结果前冻结。模型 Qwen3-14B 原始 BF16，CPU safetensors 读取、CUDA 分块计算；固定聊天模板、关闭 thinking、固定 Answer:\n。首轮执行范围为材料冻结、行为和原生采集试跑。后继自然发现、确认、机制干预有独立准入；本文件不声称已实现后继分析或完成实验。

## 核心命题与历史限制

旧材料生成器 source_binding_pointer.py 把两个档案的行序强制设为相反，r1=1-r0。旧“表”预测不能区分两项独立编码与一位加 XOR。新设计独立排列两块的实体，只换名字行序、槽位代码保持不动。名字、代码与标题物理顺序按家族配平。主要目标是原生状态保存什么及条件选择如何发生，不把外部正确公式当作已提取内部算法。

## 完整八格与条件顺序

以下给出演示家族的全部正文和查询。名字 Lina/Miro；槽位依次 red,blue,green,white。每个正文均有两个查询 b=0/1。

|表型|Orion 第0/1行|Vega 第0/1行|b=0 金答案|b=1 金答案|
|---|---|---|---|---|
|00|Lina:red / Miro:blue|Lina:green / Miro:white|red|green|
|01|Lina:red / Miro:blue|Miro:green / Lina:white|red|white|
|10|Miro:red / Lina:blue|Lina:green / Miro:white|blue|green|
|11|Miro:red / Lina:blue|Miro:green / Lina:white|blue|white|

每行记录实际句式 `Lina has code red.`。前导 `Two independent archives assign codes to the same entities. Return only the requested code word.`；标题 `Archive Orion:` / `Archive Vega:`。后置条件为 `Entity to look up: Lina\nArchive to use: Orion\nReturn only the code word.`，前置对照为 `Archive to use: Orion\nEntity to look up: Lina\nReturn only the code word.`，b=1 时换为 Vega。模型输入用真实 chat template 后追加 `Answer:\n`，不是手工模拟角色符号。各格完整文本、token IDs 和实体位置写入 *-materials.json；表内8格×前后顺序=16格/家族。

后置条件同表型的两种 b 在实体 token 结束处必须具有完全相同 token 前缀；这一位置不能使用未来 b。前置条件可能使用不同算法，分别报告，不强制共享机制。档案编号 b 指物理块；奇数家族交换 Orion/Vega 标题，避免把标题词等同物理块。四个槽位代码无重复且单token，独立抽样；不使用答案列表提示。名字按家族隔离，字符串新颖不声称预训练未见。

## 划分、暴露和统计

pilot 16家族/256输入，discovery 64家族/1024输入，confirm 128家族/2048输入；种子202611170501。完整八格均进入试跑，因此后续只声称新家族泛化，不声称11表型锁箱。所有材料运行前落盘哈希冻结。确认文件只有在发现候选冻结后才允许模型采集和分析。采集只读 pilot；不从确认选择层、坐标、阈值。多个输入/编辑不能算独立家族。

试跑行为门：每个(r0,r1,b,顺序)格，正确候选分数严格大于其他3个至少15/16，同时完整词表top1至少15/16；并列不算成功。确认行为门每格两项均>=95%。四候选分数和完整词表top1分别保存，当前口径不是完整自由生成。

正式配对比较规划：期待15个百分点差异、discordance=.25、双侧alpha=.025、128独立家族，调用tools/power_analysis.py计算n_required及power，必须pass。该功效仅适用于预先指定的家族代表题配对二值指标；不冒充多坐标发现或连续量的功效。发现筛选和小试跑不作正式显著性结论。确认的两个共同主要终点采用各97.5%家族bootstrap区间（10000次，固定seed）。

## 竞争解释及可区分预测

1. 一位加XOR：01/10可成立，00/11的两种b至少有一格预测错误；八格可否定这种固定算法，不能否定模型在不同表型切换策略。
2. 条件无关表编码：条件后置实体状态可预测r0和r1，两位都>=90%，联合>=85%；跨代码和标题映射仍成立。可解码只是候选，不是因果使用或必要性。
3. 已选结果：前置实体状态以所选r或代码为主；后置实体不可能知道未来b。后置行为正确不能单独否定前置采用预选算法。
4. 身份标记再查询：后续真实QK/OV需访问记录；实体处可解码行号也不能排除正文重查。必须对实际读者取证。
5. 两个答案缓存：代码置换影响承载物；解释需预测Value和下游读出。行位与代码必须解耦，不能凭一个探针判断。
6. 联合/分布式编码：单坐标失败允许原生小组或多个位置；若需要重新读取正文，不能声称单个名字向量闭合。

## 自然原生采集与编码标准

试跑保存实体末token、最终输入token的hs[0]及全部40块输出原生BF16位模式；B20/21/22的gate G、up U、真实down输入A全部17408单元。G/U/A从本次真实前向hook取得。所有后置b配对的实体全41边界应逐位相同；不一致停止并查输入对齐/浮点形状。该严格门可能因数值实现失败，不解释为未来信息可见。

发现阶段只在发现家族内选候选；先原生单坐标及最多32坐标/单元组，再与同层等预算随机组、名字/位置/代码基线比较。候选边界限于选择发生之前。线性ridge诊断alpha在{.01,.1,1,10,100}按家族5折选择；主张的紧凑解码器不得接入正文、b、答案或后层状态来读取r0/r1。需两位准确率>=90%、联合>=85%，且相对最强预注册非语义/随机基线联合准确率至少+10点、97.5%家族CI下界>0。否则不晋级独立表编码。四均值低秩和聚类不计验收。

## 原生选择机制标准与第二次冻结

本轮不预先假定选择发生于MLP或attention。候选必须先解释真实来源：逐项核对 alpha*V*O 写入、MLP SiLU(G)*U*down、残差及归一化；Q/K额外RMSNorm、RoPE与GQA保留。高精度重算允许误差须先由pilot原生算子校准后在发现分析前冻结，不能看确认结果后定容差。原参数完整复算只作对账，不算提取。

选择候选只能用操作前的实际输入；逐项登记允许使用哪些载体、位置与参数。冻结可执行小机制、所有索引、公式、预算、随机匹配和参数来源后才开启confirm。机制需同时满足：(a)实际行选择预测>=90%、胜最强同预算基线>=10点且CI下界>0；(b)关键自然写入/GUA预测MSE至少低于均值与随机组20%，家族CI下界>0；(c)有限原生阻断效果方向准确>=80%、超过随机对照，独立恢复将预先指定内部误差恢复>=80%，副作用另报。a/b为两主要终点；c作为单独冻结的因果确认，不借本轮功效自动宣称足量。候选不达标不执行扩大的干预。

禁止以A-B供体差向量作为机制对象或主要发现算法。允许原生计算项的定点阻断、局部参数预测及同次运行自身恢复；必须预先预测哪格变、哪格不变，设置同层等实际写入强度对照及sham。单点不影响最终答案时检查即时量与后续补偿，不能强行关闭其他路径后称自然必需。若需补充真实下游状态才能递推，明确为条件复算，不能算闭合。

## 失败决策

输入/哈希/数值门失败：停止科学判定，记录技术偏差，新代码另版绑定。
行为门失败：保留所有失败格，不平均掩盖，不在confirm改题；只记录模型行为范围，受影响内部机制确认不进入。
00/11失败而01/10通过：支持旧材料边界，不直接证明XOR，需错误分布与原生计算共同检验。
可读出但预测不超过基线：信息存在候选，未证实现机制。
自然预测通过、原生干预不支持：检查冗余与匹配剂量，不能晋级因果。
名字单位置失败、联合位置成功：缩小单向量主张，保留分布式机制。
全部候选失败：保留残差与未解释项，不自动扩大模型/语言/搜索，不把此结果写成不存在结构。
