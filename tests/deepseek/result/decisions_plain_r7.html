1 这个项目在干什么（大白话）

想搞清 LLM 内部到底怎么「存和用」语言概念（比如「苹果是一种水果」这类关系）。做法是不断做小实验， 每个实验叫一个 Phase，把结论拼成一张图。每做完就要下一个 判决（算不算成立、算不算新发现）。

体检结果：402 个 Phase、685 次判决，但只有 48 个不同的判决标签——大量重复； 397 个 Phase 里只有 26 个（6.55%）真的报告了「某个指标从 A 变成 B」，其余 93% 只是「我又做了一个实验」的目录条目。

这就是「无限 Phase 循环」：一直在产出局部特征，但攒不起来。 所以先停下来做体检（诊断 → 研究宪法 → 议程队列 → 四项零 GPU 检查），再决定要不要继续做实验。

2 三个「死线」是什么，以及它们为什么从来没响过

死线 = 事先写好的「如果出现这个结果，我就承认这条理论路线错了」。相当于给自己设的触发式否决条件—— 本来是防止自己骗自己的，结果它们被写成了永远不响。

死线原文条件（逐字）大白话状态
K13 模型 × 未见组合 的 logit 预测误差 > 5% 且不显著优于全加性基线 B4 3 个模型猜「没见过的组合」时错得都 >5%，而且都不比一个「只会做加法」的简单基线好 → 放弃「条件齿轮组 = 算子代数」（即：多个语义方向能像齿轮一样组合、有代数结构） 已重算

K3在 3 个模式族上，单坐标筛选 top-50 覆盖率均 < 30% 3 类模式里，靠单个坐标筛出的 top-50 覆盖率都 <30% → 放弃「单坐标机制」 从未被测量

体检发现的 3 个毛病（可逐条查证）

  • ① 合取（把门焊死）：K1 要求「所有模型都满足」，K3 要求「所有模式族都满足」。 而项目自己说「跨模型从不一致」⇒ 两支同时成立的概率被系统性压低。实测上面一层只有 1/3。
  • ② 自相矛盾（无法预先登记判决）：K2 在同一份文件里有两个互斥的「怎么算」—— 一份写「响应 cos 下降 >50%」，另一份写「交互份额 >50%」。两个量的单位和零假设都不同。
  • ③ 根本没有装置：K2 依赖的 3154 实验目录不存在；K3 要的「top-50 覆盖率」这个量全库都没有。
一句话：三条死线里，两条从未被测量，一条的触发条件写成合取。这就是「死线免疫」的完整病理。

为什么两个答案差这么多？因为「承诺层 k*」是提出这个理论的人自己挑的层（约 7–8% 深度处）。 用一个自己挑的层去检验自己的假设，很容易得到「我没错」的答案。换成模型真正说话的那一层，误差大了将近 7 倍。
所以：「用假设自己指定的层来判断假设」这件事，必须被显式接受或显式否决，不能默认。

决策 3 · I1 / I9：两条「制度条款」冻结吗？

I1 · 唯一全局 KPI
确认冻结：一个 Phase 未降低 E_read / E_ar(k) / C_steer 任一者，Ledger 登记为 catalog，不得登记为 advance。
大白话：一个 Phase 如果没有让 E_read（读出误差）这类全局指标变好， 就只能记成「目录」，不许记成「进展」。不许把「我又做了一个实验」当成绩。这条正是治「402 个 Phase 却攒不起来」的药。
I9 · 议程唯一来源
确认冻结：phase_queue_v1.json 为唯一议程来源，禁止由「残差 → 自动派生下一 Phase」生成新队列。
大白话：只能用预先冻结的那张 30 项队列（Q01–Q30）决定下一个做什么； 禁止「看到一个残差就自动派生下一个 Phase」——那正是无限循环的发动机。

选项：确认 / 修改（请给出改动）。
