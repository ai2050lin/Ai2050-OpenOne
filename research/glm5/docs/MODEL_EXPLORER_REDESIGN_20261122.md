## 一、混乱根因（一句话）

**三种模式在「研究对象」上是不同的东西，却被压进了同一个 `state{model,kind,block,index}` 定位器，且数学工具、着色、原生场在三处各写一套、互相隐藏。**

| 模式 | 真正的研究对象 | 当前被错当成 |
| --- | --- | --- |
| 实时模式 | **一段输入 + 一次前向**（观察点是附属） | 一个 Head/MLP 坐标 |
| 测试记录 | **一次已归档的运行**（对象是回查锚点） | 一个 Head/MLP 坐标 |
| 特征分析 | **一个具体的 Head/MLP 单元**（主角） | 一个 Head/MLP 坐标（唯一对上的） |

因为前两者被错配，所以出现：切模式时 `B26/H36` 不变、工具条不知该显示哪套、原生场到处开、特征分析退化成静态卡片。

---

## 二、重构总原则

1. **一屏一对象**：每个模式有自己独立的对象模型与定位器，互不共享 `kind/block/index` 语义。
2. **3D 场景始终共用，但定位语义随模式走**：实时模式点 3D 是"选观察位置"，特征模式点 3D 是"选研究单元"，记录模式点 3D 是"跳到该对象相关题"。
3. **统一观察工具条**：一条工具栏，按「当前对象类型 × 当前模式」动态给出可用工具，是数学工具的唯一入口。
4. **视图不互相隐藏**：原生场、递归泛化、SAE、Logit Lens 都是工具条里的"视图"，与控制台并存。全屏只是布局放大，不改模式归属。

## 三、三模式的目标结构

### 模式 A · 实时模式（输入驱动）

- **对象**：`{ 输入文本/样本, 生成步, 观察点集合 }`。
- **定位器**：输入框（自由文本或选历史样本）+ 生成步滑块 + "添加观察点"。观察点才是 `B26/H36`、`B36/U2429`。
- **工具条（按对象=输入 过滤）**：
  - 读出：原生读数、HiddenState 层间几何、Logit Lens、Tuned Lens
  - 几何：CKA / RSA、差向量投影
  - 归因：注意力分布、Head 写入分解、MLP 门控分解
- **着色**：在 3D / 原生网格上，按"当前观察点的激活值"着色（数值→颜色刻度，见第五节）。
- **主工作区**：输入 → 各层轨迹 → 选中观察点的多工具读数。

### 模式 B · 测试记录（运行驱动）

- **对象**：`{ 一次运行 run_id, 题目, 干预臂 }`。
- **定位器**：历史测试检索（题干/Phase/对象编号/模型/证据状态），选中一次运行。
- **工具条（按对象=运行 过滤）**：
  - 复核：逐题输出、配对差值、剂量/假操作/随机/恢复各臂
  - 回查：从某题跳到关联 Head/MLP（切到特征模式并带锚点）
  - 导出：JSONL / 回执核验
- **着色**：按"题目对错 / 干预效应方向"着色，不是按激活值。
- **主工作区**：运行摘要 → 逐题表 → 单题多臂对照 → 一键回查部件。

### 模式 C · 特征分析（对象驱动）★ 重点重做

这是用户诉求最强、当前最弱的一环。要从"静态 dossier 卡片"升级为"**动态特征分析器**"。

- **对象**：`{ 一个 Head 或 MLP 单元, 模型快照 }`，即 `B26/H36`、`B30/U9517`。
- **定位器**：直接输入原生编号，或从 3D 点选，或从测试记录回查带入。
- **工具条（按对象=单元 过滤）**：
  - 形态观察：神经元**按激活值着色**的网格视图、跨 token/跨样本的激活分布、正负端典型上下文
  - Goodfire 特征卡：激活统计、典型上下文、读/写方向在 unembedding 上的对齐、劈半余弦
  - **递归泛化机制**：该单元在**前后 layer** 的响应如何被复用/差异化——上游谁写入它、下游谁读取它、跨层轨迹叠加
  - 因果：匹配剂量阻断、仅恢复该单元、同输入恢复
- **着色**：核心诉求。**神经元按值显示不同颜色**（见第五节色标），支持整层 FFN 全景着色 + 单单元高亮。
- **主工作区**：单元身份卡 → 激活形态（着色网格 + 分布）→ Goodfire 特征 → 前后层递归泛化图 → 干预证据。

## 五、神经元着色规则（数值→颜色）

用户明确要求"神经元可以根据值显示不同的颜色"。统一一套色标，三处（3D 网格 / 原生场 / 特征形态图）共用：

- **发散色标**（激活有正负有零）：负值→蓝，零→中性灰，正值→红；按 `|z|` 或按当前层分位数归一。
- **顺序色标**（幅度/概率，如注意力质量、激活强度）：浅→深单色。
- 原始值与标准化值**双视图可切**，色标范围、归一方式、是否跨题共用上限都要在界面上标注（对应 AGENTS §4.5：不以 PCA/TopK 定义主干，保留低幅背景）。
- 着色是"显示设置"，改变画面不改变底层数据；分析工具读取的是有来源的记录，不是颜色。

## 八、需要你拍板的三个决策点

1. **特征分析的"递归泛化"视图**：你要的是 (a) 该单元跨层激活轨迹叠加图，还是 (b) 上游写入者→该单元→下游读取者的连接图，还是 (c) 两者都要？（这决定 `explorer-system-recursion.js` 的主视图）
2. **着色默认口径**：整层 FFN 全景着色默认用「原始值」还是「按层分位数标准化」？（影响第一眼看到的形态）
3. **实时模式的观察点**：是否允许一次前向同时挂多个观察点对比（如同时看 B26/H36 和 B28/H21），还是单观察点 + 快速切换？
