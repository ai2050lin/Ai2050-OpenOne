## 研究人员应能完成的事

**公众参与。** 实验管理首页提示任务来源、资源条件和上传范围。参与者主动开启后，节点按兼容模型和资源领取已冻结方案的分片，本机测试完成后上传，中心核对身份及版本，再按分片汇总。离线交互覆盖正常完成、停止、缺模型、没有匹配任务及中断续传。公开目录、实时队列与审核状态以受信中心为准。[参与界面](previews/client-distributed-testing.html)

**分析已有结果。** 研究者可直接从图谱探索选择测试。预览内置 Phase 2997 与 3008 两份中心回执对应的逐题文件，打开后绑定实际运行和模型快照，展示各干预条件的计数，并支持下载原始 JSONL。在正式客户端中，此路径需依当前权限下载选定运行修订的文件并核验后载入。不同模型和量尺须分开比较。

**组织系统测试。** 研究者从「系统测试方案」配置研究问题、模型、语言和家族分片大小，先核对覆盖与末片范围；「实验设计与草稿」可查找相似研究并复用已有结果。草案进入正式分发需完成中心查重、冻结文法、划分和准入检查。中心只合并相同冻结版本与模型快照下的有效分片。配对语言或模型上的同族材料保留同一划分身份，便于配对比较。日志、审阅与回执跟随实验，方向设计题与项目计划仍可从数据库方向树查阅。

研究者看到“模型答对了，某个头却选错”时，应能立即找到这些题，逐行查看这个头把注意力给了谁，转到在**同一批错位题**上测过的其他头，再核对对后者做过什么干预。研究者从一个 FFN 神经元出发，也应能反向找到测过它的题、所在单元组、个体测量、支持结果和失败结果。汇总的终点是一条别人可以逐题复核的主张。

首个验收案例沿用 GLM5 Phase 2983、2990、2997。两批五记录题在物理首行条件下，B26/H36 把正确行排第一的题数分别为 171/512 和 206/512；全模型首 token 答对 510/512 和 508/512。Phase 2990 中有 303 道模型答对而 H36 排错，另一个头 B28/H21 在这批题中排对了 301 道。Phase 2997 的因果实验另取 192 个家族，完整恢复这个头能恢复输出，只恢复选中的 128 个 FFN 单元则没有挽回答案优势。这里有两种数据关系需要明显标出：对同题换部件查看，以及在新材料上检验相关机制。单元 U17216 可以查到具体参数索引，当前证据止于组级恢复。

## 现有基础与改动边界

**客户端接入。** 实际工作台已提供总览和测试数据库两个标签，数据库使用随客户端提供的历史记录及中心现有的授权接口。已上传的逐题 JSONL 进入详情前按回执的长度和 SHA-256 核验。图谱成果库与实验记录可按运行 ID 跳转。逐题浏览按运行展开，目录检索沿用现有索引覆盖范围。全库逐题和部件索引、按入选条件汇总不同研究属于后续数据工程。

现有中心用 SQLite 记录查重、运行、上传与清单修订，用 SHA-256 寻址保存私有文件。客户端已有研究方向树、历史索引、中心运行与本地案例。Phase 3009 曾记录，中心能取回草莓与番茄的逐题结果，但按题中这两个物体查运行目录没有命中。眼下最值得做的是把**题目、部件和证据之间的查找关系**补齐。保留原始归档及旧入口，在其上增加可从清单重建的检索表。达到数据库扩容条件前，先用现有引擎量实际瓶颈。[归档实现](../../../shared/dist_protocol/test_archive.py) · [客户端入口](../../../frontend/src/components/v8/TestRecords.jsx) · [研究方向树](../../../frontend/src/components/v8/ResearchDirections.jsx)

## 研究保存契约

| 记录单位 | 最低保存内容 | 稳定定位和复用方式 |
| --- | --- | --- |
| 研究问题与设计题 | 知识网络、分析推理、语法体系的主树；叶子预设问题、典型题、相反预测、验收口径和状态。附语言、风格、组合操作、关系深度等交叉标签 | 方向 ID 和版本、设计 ID。多个方向可以引用同一测试。单列已设计、已执行、可复核、科学验收通过的覆盖数 |
| 冻结方案和材料 | 目标、原理、公式、替代解释、判定和失败动作；脚本、环境、模型与 tokenizer 哈希；家族和翻译/改写关系、发现/确认/锁箱、暴露时间、许可证；题干、送入模型的字节与 token、提示模板及答案集 | design SHA、材料版本、全局家族身份、case ID、输入哈希。相同的短题号须带上材料批次 |
| 运行、题目与评分 | 采集键、分析键、运行/重试/恢复父项、硬件与精度、脚本版本、配置、种子、停止原因；条件、实际生成 token、候选完整序列分数、错误类型、复评分数、必要日志 | run ID、清单修订 SHA、case、干预臂、生成步、评分器版本。同一生成由两种评分器评估时保留两条评分并标同源 |
| 原生读出与张量 | 模型，token 字符跨度和语义角色，层与零基索引、归一化前后、hook、生成步、位置、dtype、轴顺序、完整形状、量化和聚合方式 | artifact SHA、分块和行/切片。每个摘要给分母、筛选条件与完整数据入口；未采、已退役和权限限制各有状态 |
| Head | Q 头及共享 KV 组；源/目的 token，Q/K 边界、掩码、RoPE、注意力分数及质量、V 和 O 写入；逐角色累积、表外剩余量、上游输入与参数切片 | snapshot / block / head / channel / query / source。区分“看哪里”“写了什么”“输出用了多少”；共享 K/V 的组级影响明确记录 |
| FFN 原生单元 | 层、单元、适用的 expert，gate/up 投影与激活、down 列、当题写入；自然语料分布、激活与不激活例、按任务的选择性及匹配对照 | snapshot / block / unit / hook / position。分别给单元和单元组建身份，写清组成员、筛选集与冻结版本 |
| 关系、主张与反例 | 发送对象 → 途中残差/归一化 → 接收对象，时间和位置、具体通道、剂量、随机/假操作、恢复、旁路、区间与未解释效应。每种主张独立记录支持、反证、未测与技术无效 | edge ID、claim ID 和适用条件；每条证据指向运行修订、样本/家族或干预臂与数据切片。可以对同一条边保留相反结论 |
| 分析工作集 | 研究问题、选择的运行及修订、筛选与排除原因、分母和权重、方法/代码版本、复核者笔记、结果与导出清单 | 生成只读版本 ID。新分析引用原采集和上一个分析版本。个人筛选与正式科学登记有不同权限 |

**数学口径。** 在某一查询位置，把头对记录内各 token 的注意力相加得到该行质量。比较五个质量可找出头的首选行。将每个来源的 V 乘以注意力，再经该头的 O 切片才得到写入。对 SwiGLU，单元激活为 SiLU(gate) × up，写入为该激活乘 down 的相应列。前者是部件之间可能计算联系的入口，后者可核对到真实参数和数值。检验“下游使用了这份信息”还需匹配剂量的阻断、仅恢复候选接收端、完整恢复及目标行为测量。选图边的数据必须注明观察、原生算术、留出预测、原模型干预和独立复算分别到哪一步。

## 存放、归档和读取

1. **最低复核包长期保留。** 小型方案、清单、限制、结论用版本化 JSON，逐题文本与评分可用 JSONL；体量增大时用按运行和层分区的 Parquet 派生索引。原生张量沿用已落盘 NPZ 或适配可随机切片的分块格式，保留真实 dtype、轴及 SHA。模型标量以权重版本和切片定位，选用的值可随关键证据附包。旧格式通过适配器读，保留原字节。
2. **以协议归档。** 复用查重、登记、分块续传、finalize 和读回核验。成功、失败、中断都保留脚本、材料、逐题结果、必要日志和清单。用于关键结论的证据、重要原场和客户端应加载的切片上传中心；清单记录字节数、SHA、格式、来源、保留用途。技术校验、科学审阅和独立复算分别登记。合成数据留在工程沙盒。[归档协议](../../../deploy/README_TEST_ARCHIVE.md) · [协议客户端](../../../deploy/test_archive_client.py)
3. **本地大文件按用途管理。** Windows 使用 D 盘策略。可避免重测的全场或中间分片放在 `D:\ai2050_native`，登记依赖运行、预期复用、体积、最近使用和重建方式。只有已确认可重建且无人使用的临时件，才按清单清理。重要包上传失败时保留本地并续传。既有原场退役后若需重新跑模型，要在目录显示这一事实。
4. **把文件变成可查询的证据。** 中心在清单核验后解析允许的文件角色，生成 case、score、component、measurement、edge、claim、artifact_ref 和 family/exposure 关系；以“运行修订＋对象主键＋评分版本”幂等导入。缺少逐题文件的历史条目可检索标题及来源，显示可追溯深度。统计材料、运行、备忘条目时使用各自分母。索引重建在新版本完成引用和数量核对后切换，保留前版供回退。
5. **查询和权限。** 通过受保护的分页接口取目录、分面、聚合、案例、路径和小切片。中文词项/二元片段与英文词、部件别名并行检索，联合索引以模型、任务、读出、条件和研究状态为主。模型快照、单位或评分版本改变时拆开缓存。服务器对查询、自动补全、计数、切片、分享链接及导出执行相同权限。锁箱只显示允许公开的承诺；离线模式只读取明确授权的快照。缺件标出原因、回执与恢复入口。

## 跨测试综合的判定规则

| 资料关系 | 客户端动作 | 这次样稿中的对应例 |
| --- | --- | --- |
| 同模型/精度、自然读出、任务分母、评分口径、划分和条件，题族不重叠 | 展示每批 n/N 后，按预定权重合计。按题合计为 Σ正确数 / Σ题数。若需推断区间，保留独立家族为重抽样单位；存在共享实体或固定参照时标清条件 | 2983 与 2990 的三个规则逐一计算；示范物理首行的 377/1,024 与 1,018/1,024 |
| 同一采集或同一题被干预、重评分、翻译或多次上传 | 按来源去重；有配对则保留成对差异与共同分母。未知重叠只并列。一个家族的多道题保留对应簇 | 3008 首位候选与贪心续写，2990 的 303 个历史分歧例与 2997 的同题回查 |
| 研究问题相关，量尺、模块、快照、语言评分设计或干预不同 | 并排展示量尺、基线和范围，记录“可比较什么”；只在预先定义的兼容组内汇总。方向相反时保留异质性和反例 | 2997 的 logit 优势、3008 的同异实际答案、Claude 322 的 4B 双语候选评分 |
| 只有摘要、剂量不匹配或区域未测 | 标明缺件或技术限制；从图表可跳到失败原因和所缺证据 | 仅恢复 128 个单元没有恢复答案优势；U17216 单独干预待测；不能把组级结果登记为单单元的因果效应 |

完整版比较工作集固定兼容键、样本与家族重叠矩阵、纳入和排除清单、分母、effect 定义、区间方法、口径变更与基线。多运行不同任务的关联可以形成有价值的研究线索；升级为同一计算机制须事先预测新条件的输出/失败模式，比较匹配基线，并在原模型上区分替代路径。独立节点复算与同实验室新材料复现分别记录。

## 对标、实施和验收

借鉴部件可定位、样例可反查的导航。把图的计算、裁剪和呈现分开，为误差与残差留出位置。沿用运行日志能够展开到单个样本、评分和输入输出的做法。本项目还要做到从**失败的边或负结果**反查研究方向及对应题目。[Neuronpedia](https://github.com/hijohnnylin/neuronpedia) · [Circuit Tracer](https://github.com/decoderesearch/circuit-tracer) · [Inspect AI 日志查看器](https://inspect.aisi.org.uk/log-viewer.html)

1. **当前评审。** 离线原型只嵌入已开放历史资料，已展示的主例可以逐题操作。研究人员评审首屏问题、比较集选择、分歧题回查、部件入口和异口径提示。五项研究覆盖界面验收需要的几类证据，不能用来估计全库覆盖率。
2. **确认后接入只读索引。** 先用上述五案以及一个真实缺件旧案做迁移试点。验收每个数字能定位到清单与文件，旧索引不伪造题目，重复导入不增计数，服务器在线/断线/权限变化有一致行为。既有方向树和测试记录入口继续可用。
3. **开放研究工作集。** 提供按问题、部件、条件、失败类型查询和版本化保存。验收同题重评分不重计、不同模型同号头不误连、四/五候选不混池、未知重叠仅并列、对照失效可见。对单题反向跳转和长表分页做键盘、小屏和大批量检查。
4. **引入重分析与扩大覆盖。** 先给单题复算、条件分层、配对效应及家族区间，随后接入 Head/FFN 原场切片与组合路径。用固定的中英文、推理和语法验收题记录查询耗时、载荷、失败恢复与复核一致率，再决定并行度、列存与索引迁移；单独跟踪科学指标，包括未见家族的预报、相对简单基线的收益、失败类型和对照副作用。

**评审边界。** 静态稿使用本地只读快照，研究目录和组件选择器的覆盖小于完整数据库。本轮验收针对静态交互、展示数字及其来源。真实中心鉴权、全库检索性能、在线迁移、跨机独立复算与协作编辑需在正式接入后分别验收。
