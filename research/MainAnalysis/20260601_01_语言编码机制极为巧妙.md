# 一、核心假设

语言编码机制不是：

```text
一个概念 = 一个向量
一个功能 = 一个方向
```

而是：

```text
一个概念/功能 = 在整体关系网络中的位置 + 与其他节点的相对路径 + 被上下文激活的路径束
```

更准确公式：

```text
Meaning(x, c) = Position_in_Network(x, c) + Path_Bundle(x, c) + Relational_Delta(x, others)
含义 = 网络位置 + 条件路径束 + 相对差分
```

其中：

```text
x：词、概念、操作符或功能
c：上下文
Position_in_Network：它在整体关系网络中的位置
Path_Bundle：它激活的计算路径束
Relational_Delta：它和其他节点之间的差异关系
```

所以破解目标不是找 `apple direction（苹果方向）`，而是找：

```text
apple 与 banana、pear、fruit、tree、red、eat、sweet、object 的关系结构
```

也不是找 `not direction（否定方向）`，而是找：

```text
not 与 no、never、anti-、un-、opposite、false、exclude、contradict 的关系网络
```

---

# 二、测试对象要从“点”变成“关系图”

## 1. 建立多层关系网络

至少要构造 8 类关系：

```text
1. 同类关系：apple-banana，dog-cat
2. 上下位关系：apple-fruit，dog-animal
3. 属性关系：apple-red，banana-yellow，knife-sharp
4. 功能关系：knife-cut，key-open，translator-translate
5. 反义关系：happy-sad，open-closed
6. 否定关系：happy-not happy，possible-not possible
7. 操作关系：translate English，translate French，translate music style
8. 组合关系：red apple，not happy，must go，if rain
```

这样每个节点不是孤立词，而是有多种边：

```text
apple
├── same_class: banana, pear
├── hypernym: fruit
├── attribute: red, sweet
├── function: eat
├── location/source: tree
├── contrast: stone, tool
```

这才是整体编码网络。

# 三、核心实验框架

## Block A：全局关系保持测试

目标：测试模型内部是否保持人类语义关系网络。

做法：

先构造一个外部关系图：

```text
G_external
外部语义关系图
```

节点包括：

```text
水果、动物、工具、地点、动作、属性、逻辑词、操作符、翻译任务、句法角色
```

边包括：

```text
同类、反义、上下位、功能、属性、操作、作用范围、翻译关系
```

然后在每层提取模型内部状态，构造内部图：

```text
G_layer
模型第 l 层内部关系图
```

比较：

```text
G_external 和 G_layer 是否同构或近似同构？
```

指标：

```text
Mantel correlation（曼特尔相关）
Graph edit distance（图编辑距离）
Neighborhood overlap（邻域重叠）
Relative rank preservation（相对排序保持）
Subgraph isomorphism（子图同构）
```

核心问题：

```text
模型是否在内部保留了“苹果更接近香蕉而不是锤子”？
模型是否知道“not happy 和 sad 相关但不是同一个节点”？
模型是否知道“翻译英语”和“翻译法语”共享翻译操作，但语言路径不同？
```

如果成立，说明模型不是点编码，而是关系网络编码。

---

## Block B：复用-差异化矩阵

目标：直接测“哪些概念/功能共享路径，哪些分化”。

对任意两个功能 A、B，计算：

```text
Reuse(A,B)
复用程度

Difference(A,B)
差异程度

Conflict(A,B)
冲突程度
```

例如：

```text
Reuse(apple, banana) 高
Reuse(apple, hammer) 低

Reuse(translate English, translate French) 高
Difference(translate English, translate French) 中等
Conflict(translate English, solve math) 高

Reuse(not, never) 高
Reuse(not, sad) 中低
Difference(not happy, sad) 高
```

具体指标：

```text
1. 路径重叠：两者激活的层、head、MLP、残差方向是否重叠
2. 子空间重叠：两者因果子空间是否相交
3. patching transfer（激活替换迁移）：A 的方向能否在 B 任务中起作用
4. clean delta（清洁差分）：去掉共享部分后，剩下的差分是否决定功能
```

关键公式：

```text
v_A = shared(A,B) + delta_A
v_B = shared(A,B) + delta_B
```

如果：

```text
shared 很大，delta 很小但因果强
```

说明：

```text
模型用大路径复用，用小差分区分
```

这就是你说的巧妙平衡机制。

---

## Block C：关系操作代数测试

语言机制不只是关系图，还包含操作。

例如：

```text
not(happy)
translate(English → Chinese)
translate(French → Chinese)
make_past(go)
make_passive(dog bites man)
```

要测试模型是否形成了“操作代数”。

### 1. 否定操作

测试：

```text
not happy
not sad
not possible
not impossible
not all
all not
```

看是否满足：

```text
not(not X) ≈ X
not happy ≠ sad
not possible ≠ impossible，但相关
```

### 2. 翻译操作

测试：

```text
translate English sentence to Chinese
translate French sentence to Chinese
translate English style to formal style
translate music mood to words
```

分解：

```text
translation_core（翻译核心）
source_language_delta（源语言差分）
target_language_delta（目标语言差分）
modality_delta（模态差分）
```

核心问题：

```text
翻译英语和翻译法语是否共享 translation_core？
翻译音乐和翻译语言是否共享“跨表征映射”机制？
```

如果共享，说明模型有抽象操作路径。

### 3. 角色操作

测试：

```text
open as adjective
open as verb
light as noun
light as adjective
```

看模型是否把：

```text
token identity（词元身份）
role（角色）
construction（构式）
```

分离成可组合关系。

## Block D：子图迁移实验

这是最关键的因果实验。

不是测单个方向，而是测一个关系子图能否迁移。

例如水果子图：

```text
apple - banana - pear - fruit - sweet - eat
```

动物子图：

```text
dog - cat - horse - animal - alive - move
```

工具子图：

```text
knife - hammer - key - tool - use - cut/open
```

对水果子图提取：

```text
Fruit_Subgraph_Code
水果关系子图编码
```

然后测试：

```text
把 Fruit_Subgraph_Code 的共享部分注入 pear，是否增强 fruit-like 输出？
把 tool 的差分注入 apple，是否破坏 fruit 关系？
把 banana 的 delta 注入 apple，是否更像 banana 而不是 tool？
```

这比测一个词更强，因为它验证的是：

```text
关系网络是否可迁移
```

不是单点向量是否有效。

## Block E：整体路径束图谱

对每个输入，不只记录 hidden state（隐藏状态），而是记录完整路径：

```text
Path(x) =
{
  active heads,
  active MLP neurons,
  residual delta,
  Jacobian response,
  causal patch effect,
  output readout gain
}
```

也就是把每个词/功能表示成：

```text
路径束
```

然后比较路径束之间的关系。

例如：

```text
Path(apple) 与 Path(banana) 高重叠
Path(apple) 与 Path(car) 低重叠

Path(not) 与 Path(never) 高重叠
Path(not) 与 Path(sad) 低重叠

Path(translate English) 与 Path(translate French) 高重叠
Path(translate English) 与 Path(write poem) 中等重叠
```

最终形成：

```text
Path-Bundle Atlas
路径束图谱
```

中文：

```text
全局路径束图谱
```

这才是“编码即路径”的系统版本。

# 四、关键算法：共享主路径 + 差分路径分解

对每一组关系，比如水果组：

```text
apple, banana, pear, orange
```

做分解：

```text
Path(apple)  = Shared_fruit_path + Delta_apple
Path(banana) = Shared_fruit_path + Delta_banana
Path(pear)   = Shared_fruit_path + Delta_pear
```

对翻译功能：

```text
Path(translate English) = Shared_translation_path + Delta_English
Path(translate French)  = Shared_translation_path + Delta_French
Path(translate Music)   = Shared_cross_mapping_path + Delta_music
```

对否定：

```text
Path(not happy) = Shared_property_path + Not_operator + Scope_property + Delta_happy
Path(sad)       = Shared_emotion_path + Lexical_negative_delta
```

这能解释：

```text
not happy 和 sad 有关系，但不是同一个东西
```

因为它们共享某些情感/评价路径，但一个是操作符，一个是词汇负性。

# 五、最终要输出三张图

这个方案的目标不是得到几个表格，而是输出三张总图。

## 1. 复用图

回答：

```text
哪些概念/功能共享计算路径？
```

例如：

```text
apple-banana 高复用
not-never 高复用
translate English-translate French 高复用
must-should 高复用
```

## 2. 差异图

回答：

```text
哪些微小差分决定功能差异？
```

例如：

```text
apple vs banana 的差分是颜色/形状/味觉
not vs sad 的差分是操作符 vs 词汇负性
translate English vs translate French 的差分是源语言解析路径
```

## 3. 冲突图

回答：

```text
哪些功能共用路径但互相干扰？
```

例如：

```text
role 与 construction 在 DS7B 中冲突
O(not) 与 R(verb) 可能反向
antonym 与 negation 部分相关但不是同一路径
```

这三张图合起来才是整体编码机制。

# 七、判断标准

一个方案是否真正破解了整体编码机制，要满足 5 条：

```text
1. 能解释单词关系：apple-banana-fruit
2. 能解释操作关系：not、never、if、must
3. 能解释功能复用：翻译英语/法语共享什么
4. 能解释差异化：not happy 为什么不是 sad
5. 能跨模型比较：同一功能在不同架构中如何实现
```

如果只能解释某个词、某个方向，那还不是破解。

如果能输出：

```text
复用矩阵
差异矩阵
冲突矩阵
路径束图谱
关系保持曲线
```

那才是真正接近机制。

# 八、最终方案总结

你现在要做的不是继续测：

```text
某个词有没有方向
某个功能有没有方向
```

而是建立：

```text
全局相对编码图谱
```

核心算法是：

```text
1. 建立外部关系网络
2. 提取模型内部关系网络
3. 比较两者的拓扑保持
4. 分解共享路径和差分路径
5. 做子图级因果迁移
6. 建立复用、差异、冲突三张图
```

最核心公式：

```text
Code(x) = SharedPath(cluster) + DeltaPath(x) + RelationEdges(x, others) + ContextGate(x, c)
```

中文：

```text
编码 = 簇共享路径 + 个体差分路径 + 与其他节点的关系边 + 上下文门控
```

这才符合你说的：

```text
语言不是点编码，而是整个网络内部的相对关系编码。
```

一句话总结：

```text
破解语言编码机制的关键，不是找 apple 的编码，也不是找 not 的编码，
而是重建模型内部的关系网络：
哪些路径复用，哪些路径分化，哪些关系同构，哪些关系冲突，哪些微小差分被后续层高增益读取。
```

这就是下一阶段最应该做的系统测试方案。
