应该做热力图，但不能把“完成一张全模型 hidden-state 热力图”当成破解目标。

历史已经表明：

}

更好的目标是建立“语言模式族的条件因果图谱”：

\rightarrow
\text{因果干预图}
\rightarrow
\text{冗余/门控超图}
\rightarrow
\text{跨模式族复用—差分图}
\rightarrow
\text{训练形成图}
\]

热力图应当是第一层“侦察相机”，而不是最终理论。

## 一、对总体假设的判断

### 1. LLM部分恢复了语言背后的结构：合理，但尚未完全证实

LLM能够完成翻译、语法、知识调用、类比、风格控制和多步推理，说明训练确实形成了某种可组合的内部结构。

memo中的结果也支持：

- 不同任务存在相似的早—中—晚处理相位；
- query会改变被调用源信息的因果权重；
- 不同前端任务会汇聚到共享的晚层答案壳；
- K/V可以运输多token短语、词序、形态和EOS；
- 不同模型重复功能角色，但使用不同物理层和head。

因此，“训练恢复了一部分语言结构”是合理的工作假设。

但目前不能进一步断言：

- LLM恢复了语言唯一正确的数学结构；
- 人脑使用相同实现；
- 破解LLM就能直接破解大脑。

LLM机制可以提供大脑语言机制的候选理论，但仍需独立的神经科学证据。

### 2. “语言是模式集合”：方向正确，但定义过宽

如果“模式”包括所有知识、语法、推理、风格和上下文变化，那么任何现象都可以被称为模式，猜想就不容易被证伪。

需要把模式定义为可实验识别的对象：

> 在一组上下文变化下保持某种功能关系，并能通过特定干预被破坏、转移或救援的条件响应结构。

也就是：

\[
\text{模式}
=
\text{适用条件}
+
\text{角色关系}
+
\text{内部响应}
+
\text{因果作用}
+
\text{输出约束}
\]

这样“转折模式”“翻译模式”“对象—属性绑定模式”才能进行统一比较。

### 3. 相对编码：获得较多支持，但不能理解为静态概念图

历史确实反复否定固定编码：

- 固定跨层方向失败；
- 单个中层位置不能稳定运输完整状态；
- 相同功能在不同模型中落在不同层和head；
- query会改变source的因果作用；
- 同一概念在不同任务和语言中的执行方向会旋转；
- 共享的是控制壳和处理相位，而不是固定内容向量。

因此更准确的说法是：

\[
\boxed{
\text{编码是上下文和任务条件化的相对状态转移，而不只是静态关系位置。}
}
\]

“苹果相对于水果、食物、物体”可能只是其中一部分。模型还要编码：

- 当前句子里“苹果”是什么角色；
- 当前任务需要调用哪种关系；
- 当前候选答案是什么；
- 后续生成需要什么语法形式。

所以相对编码很可能是动态关系，而不是一张固定知识图。

### 4. 模式复用与最小差分：有证据，但“最优性”未证实

历史支持的复用包括：

- 跨任务共享的晚层答案壳；
- 跨模型重复的source→query→汇聚处理次序；
- 多种关系共享的控制结构；
- 不同内容使用相似的K/V运输角色；
- 多条冗余路径复用相同功能。

但“模型会用最少差异表达所有独特特征”“整体分布接近最优解”目前没有证据。

训练优化的是预测损失，而不是显式最小化模式差分。冗余、噪声、历史依赖和训练偶然性都可能留下并不最优的结构。

因此应将猜想改成：

> 训练倾向于产生可复用的功能骨架和条件化差分，但复用程度、冗余程度和效率需要实验测量，不能预设为最优。

## 二、为什么不能把“完整热力图”作为最终目标

### 1. 历史已经出现过热力图幻影

[Phase994](D:/AI2050/Ai2050-OpenOne/research/glm5/docs/AGI_GLM5_MEMO_20260805.md:34959) 找到了看起来连续的早—中—晚 hidden 轨迹。

但 [Phase998](D:/AI2050/Ai2050-OpenOne/research/glm5/docs/AGI_GLM5_MEMO_20260805.md:36976) 发现：

- 早层source patch可以100%改变答案；
- 中层query完整状态替换几乎无效；
- 中层也不能中介早层干预。

所以连续热区可能只是三个相关投影，而不是一条真正执行路径。

### 2. 热力图容易混合不同对象

一个强响应格子可能代表：

- 输入词面差异；
- 位置信息；
- query控制；
- 内容运输；
- 输出候选已形成；
- residual端点混杂；
- 模板和tokenizer差异；
- 任务难度；
- 数值尺度。

单纯颜色深浅不能区分这些原因。

### 3. 单点热力图看不到冗余

Phase1158证明，路径A、B单独删除都没有效果，联合删除才失败。

因此单组件因果热力图也可能显示：

```text
A：无效
B：无效
```

而真实结构是：

```text
A 或 B 均可独立完成任务
```

必须增加联合干预和超边分析。

### 4. 全语言热力图在原则上无法穷举

真实响应依赖：

\[
R=
R(\text{词汇、句法、语义、任务、query、上下文、位置、历史生成、模型状态})
\]

组合数量近乎无限。所谓“全模型完整热力图”只能是有限材料上的投影，不可能穷尽语言。

## 三、应该完成什么样的热力图

建议完成的不是一张图，而是六本相互约束的图谱。

### 1. 行为资格图

坐标：

\[
\text{模式族}\times\text{模板}\times\text{词汇世界}\times\text{模型}
\]

记录：

- 正确率；
- 候选margin；
- 自由生成；
- 最差cell；
- EOS和多token行为。

只有行为通过的单元才进入内部分析。

### 2. 角色—深度—组件响应图

坐标：

\[
\text{模式族}
\times
\text{角色位置}
\times
\text{深度}
\times
\{\text{residual, attention, MLP, Q,K,V}\}
\]

这就是改进后的响应热力图。它不使用绝对token位置，而使用：

- source；
- query；
- boundary；
- distractor；
- answer prefix；
- generated token。

其功能是发现候选处理相位。

### 3. 因果Patch图

每个响应热点都必须经过：

- 正确供体patch；
- 错供体；
- 错位置；
- 随机通道；
- 词面匹配负控；
- query/source正交世界；
- 自然重算。

记录的不再是 hidden 差异，而是输出因果效应：

\[
C_i=
Q(F(\operatorname{patch}_i(S)))-Q(F(S))
\]

### 4. 必要性—冗余—门控图

对候选组件测试：

- 单点删除；
- 双点联合删除；
- source+query联合干预；
- head group×depth矩形；
- 正确上下文与冲突上下文；
- 低阶充分路径组合。

得到的对象不是普通二维热图，而是因果超图：

\[
\{A,B\}\rightarrow Y
\]

它能表达“任何一条都充分”“两条必须联合”“只有特定query下才启用”等结构。

### 5. 模式族复用—差分图

这是项目最需要的新核心图谱。

对于模式族 \(F_a,F_b\)，比较：

- 是否共享处理相位；
- 是否共享source/query角色；
- 是否共享控制壳；
- 是否可以跨族patch；
- 正确族救援是否优于错误族；
- 哪些差异能因果决定输出；
- 未见组合能否由已知族组合预测。

复用不能只用余弦相似定义。应同时满足：

1. 匹配负控后响应相似；
2. 执行相同角色；
3. 可以进行有限跨族运输或组合；
4. 破坏后产生相同功能缺陷。

差分部分则应满足：

1. 对目标模式具有选择性；
2. 错误家族不能同样恢复；
3. 差异能够预测或控制具体输出。

### 6. 训练形成图

记录模式结构是怎样通过训练出现的：

\[
\text{训练状态}
\times
\text{更新事件}
\times
\text{模式族响应}
\]

需要测：

- 某种局部响应何时首次形成；
- 同一父状态的不同更新方向产生什么差异；
- 共享骨架与模式特异部分出现的先后顺序；
- 正确参数联盟能否选择性救援未来响应；
- 模式是否先记忆、后压缩、再复用。

这一步才真正接近项目所说的“可塑性原理”。

## 四、更好的整体方案：条件因果模式图谱

建议把项目的最终产物从“LLM全局热力图”改成：

\[
\boxed{
\text{语言模式族本体}
+
\text{条件因果模式图谱}
+
\text{模式形成动力学}
}
\]

每个模式族至少包含以下字段：

| 字段 | 含义 |
|---|---|
| 适用条件 | 什么上下文会调用该模式 |
| 输入角色 | source、query、对象、属性、边界等 |
| 行为约束 | 模式改变哪些输出 |
| 响应相位 | 早、中、晚层分别出现什么变化 |
| 运输载体 | Q/K/V、residual、MLP或其联盟 |
| 控制结构 | query如何选择该模式 |
| 必要路径 | 联合删除哪些结构会失败 |
| 充分路径 | 哪些局部状态可推动模式 |
| 冗余结构 | 有多少可替代实现 |
| 复用骨架 | 与哪些模式族共享功能结构 |
| 特异差分 | 什么内部差异决定该族独特功能 |
| 形成过程 | 训练中何时、如何出现 |
| 适用边界 | 哪些模板、语言、模型中不成立 |

## 五、模式族体系不应一次性手工穷举

“先建立完整语言模式族体系，再逐一破解”在实践上风险很高，因为人类预先划分的语言学类别未必对应模型内部类别。

更可行的是双向构建：

### 自上而下

从语言功能定义候选族：

- 对象—属性绑定；
- 分类和上下位关系；
- 时序关系；
- 因果关系；
- 否定；
- 转折；
- 比较；
- 指代；
- 翻译；
- 语法一致；
- 标点和边界；
- 风格；
- 推理操作。

### 自下而上

根据条件因果响应判断：

- 两个表面不同任务是否实际上共享一个骨架；
- 一个语言学类别是否包含多个内部机制；
- 哪些类别只能在特定query或上下文中形成；
- 哪些内部结构无法被现有模式标签解释。

最终模式族体系应由语言定义和模型因果结构共同修正，而不是完全预设。

## 六、最小计算单元和不变量应该怎样寻找

历史基本否定了这些候选：

- 单神经元；
- 单head；
- 单层；
- 单位置hidden向量；
- 固定跨层方向；
- 固定物理路径。

当前更好的候选是“条件因果响应单元”：

\[
U=
(\text{角色状态},
\text{上下文条件},
\text{干预响应},
\text{下游作用})
\]

寻找不变量的方法不是直接引入流形曲率，而是进行分裂与合并：

- 如果两个物理组件在所有登记干预下具有相同功能响应，可以合并为一个功能单元；
- 如果一个单元在不同query、模式族或上下文中产生不同因果响应，就必须拆分；
- 如果两个模式共享骨架但错误家族救援失败，则共享部分是复用结构，剩余部分是差分结构；
- 如果扩大干预登记表后原本相同的机制变得可分，说明旧不变量只是测量不足造成的等价。

Phase1200已经为这种方法提供了已知真值校准，但尚未在自然语言大型模型中完成闭合。

## 七、可行性判断

| 目标 | 可行性 | 判断 |
|---|---:|---|
| 制作全层hidden响应热力图 | 高 | 技术上容易，但科研价值有限 |
| 制作角色×深度×组件响应图 | 高 | 应该完成，适合作为候选发现入口 |
| 制作因果patch图 | 中高 | 可完成，但计算量较大 |
| 制作联合消融和冗余超图 | 中 | 组合爆炸，需要逐级筛选 |
| 建立十几个核心模式族因果图谱 | 中高 | 当前最合理的阶段目标 |
| 建立全语言完整模式图谱 | 低 | 不能穷举，只能逐步扩展 |
| 找到跨三模型完全相同物理路径 | 很低 | 历史证据明确不支持 |
| 找到跨模型功能不变量 | 中高 | 当前最值得投入的方向 |
| 从LLM机制直接推导人脑机制 | 当前很低 | 需要独立脑科学验证 |
| 建立可操作的语言条件计算理论 | 中 | 具备基础，但尚缺自然语言因果闭合 |

## 八、建议的阶段性路线

### 第一阶段：建立模式族实验标准

选择5–10个基础模式族，不追求全语言：

- 对象—属性绑定；
- 上下位分类；
- 转折；
- 否定；
- 翻译；
- 指代；
- 比较；
- 时序；
- 语法一致；
- EOS/边界。

每族统一角色、模板、负控、组合留出和行为门。

### 第二阶段：完成多面板热力图

对通过行为门的模式族制作：

- 响应图；
- Q/K/V图；
- 组件写入图；
- 输出候选图；
- matched-null图；
- 跨模型功能对齐图。

这一步只发现候选，不宣布机制。

### 第三阶段：完成因果闭合

对候选结构进行：

- patch；
- 删除；
- 联合删除；
- 阻断；
- 恢复；
- 正确/错误家族救援；
- 自由生成；
- 新词汇和新模板复验。

### 第四阶段：建立复用—差分矩阵

回答四个核心问题：

1. 哪些模式共享控制壳？
2. 哪些模式共享运输骨架？
3. 哪些差分决定模式独特性？
4. 哪些模式能够组合成未见过的新模式？

### 第五阶段：分析训练形成

在微型Transformer中获得已知真值和训练轨迹，再把已经校准的方法迁移到较大模型的持续训练或微调过程。

### 第六阶段：建立预测和控制能力

真正的理论不能只解释已有结果，还要能够：

- 预测一个新模式会使用哪些功能阶段；
- 预测破坏哪些联盟会出现什么错误；
- 用小规模干预选择性修改某种模式；
- 保持其他模式基本不变；
- 预测训练材料如何改变模式复用和差分。

只有达到这一层，才接近“智能理论”，而不仅是内部图谱描述。

## 最终结论

应该做热力图，但应停止追求“一张完整的全模型热力图”。历史已经证明，原始 hidden 热区很容易形成虚假线程、端点混杂和固定坐标幻觉。

更好的方案是：

\[
\boxed{
