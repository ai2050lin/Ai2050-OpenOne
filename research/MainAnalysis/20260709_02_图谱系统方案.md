提问：
要完成  语言模式族图谱， 当前路线是否合理，有哪些可以改进的地方，  能不能完成一个系统方案，  根据系统方案完成，而不是每次完成一小步， 效率低质量差。
另外给出图谱的可视化客户端的修改方案， 包括图谱的数据格式，以及客户端的显示方案，方便查看研究。


回答：

当前路线**方向是合理的，但执行方式需要升级**。

现在的问题不是理论错，而是研究被拆成太多 Phase 小步：每次跑一个局部测试、写一段总结、再临时决定下一步。这样会导致效率低、数据格式分散、可视化只能看表格，最后很难形成真正的“语言模式族图谱”。

我建议从下一阶段开始，不再按“小 Phase 试探”推进，而是冻结一个系统工程方案：**Pattern Family Atlas v2（语言模式族物理路径图谱 v2）**。

**总判断**

当前路线应该继续：

```text
语言模式族样本库
-> 行为/读出基线
-> 层路径追踪
-> 组件路径追踪
-> 因果必要性审计
-> 补偿路径审计
-> rollout/闭合验证
-> 图谱固化
```

但要改进为批处理系统，而不是每次只完成一个局部实验。

当前已经完成的部分：

```text
pattern_family_atlas: 约 0.90
physical_path_atlas: 约 0.39
component_path_atlas: 约 0.20
causal_closure: 约 0.18
```

说明“语言族分类和样本框架”已经不错，但“内部物理路径、组件因果、补偿路径、闭合验证”还不够。

**系统方案**

目标不是马上闭合，而是完成一张可查询、可比较、可复测的图谱：

$$
Atlas(f,m)
=
[
Cases,
Behavior,
Readout,
LayerPath,
ComponentPath,
CausalAudit,
CompensationPath,
Rollout,
Closure
]
$$

其中：

- $f$ 是 pattern family（语言模式族）；
- $m$ 是 model（模型）；
- 每个语言族、每个模型都要有同一套字段。

建议固定九大语言模式族：

```text
content_knowledge
output_protocol
reasoning_constraint
syntax_structure
language_action
cross_lingual
readout_competition
state_drift
closure
```

每个族至少做四类样本：

```text
base: 正常样本
protocol: 输出协议变体
boundary: 边界/停止变体
perturbation: 干扰/反例样本
```

每个样本都走完整流水线：

```text
1. behavior scan
2. readout competition scan
3. layerwise residual trace
4. attention / MLP component attribution
5. causal necessity audit
6. compensation path audit
7. rollout verification
8. closure scoring
```

这样一次实验就不是“测一个现象”，而是把一个样本的完整路径打通。

**核心评分公式**

每个样本最终生成一个统一分数：

$$
Score(x)
=
w_1 B(x)
+
w_2 R(x)
+
w_3 L(x)
+
w_4 C(x)
+
w_5 I(x)
+
w_6 G(x)
+
w_7 K(x)
$$

其中：

- $B(x)$：behavior score，行为是否符合目标；
- $R(x)$：readout score，读出竞争是否清楚；
- $L(x)$：layer path score，层路径是否稳定；
- $C(x)$：component path score，attention/MLP/residual 组件路径是否清楚；
- $I(x)$：intervention score，因果干预是否支持；
- $G(x)$：generation rollout score，生成轨迹是否稳定；
- $K(x)$：closure score，是否真正闭合。

图谱完成度不再用主观判断，而是：

$$
AtlasCompletion(f,m)
=
\frac{
\sum_{x \in X_{f,m}} Score(x)
}{
|X_{f,m}|
}
$$

这样每个语言族、每个模型都能横向比较。

**下一步应该怎么做**

我建议 Phase270 不要只是“MLP compensation audit”单点测试，而是升级为一个总控任务：

```text
Phase270-280: Pattern Family Atlas v2 System Build
```

分成四个批次：

```text

Batch C: 组件因果和补偿路径审计

具体任务：

```

重点是：  
后续每个 Phase 都服务于同一个系统，不再临时造表、临时造字段。
