# 单类别复用差分编码恢复算法

> 时间：2026-07-18 00:47（America/Adak）
>
> 证据边界：本文件只审计现有结果并冻结下一轮算法，没有运行模型、没有读取密封集、没有新增机制证据。

## 一、总体判断

用户提出的方向总体正确，而且比继续扩大九族图谱或继续追求闭合更接近当前真正的瓶颈。

正确的部分有四点：

1. 破解知识编码的关键，不只是找到“苹果相关神经元”，而是区分同类对象共享了什么、每个对象保留了什么差异、属性内容在哪里、对象与属性如何绑定。
2. 当前参数量和活动量巨大，直接扫描全模型会产生海量高分候选，却很难区分共同架构、答案身份、词元表面和真实知识结构。
3. 早期扩大水果样本和知识图谱，增加了客观覆盖，却没有解决“语言结构与物理计算事件如何对应”的算法问题。
4. 暂停闭合、暂停统一理论、暂停全网单神经元扫描，把目标收缩到一个类别，是当前最合理的研究收缩。

但需要修正两点：

1. 破解水果类别不会自动让语法和推理迎刃而解。它首先能验证一套“参数化知识如何被检索、差分、绑定和读出”的恢复方法；该方法能否迁移到语法和推理，仍需以后独立验证。
2. “苹果如何编码”不是一个脱离任务的静态问题。更准确的问题是：当模型在某个查询、上下文和生成时刻处理苹果时，哪些参数支持被调用，哪些运行事件表示类别共性，哪些事件保留对象差异，哪些事件选择属性并把属性绑定到苹果。

因此本阶段唯一目标应冻结为：

```text
恢复一个水果知识查询从对象进入、类别复用、对象差分、属性选择、对象－属性绑定到答案读出的最小因果事件图；
然后只在这条事件图内部定位实际使用的参数支持。
```

这不是闭合，也不是完整智能理论。它是判断当前项目是否真正具备“从行为恢复编码规则”能力的最小实验。

## 二、历史结果对这个方向的支持与否定

### 1. Phase301-304（阶段301-304）

当时建立了20个对象、8类属性、507条三模型测试计划，并观察到：

```text
类别任务相对最稳定；
颜色和味道相对可用；
形状、用途和差分对比很弱；
柑橘、浆果、热带和树果对象在修正矩阵中出现同类聚集。
```

但这些结果主要来自行为和读出相似度。Phase303（阶段303）已经发现：两个对象都答错，也会产生假高复用。Phase304（阶段304）又把研究者预先写入的类别和子类标签加回复用分数，因此该矩阵不能作为内部共享编码的独立证据。

可保留的是样本库和“水果是合适的最小研究对象”，不能保留“共享主干已经破解”的结论。

### 2. Phase305-309（阶段305-309）

三位置路径图谱观察到：

```text
同类对象对的轨迹相似度高于差分控制；
查询位置和最终位置的区分比对象入口更清楚；
注意力和多层感知机都参与；
颜色的共享／差分区分很弱。
```

这说明知识查询不是单纯在对象词元处读取一个固定向量，后续查询路由和答案聚合同样重要。

但该阶段比较的是逐层边际轨迹相似度，没有证明这些相似轨迹对行为必要，也没有排除共同架构、答案身份和模板的影响。

### 3. Phase379（阶段379）

共有骨架审计发现，未经去混杂的轨迹几乎全部高度相似；去除模型和观测轴共有骨架后，跨模型功能残差明显下降。

这直接证明：

```text
“苹果和梨的路径很像”不能直接解释为它们复用了水果编码；
它们也可能只是经过了同一个Transformer（变换器）架构、相同位置和相同输出接口。
```

### 4. Phase393（阶段393）

三个模型都确认属性位置的内容状态可以被后续网络使用，72个方向中71个能改变属性答案。

但错误深度在72个方向中同样全部有效。这说明已确认的是“属性内容可搬运”，不是“自然属性形成位置”或“苹果－红色绑定规则”。

### 5. Phase394-399（阶段394-399）

后续实验反复说明：

```text
内容状态、结构路线、绑定规则和输出接口必须分账；
相同词元集合不等于相同绑定；
稳定关系签名不等于可单独搬运的关系状态；
动态联合轨迹存在，但不能压缩成单个静态查询状态。
```

### 6. Phase519-553（阶段519-553）

自然关系、成对地址、九族行为和全层路线校准进一步证明：

```text
模型可以在某些合同下稳定答对；
角色、查询和路线信号可以稳定出现；
但具体实体配对身份经常丢失；
答案身份、表面形式和共同架构足以制造大量伪候选；
Phase551（阶段551）的1053个候选在完整因素校准后全部撤销。
```

所以，水果方向不是重新启用旧相似度图谱，而是要把旧水果样本放入更严格的因果恢复算法中重新测试。

## 三、过去一直没有破解的核心原因

### 1. 研究对象定义错了

过去经常寻找：

```text
水果向量；
苹果方向；
属性层；
关系神经元；
高相似路径。
```

这些都是预先假定的物理形状。模型真实使用的单位可能是一个依赖对象、查询、关系、位置和生成时刻的事件块，而不是固定向量或固定神经元。

### 2. 把知识存储和知识运行混在一起

参数主要保存长期能力，激活主要表示当前输入下被调用的计算。

现有研究大部分追踪激活，却希望直接回答“知识如何存储在参数中”。这中间缺少一步：

```text
先恢复当前知识查询实际使用的因果运行路径；
再沿这条路径定位真正参与计算的权重、通道和注意力连接。
```

没有运行路径约束，直接分析全部参数几乎必然淹没在无关结构中。

### 3. 以表示相似代替功能相同

两个轨迹相似，可能因为：

```text
使用相同模板；
位于相同位置；
答案词相同；
经过相同归一化和残差骨架；
都失败；
都接近输出接口。
```

只有当删除同一类事件造成同一种功能损伤、正确恢复能够修复、错误对象或错误属性不能修复时，才有资格称为功能复用。

### 4. 没有把四种信息拆开

水果知识至少包含四本账：

```text
类别账：苹果、梨、香蕉都属于水果；
身份账：苹果不是梨，也不是香蕉；
属性内容账：红色、黄色、酸、甜、果核、果皮等内容；
绑定账：红色属于当前苹果，而不是同句中的香蕉。
```

旧实验通常同时改变其中两项或三项，因此高分信号无法解释。

### 5. 搜索方向反了

过去从全网寻找高分节点，再尝试解释它们。参数越多，偶然高分和共同骨架候选越多。

更有效的方向是：

```text
从已经确认的正确答案事件出发；
只沿真实计算图的父边向上追；
每次验证哪一组父事件是必要的；
只展开通过因果门的父组。
```

这样搜索空间由“全模型所有神经元”缩小为“当前正确行为实际使用的父事件树”。

## 四、这次到底要破解什么

### 1. 不寻找静态的“水果区域”

本轮要恢复的是一次知识查询的运行脉络：

```text
对象识别
-> 查询关系选择
-> 类别或属性内容被调用
-> 对象与内容保持正确绑定
-> 候选答案竞争
-> 最终输出
```

### 2. 五类事件必须分开记录

| 事件类型 | 要回答的问题 | 不能混入的内容 |
|---|---|---|
| 对象身份事件 | 当前对象是苹果还是梨 | 类别答案、颜色答案 |
| 类别共享事件 | 当前对象是否被按水果处理 | 具体水果身份 |
| 属性内容事件 | 红色、酸、果核等内容是否可用 | 内容属于谁 |
| 绑定事件 | 当前属性属于哪个对象 | 单纯的属性词出现 |
| 查询和读出事件 | 当前要回答类别、颜色还是味道 | 上游知识形成 |

### 3. “复用”与“差分”的操作定义

复用不是轨迹看起来相似，而是：

```text
同一类父事件在多个水果、多个表面和多个答案中都对类别功能必要；
删除后主要损伤类别判断；
用另一个水果的对应事件恢复时可以修复类别功能；
错误类别对象的事件不能同样修复。
```

差分不是两个向量的距离，而是：

```text
改变对象身份或属性时，某个父事件的因果后果随之改变；
该变化可以预测苹果与梨、红色与黄色或果核与果皮的区别；
同时不破坏已经确认的水果类别功能。
```

绑定不是看到对象和属性都活跃，而是：

```text
在词元集合、答案集合和查询不变时，只交换对象－属性配对；
候选事件必须跟随配对关系变化；
正确配对恢复有效，错误配对恢复无效。
```

## 五、算法：水果类别复用－差分因果追踪

算法保持描述性，不引入新的理论名称，不先拟合复杂公式。

### 阶段A：建立两个互补世界

#### A1. 自然知识世界

用途是研究参数中已经学习的熟悉知识。

冻结18种常见水果，分为6个子类，每个子类3种：

```text
仁果／树果：apple、pear、quince；
柑橘：orange、lemon、lime；
浆果类：strawberry、blueberry、raspberry；
热带：banana、mango、pineapple；
核果：peach、cherry、plum；
瓜类：watermelon、cantaloupe、honeydew。
```

同时冻结12个匹配控制对象：

```text
与水果同属食物但不是水果；
与水果颜色相同但类别不同；
与水果形状相近但类别不同；
与水果共享“可食用、植物、圆形、甜”等局部属性但整体类别不同。
```

有争议的番茄、黄瓜、坚果不进入主分母，只进入边界压力集。

自然属性只保留五类：

```text
类别；
子类；
典型颜色集合；
典型味道集合；
典型部件集合。
```

颜色和味道允许多个正确值，不把苹果强制压成唯一“红色”。用途、风格化描述和地区性答案不进入核心分母。

#### A2. 受控上下文世界

用途是分离对象、类别、属性和绑定，不用于声称参数中预先存有虚构实体。

每个世界包含：

```text
两个实体；
两个类别标签；
两个属性值；
两种对象－属性配对；
一个固定查询；
相同词元多重集的顺序交换版本。
```

每个世界产生16个因素单元，只改变：

```text
对象身份；
类别身份；
属性值；
绑定配对。
```

表面改写、句序和答案顺序作为独立重复，不与这四个因素混成同一分母。

### 阶段B：冻结样本规模和留出

受控上下文世界：

```text
发现集：96个独立世界；
确认集：96个独立世界；
密封集：96个独立世界；
每世界16个因素单元。
```

自然知识世界：

```text
18种水果加12个控制对象；
5种关系；
4种自然表面；
2种句序或查询顺序；
每个模型1200条自然行为案例。
```

三个模型的总行为注册约为17424条。模型按 Qwen3（通义千问3）、GLM4（智谱GLM4）、DS7B（深度求索7B）顺序串行执行。

发现、确认和密封按完整实体、属性组合和模板族切分，不允许同一基础世界通过改写同时进入不同分割。

### 阶段C：先做行为资格，不合格不采内部状态

每个模型单独判断，不要求三个模型使用完全相同的自然提示。

行为账同时记录：

```text
自由生成是否表达正确语义；
首个候选分叉处正确答案是否领先；
表面改写是否稳定；
句序交换是否稳定；
答案顺序交换是否稳定；
模型是否忽略受控上下文而回退到常识；
解析是否完整。
```

行为失败的模型－合同单元停止，不以内部高分补救行为失败。

### 阶段D：方向保真地记录真实运行事件

只对行为合格单元记录：

```text
所有层的层输入、注意力输出、多层感知机输出和层输出；
对象、属性、关系、查询和当前生成位置；
注意力来源到接收位置的真实写入；
多层感知机通道组的有符号写入；
完整候选词表边距；
提示结束、查询完成、答案首次分叉、答案完成和停止事件；
每个事件在计算图中的合法父事件。
```

不把不同词元长度的绝对位置直接对齐。跨表面只比较语义角色和事件顺序。

### 阶段E：建立四本因素差分账

对每个事件分别建立：

```text
只改变类别时发生什么；
只改变对象身份时发生什么；
只改变属性值时发生什么；
只交换绑定时发生什么；
两个或多个因素同时变化时是否出现协同、抵消或补偿。
```

保留完整有符号事件，不立即压缩成范数、余弦、主成分或一个综合分数。

观察分数只用于安排干预顺序，不能用于命名机制。

### 阶段F：从正确答案向上游反向追踪

搜索起点是已经行为合格的终端语义事件。

每一轮只做以下操作：

1. 找到当前事件在真实计算图中的直接父组。
2. 分别删除注意力父组、多层感知机父组和来源位置父组，让后续网络自然重算。
3. 测试同案例自然恢复，确认干预工具本身可以恢复基线。
4. 使用只改变一个因素的匹配供体恢复。
5. 使用错误对象、错误类别、错误属性、错误绑定、错误时间、错误深度和同规模随机供体作为控制。
6. 记录目标行为、非目标水果知识、普通语言输出和数值稳定性。
7. 只展开表现为必要或联合必要的父组。

如果两个父组单独删除都不影响行为、联合删除才影响，就保留为联合块，不再强行按单点分数拆开。

### 阶段G：用功能响应而不是表示距离决定是否相同

每个候选父组都保存一张响应卡：

```text
删除后类别判断是否损伤；
删除后对象身份是否损伤；
删除后属性内容是否损伤；
删除后绑定是否损伤；
正确恢复修复了什么；
错误恢复是否也能修复；
非目标知识和语言能力是否保持；
作用是否跨水果、跨表面和跨答案重复。
```

两段内部活动只有响应卡近似相同，才归为同一种功能事件。隐藏向量相似只能作为辅助描述。

### 阶段H：运行路径通过后才进入参数层

这是本算法相对过去最重要的补充。

#### H1. 注意力路径

只检查已通过因果门的注意力事件：

```text
哪个查询位置选择了哪个来源位置；
选择是否跟随类别、对象、属性或绑定变化；
值写入携带的是内容、角色还是答案接口；
屏蔽对应头或来源边是否产生预测的功能损伤；
错误来源是否不能恢复。
```

#### H2. 多层感知机路径

只检查已通过因果门的多层感知机事件：

```text
哪些通道组在当前水果查询中产生主要有符号写入；
哪些组跨水果重复承担类别功能；
哪些组随苹果、梨、香蕉身份变化；
哪些组随颜色、味道或部件关系变化；
组删除、组恢复和错误组恢复是否符合响应卡。
```

#### H3. 参数支持图

参数层只输出三种结论：

```text
共享参数支持：跨多个水果重复参与同一类别功能；
差分参数支持：随对象或属性变化并保持类别功能；
绑定参数支持：只在对象－属性配对改变时改变因果后果。
```

不要求一个神经元只保存一个概念。一个通道可以参与多个功能；最终单位可以是协同通道组或注意力边组。

### 阶段I：未见水果和重新组合验证

算法必须在没有用于找候选的水果上作出预先预测：

```text
哪些事件属于类别共享部分；
哪些事件应该随对象身份改变；
哪些事件应该随属性关系改变；
交换绑定后哪条路径应该跟随新配对；
删除共享部分是否损伤所有水果类别判断；
恢复差分部分是否只修复对应对象或属性。
```

只在已见水果上解释高分，不算破解编码。

受控上下文与自然知识若出现相同的功能事件拓扑，可以提升为“检索和绑定过程可能复用”；若拓扑不同，则应分别登记参数化知识检索和上下文临时绑定，不能强行合并。

## 六、什么结果才算破解了一个类别

不再使用“有一张相似度图”作为成功标准。

必须依次通过以下九道门：

1. 行为门：模型在冻结表面、顺序和答案控制下稳定完成水果任务。
2. 分账门：类别、身份、属性和绑定四类效应可以在匹配世界中分别观察。
3. 父边门：候选位于终端事件的真实计算父链上。
4. 必要门：删除候选会造成预先指定的功能损伤。
5. 恢复门：同案例恢复和正确因素供体能够修复损伤。
6. 排他门：错误对象、属性、绑定、时间和随机供体不能同样修复。
7. 保真门：目标功能改变时，非目标水果知识和基本语言行为大体保持。
8. 未见门：同一事件图在未见水果、未见表面和未见属性组合上重复。
9. 参数门：运行事件可以下钻到实际使用的注意力边组或多层感知机通道组。

达到前八门，可以称为“水果类别的运行编码机制候选”。

达到第九门并通过密封集，可以称为“水果类别的参数支持与运行机制已得到模型内验证”。

仍不能由此直接宣称语法、推理或全部语言编码已经破解。

## 七、如何判断失败发生在哪一层

| 结果 | 应当得出的结论 | 禁止的解释 |
|---|---|---|
| 行为不稳定 | 当前合同不适合该模型 | 模型内部没有水果知识 |
| 轨迹稳定但删除无效 | 描述性标记或冗余路径 | 已找到共享机制 |
| 删除有效但错误供体也恢复 | 共同架构、答案或通用能量通道 | 水果专属编码 |
| 属性供体有效且错误深度也有效 | 内容可搬运 | 找到自然属性层 |
| 对象和属性可见但绑定交换不跟随 | 内容存在，配对规则未找到 | 知识边已破解 |
| 联合块有效、单单元无效 | 分布式协同或补偿 | 没有机制 |
| 自然和上下文路径不同 | 参数化知识与临时绑定实现不同 | 算法失败 |
| 密封水果不复制 | 开放集候选失效 | 继续调阈值挽救 |

## 八、与旧算法相比，真正改变了什么

| 旧路线 | 新路线 |
|---|---|
| 扫描全网高分神经元 | 从正确答案沿合法父边反向追踪 |
| 用轨迹相似定义复用 | 用删除、恢复和错误恢复定义复用 |
| 把对象、类别、属性混在一起 | 建立四本因素账 |
| 先压缩成范数或综合分数 | 保留有符号事件和完整响应卡 |
| 只研究激活 | 先恢复运行路径，再定位参数支持 |
| 单点排名 | 允许联合必要、补偿和冗余事件块 |
| 已见样本解释 | 未见水果和重新组合预测 |
| 三模型物理坐标硬对齐 | 比较功能事件顺序和因果拓扑 |
| 高分即进入神经元扫描 | 路径通过九道门后才下钻 |

核心优化不是增加新的特征分数，而是改变搜索空间和裁决标准：

```text
搜索空间：全模型参数 -> 当前正确行为的合法父事件树；
裁决标准：表示相似 -> 功能损伤、正确恢复、错误控制和未见复制；
参数分析：全量权重扫描 -> 已确认运行路径内的参数支持。
```

## 十二、最终结论

用户的核心判断是正确的：当前项目最缺的不是更多语言族、更多理论公式或更大的相似度图，而是一套能把语言结构因素与真实计算事件一一拆账、再用因果后果裁决的恢复算法。

水果类别是合适的最小目标，因为它同时具备：

```text
稳定类别共性；
清楚对象差异；
多种属性；
对象－属性绑定；
子类继承；
自然知识与受控上下文两种来源。
```

真正的核心关键是：

```text
不要从数十亿参数中直接寻找“苹果”；
先从模型已经答对的苹果事件向上游恢复它实际使用的最小因果路径；
再只在这条路径中判断哪些参数被多个水果复用、哪些参数形成对象和属性差分、哪些边保持正确绑定。
```

如果这条算法能够在未见水果上预测并重现类别共享、对象差分和属性绑定，它就第一次真正接近“编码机制恢复”。如果失败，也会明确失败在行为、因素分离、因果路径、绑定还是参数支持，而不再只产生一批无法解释的高分节点。
