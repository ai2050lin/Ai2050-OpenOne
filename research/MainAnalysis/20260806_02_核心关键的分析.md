#### 1.4 复用模式识别

```python
# 跨样本、跨词面、跨模板的路由事件重复
def find_reusable_routing(events_list):
    reusable = []
    for event in events_list:
        # 检查：换名字后，同layer同head是否仍然从source_role读到target_role？
        cross_name_repeat = check_repeat_across_names(event)
        # 检查：换模板后，同layer同head是否仍然路由？
        cross_template_repeat = check_repeat_across_templates(event)
        if cross_name_repeat and cross_template_repeat:
            reusable.append(event)
    return reusable
```

**这一层回答**：
- 高维模式如何复用？→ 路由事件的跨样本重复
- 在哪个layer发生？→ 路由事件的层分布
- 不同任务是否共享路由？→ 跨任务路由事件的重叠

### Layer 2：组件级因果响应矩阵

**目标**：回答"哪个组件真正搬运了内容"。

**核心思想**：不是搬运整残差（K79证明整残差主要是通用方向场），而是**逐组件分解**。

#### 2.1 组件分解干预

```python
# 不搬运整残差，而是分别搬运：
intervention_targets = {
    "attention_output": "只搬运特定head的attention output",
    "mlp_output": "只搬运特定MLP通道的output",
    "residual_subset": "只搬运特定维度子集",
    "kv_cache": "只搬运特定位置的K/V",
}

# 对每个组件，做独立干预
for component in intervention_targets:
    for layer in candidate_layers:
        for unit in candidate_units:
            # 干预：将source的component状态写入target
            patched_output = patch_component(
                target_model, layer, unit, 
                source_state=donor_state[component]
            )
            # 测量：输出边际变化
            response_matrix[target_item][donor_item][component] = {
                "margin_change": compute_margin_change(patched_output),
                "flip_success": check_flip(patched_output),
            }
```

#### 2.2 响应矩阵构造

```python
# 目标×供体×组件 的三维响应矩阵
E = np.zeros((n_targets, n_donors, n_components))

for i in range(n_targets):
    for j in range(n_donors):
        for c in range(n_components):
            E[i, j, c] = margin_change(target_i, donor_j, component_c)
```

#### 2.3 对角优势检测（K79的核心教训）

```python
# 内容特异性：正确供体必须显著胜过错误供体
D_item = median(diag(E)) - median(off_diagonal(E, matched_controls))

# 关系特异性：同关系供体必须胜过不同关系供体
D_relation = median(same_relation(E)) - median(different_relation(E))

# 方向特异性：同方向供体必须胜过反方向供体
D_direction = median(same_direction(E)) - median(opposite_direction(E))

# 判决
if D_item > threshold and D_item > D_direction:
    # 存在内容特异载荷
    content_specific_components = find_top_components(E, D_item)
elif D_direction > threshold and D_item < threshold:
    # 只是通用方向场（K79的情况）
    STOP("该位置是通用答案方向场，不是内容编码")
```

**这一层回答**：
- 低维精确如何分支？→ 组件级响应矩阵的对角优势
- 哪个组件负责内容？→ D_item 显著为正的组件
- 哪个组件只是通用方向？→ D_direction 显著但 D_item 不显著的组件

### Layer 3：供体身份特异性验证

**目标**：回答"搬运的是内容，还是只是方向"。

**核心思想**：Phase 1141 证明整残差主要是通用方向场。必须用**供体差分注入**排除通用基线。

#### 3.1 绝对替换 vs 差分注入

```python
# 绝对替换（Phase 1138-1141的做法）
H_patched_abs = H_target + (H_donor - H_target)

# 差分注入（排除通用基线）
delta_H_donor = H_donor_opposite - H_donor_base  # 供体自身的"答案翻转差分"
H_patched_diff = H_target + alpha * delta_H_donor

# 如果对角优势只在绝对替换中存在，在差分注入中消失：
# → 来自全状态兼容性，不是内容运输
# 如果两种操作都保留对角优势：
# → 更接近可复用的内容运输规则
```

#### 3.2 多级供体设计

```python
donor_types = {
    "correct": "同item、相反答案",           # 测试充分性
    "same_relation": "不同item、同关系、同方向", # 测试关系特异性
    "diff_relation": "不同item、不同关系、同方向", # 测试关系特异性
    "same_answer": "同item、答案不变、时间改变",  # 排除时间效应
    "self_identity": "目标自己的状态写回",       # 仪器恒等
}
```

**这一层回答**：
- 搬运的是内容还是方向？→ 差分注入是否保留对角优势
- 内容特异性有多强？→ 正确供体vs错误供体的幅度比
- 是否存在"内容编码"？→ D_item 在差分注入中是否仍显著

## 八、最终结论

您关于"语言是模式组合、根据层数细化、背后有精巧高效机制"的直觉，**方向完全正确**，且与当前研究的核心发现高度一致。

但 Phase 1138-1141 的关键教训是：

> **"精细化"不是线性的从粗到细，而是"复用外壳 + 条件化差分 + 分布式路由"的动态叠加。**  
> **高层（0.7+）不是"精细化内容"，而是"通用方向场"。**  
> **真正的"内容精细化"发生在中层（0.3-0.5），通过组件级条件化路由实现。**

CCST 算法的设计目标，就是用**六层递进的因果验证**，把这个"复用外壳 + 条件化差分 + 分布式路由"的完整结构，从"描述性图谱"推进到"可执行、可预测、可干预的因果机制图"。

**这不是再找一个"更聪明的位置"，而是画出一张"每个目标接受每个供体会发生什么"的完整因果响应矩阵。**

只有当正确供体在矩阵对角线上稳定、明显胜过所有匹配错误供体，且跨材料、跨模型、跨规模重复时，我们才能真正说：

> **我们临摹出了神经网络内部的结构和脉络。**
