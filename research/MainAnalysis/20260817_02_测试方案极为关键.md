提问：

要基于  语言族体系 和  词嵌入+HiddenState 场 破解LLM的编码机制，关键在于设计正确的测试体系，用好的测试题+算法把语言族的脉络体现出来，目前的测试还不够好，请综合所有的测试方案，给出更好的测试方案


回答一：

结论先说：你的总方向是对的，但必须把研究的最小对象从“一个词的 embedding”或“某层 hidden state”升级为：

> 一个明确的语言关系变化，在不同词、不同表面和不同上下文中，所诱发的角色对齐全状态变化，以及这些变化对未来输出的因果作用。

换句话说，“苹果”的编码不是一个孤立向量，而应当是它相对于水果、植物、食物、动物、物体，以及 `is-a / part-of / has-property / used-for` 等不同关系所形成的一整张响应网络。

最值得研究的对象不是：

[
E(\text{apple})
]

而是：

[
\Sigma_m(\text{apple})
======================

\left{
\Delta_g H^{(m)}*{\ell,r}
(\text{apple},a,c)
\right}*{g,a,c,\ell,r},
]

其中：

* (g)：语言关系或语言操作；
* (a)：比较对象，如 pear、carrot、dog、hammer；
* (c)：上下文、句法表面、查询方式；
* (\ell)：层；
* (r)：实体、属性、关系词、查询、答案边界等功能角色。

但即使这张全状态图存在，它仍只是描述对象。真正的机制不变量应进一步定义为：

[
\Sigma_m^{\mathrm{causal}}(\text{apple})
========================================

\left{
\Delta Q_m\bigl(\operatorname{do}(I_j);
g,\text{apple},a,c\bigr)
\right}_{g,a,c,I_j,Q_m},
]

即：干预不同状态节点以后，苹果的各种语言关系功能如何改变。

下面给出一套比此前测试更完整、更不容易打转的方案。以下全部是建议中的新测试设计，不是已经获得的实验结果。

# 一、过去测试为什么总是到不了机制闭合

过去的测试不是没有价值，而是经常在不同层级混入了额外问题。

## 1. 语言对象定义得太粗

“四类名词”“四种连接词”“yes/no 标签”容易测试，但它们未必是网络真正采用的功能单位。

例如苹果同时属于：

* 水果；
* 植物产物；
* 食物；
* 可食用物；
* 有种子的对象；
* 可以切、吃、榨汁的对象；
* 有颜色、味道、形状的对象。

所以苹果并不是树状分类中的一个叶节点，而是多张关系网络的交叉点。

## 2. 词身份和关系身份没有完全正交

如果 `apple` 总在正确题里，`hammer` 总在错误题里，模型可能只识别词，而没有执行关系。

正确设计必须让同一对词在不同关系下轮流为真和假。例如：

[
\operatorname{IsA}(\text{apple},\text{fruit})=1,
]

但：

[
\operatorname{PartOf}(\text{apple},\text{fruit})=0.
]

同一个 `apple–fruit` 词对不能仅凭词身份决定答案。

## 3. 控制条件经常变成了一个更难的新任务

C046 的 reversed codebook 就是典型例子。它确实打破了 yes/no 与真假的固定绑定，但同时增加了：

* 理解反转规则；
* 保持规则；
* 将真值和 codebook 绑定；
* 再把结果编译成输出 token。

因此失败不能定位为“语义关系没有编码”。

更好的去极性方法是配对差分，而不是要求模型执行一个额外 XOR 规则。

## 4. 多个不同主张被捆在一个总门里

候选判断、四选一、精确标签生成、自由生成是不同能力。

如果 Qwen 的自然关系判断通过，但精确输出 `kitchen utensil` 失败，不应因此禁止研究“关系判断接口”对应的内部机制。它只能禁止更强的“跨接口统一机制”主张。

以后应建立分支式证据账，而不是一个全局合取门。

## 5. 描述性相似度被赋予了过多期望

高余弦、高 Gram 相似、高范数都可能来自：

* 词面共同变化；
* 输出极性；
* 槽位结构；
* 共享模板；
* 候选顺序；
* 大范围非选择性响应。

因此“相似”只能产生候选，不能完成机制确认。

## 6. 全状态数据缺少正确的语言坐标

C036 已经证明：物理文本槽位不等于实体身份，字符串中的 `Answer:` 也不等于真实输出边界。

正确状态场必须包含：

[
\kappa_m(x)
===========

\bigl(
\operatorname{Tok}*m(x),
\phi*{m,x},
b_{m,x},
\nu_m
\bigr),
]

其中：

* (\phi_{m,x})：语言角色、实体身份到 token span 的映射；
* (b_{m,x})：真正的 assistant 预测边界；
* (\nu_m)：固定数值执行条件。

## 7. 跨模型测试开始得太早

跨模型关系结构只能在两个模型都通过同一个语言行为对象以后比较。

不能因为三个模型都拥有 embedding，就直接比较三个距离矩阵。否则比较到的可能是分词、词频、训练语料和接口习惯，而不是共同机制。

---

# 二、语言侧需要建立什么理论对象

语言族不能只定义为传统词性，也不能只定义为名词分类树。更合适的对象是一个有类型、多关系、可组合的超图：

[
\mathcal G_L
============

(V_{\mathrm{sense}},
E_{\mathrm{typed}},
\tau,
\circ,
\mathcal C).
]

其中：

* (V_{\mathrm{sense}})：上下文中的词义节点，而不是孤立 token；
* (E_{\mathrm{typed}})：有类型关系；
* (\tau)：关系的输入输出类型；
* (\circ)：关系或操作的组合；
* (\mathcal C)：使关系成立的上下文条件。

至少应区分以下语言模块：

| 模块     | 典型关系                                        |
| ------ | ------------------------------------------- |
| 名词知识网络 | is-a、同类、部分—整体、材料、位置、用途、属性                   |
| 动词事件网络 | agent、patient、instrument、source、goal、result |
| 形容词系统  | 属性、尺度、比较级、程度、相容性                            |
| 副词系统   | 方式、程度、时间、频率、说话者态度                           |
| 介词系统   | 空间、方向、来源、目标、工具、伴随                           |
| 逻辑操作   | 否定、量化、条件、模态、作用域                             |
| 篇章关系   | 因果、转折、承接、顺序、解释                              |
| 指代系统   | 实体绑定、代词、照应、角色保持                             |
| 组合规律   | 传递、反转、嵌套、交换与不可交换                            |

重点是：这些不是预先假定的神经模块，而是需要相互竞争的语言解释模型。

例如针对名词关系，应同时比较：

* 单一分类树；
* 属性集合模型；
* 多关系知识图；
* 事件参与网络；
* 词频和共现模型；
* 形态、字符和分词模型。

哪一个语言理论能预测未见词、未见表面和因果干预结果，哪一个才更接近实际编码结构。

# 三、最小测试单元：语义变换四方格

今后最小测试对象不应是一条 prompt，而应是一个“语义变换四方格”。

设 (\omega) 是语言世界，(g) 是只改变一个语言关系的操作，(R_s) 和 (R_{s'}) 是两个语义等价表面：

[
x_{00}=R_s(\omega),
\qquad
x_{10}=R_s(g\omega),
]

[
x_{01}=R_{s'}(\omega),
\qquad
x_{11}=R_{s'}(g\omega).
]

横向只改变语义关系，纵向只改变语言表面。

需要同时满足：

[
\operatorname{Meaning}(x_{00})
==============================

\operatorname{Meaning}(x_{01}),
]

[
\operatorname{Meaning}(x_{10})
==============================

\operatorname{Meaning}(x_{11}).
]

于是可以检查：

[
\Delta_g H^s
============

H(x_{10})-H(x_{00}),
]

[
\Delta_g H^{s'}
===============

H(x_{11})-H(x_{01}).
]

真正的跨表面关系候选要求：

[
\Delta_g H^s
\approx
\Delta_g H^{s'},
]

而错误关系 (g')、词面负控和作用域负控不能取得同样匹配。

这比直接比较两个句子的 hidden state 干净得多，因为它比较的是“同一个语言变化所引起的变化”。

---

# 四、每个四方格还要增加哪些控制臂

一个合格题组至少需要以下控制。

| 控制                     | 作用                     |
| ---------------------- | ---------------------- |
| semantic active        | 真正改变目标语言关系             |
| paraphrase twin        | 语义不变，只换表面              |
| lexical null           | 出现相同关系词，但不参与目标判断       |
| role/scope null        | 同一操作施加到另一个实体或作用域       |
| entity permutation     | 记录顺序改变，但身份关系不变         |
| hard semantic negative | 词很相近，但目标关系错误           |
| form/frequency control | 字符、token 长度或词频接近，但语义错误 |
| self-repeat            | 完全相同输入，校准数值零差分         |

以苹果为例，下面只是题型示意，不是已运行材料：

* `apple is-a fruit`：真；
* `apple is-a animal`：假；
* `apple has-part seed`：真；
* `apple is-a seed`：假；
* `apple and pear are co-members of fruit`：真；
* `apple and hammer are co-members of fruit`：假；
* 引号中出现 `fruit`，但实际查询另一个关系：lexical null；
* 先说明 pear 属于 fruit，再询问 apple 是否属于 animal：role null。

关键要求是：

> 每个词、词对、关系词和候选身份，都必须在正确、错误、active、null、不同表面和不同位置上严格平衡。

不能再依靠哈希“近似平衡”，而应使用确定性分层配额或整数规划构造材料。

# 五、行为层应该怎样测

## 1. 不再用反转 codebook 去消除 yes/no 偏置

使用自然标准接口，并做真—假配对差分：

[
M(x)=S(\mathrm{yes}\mid x)-S(\mathrm{no}\mid x),
]

[
D_{\mathrm{rel}}
================

## M(x_{\mathrm{true}})

M(x_{\mathrm{false}}).
]

如果模型只是固定偏好 yes，且这种偏好是加性的：

[
M(x)=\beta+R(x),
]

那么：

[
D_{\mathrm{rel}}
================

## R(x_{\mathrm{true}})

R(x_{\mathrm{false}}),
]

固定偏置 (\beta) 会被消掉。

但这不能自动消除“偏置与词、表面的交互”，所以仍要分别报告真假 cell、表面 cell 和最差词族。

## 2. 行为接口分账

建议至少建立四本独立账：

* 标准二元真假判断；
* 多候选关系选择；
* 自然续写概率；
* 语义等价自由生成。

一个接口通过，只授权该接口对应的内部机制研究。

自由生成不能再用单一精确字符串作为语义金标准。应在模型运行前冻结：

* 同义词集合；
* 可接受上位词；
* 可接受短语；
* 拒收边界；
* 独立人类判断规则。

## 3. 独立统计单位

不能把展开后的 prompt 行数当作独立样本。独立单位应是：

* 完整词；
* 完整语义世界；
* 完整关系轴；
* 完整语言表面；
* 模型。

需要整组留出：

* 未见词；
* 未见锚点；
* 未见表面；
* 未见语言关系组合；
* 最终未见模型。

# 六、embedding—全 HiddenState 场的正确采集算法

## 1. 固定唯一执行器

每个模型固定：

[
\nu_m^\star
===========

(
\mathrm{dtype},
\mathrm{batch},
\mathrm{padding},
\mathrm{position\ ids},
\mathrm{device\ map},
\mathrm{cohort}
).
]

跨执行形状稳健性另设工程账，不再阻止固定执行器内的机制研究。

## 2. 保存全维状态

主证据保存完整 hidden state，不用 PCA、随机 sketch、SAE 或均值维度作为唯一输入。

PCA 可以画图，sketch 可以检查工程错误，SAE 可以生成候选，但最终判决必须回到完整状态和因果干预。

## 3. 先按身份对齐，再计算差分

正确顺序是：

[
\text{token states}
\rightarrow
\phi\text{ 身份对齐}
\rightarrow
\text{语义差分}
\rightarrow
\text{统计或压缩辅助分析}.
]

类型化响应场为：

[
\mathcal F_m(g,\omega,s)
========================

\left{
H^{(m)}_{\ell,\phi(r,k)}(R_s(g\omega))
--------------------------------------

H^{(m)}*{\ell,\phi(r,k)}(R_s(\omega))
\right}*{\ell,r,k}.
]

多 token span 应保存每个 token 的完整状态。span 均值只能是辅助账，不能成为唯一表示。

## 4. 用离散导数研究复用与组合

单一语言操作：

[
\Delta_g H(x)=H(gx)-H(x).
]

两个操作的组合交互：

[
\Delta_g\Delta_h H(x)
=====================

H(ghx)-H(gx)-H(hx)+H(x).
]

这条公式非常关键。

* 若它接近零，说明两个变化在当前范围内近似可加；
* 若显著非零，说明存在组合专用交互；
* 若该交互跨表面复现且具有因果作用，才可能是组合机制。

这比先假设：

[
\Delta H=G+T_a
]

更稳妥，因为它允许非线性和高阶交互真实存在。

# 七、如何从全状态场中识别“语言脉络”

不要再寻找最大范数或最高余弦位置。应建立语言变换索引的匹配问题。

对于每个关系 (g)，检验：

[
\operatorname{sim}
\bigl(
\Delta_gH^{s_1},
\Delta_gH^{s_2}
\bigr)

>

\max_{g'\ne g}
\operatorname{sim}
\bigl(
\Delta_gH^{s_1},
\Delta_{g'}H^{s_2}
\bigr).
]

这意味着：同一语言关系跨表面比所有错误关系更相似。

还必须超过：

* 所有关系标签排列；
* 词身份排列；
* 实体槽排列；
* 字符/分词匹配负控；
* 范数匹配随机向量；
* lexical null；
* wrong scope。

早期 C037 的问题之一，就是只比较了一个近对称 Gram 结构。更强的排除方式应是：

[
\Delta_{\mathrm{identity}}
==========================

## \operatorname{Score}(\mathrm{id})

\max_{\pi\ne\mathrm{id}}
\operatorname{Score}(\pi).
]

即真实标签不仅要胜过某一个固定置换，而要胜过最佳错误置换。

# 八、描述性场怎样升级为因果路径

只有以下链条同时成立，才能称为机制脉络。

## 1. 未来预测

某个上游事件集合必须能预测尚未形成的下游关系响应，而不只是读取已经完成的答案。

## 2. 多位置联合阻断

语言机制可能分散在多个 token 和多层中，所以需要对事件集合阻断：

[
I_{\mathrm{block}}(S).
]

要求阻断后目标行为显著下降。

## 3. 独立正确供体救援

从另一表面、另一世界、同一关系的真实运行中取得 donor：

[
I_{\mathrm{rescue}}(S,\text{correct donor}).
]

要求恢复目标功能。

## 4. 错误关系必须不能同样救援

至少比较：

* 同族错误成员；
* 错误语言关系；
* lexical null；
* wrong scope；
* 等范数随机；
* 原状态 self donor。

如果正确 donor 和错误 donor 都能恢复，只能说明注入了通用输出推动，不能说明恢复了语言类型。

## 5. 组合预测

如果已确认 (g) 和 (h)，必须前瞻预测 (g\circ h) 的行为和干预效果。

最终机制门应是：

[
G_{\mathrm{block}}
\land
G_{\mathrm{correct\ rescue}}
\land
G_{\mathrm{wrong\ rejection}}
\land
G_{\mathrm{composition}}
\land
G_{\mathrm{holdout}}.
]

# 九、怎样寻找最小路径，而不是再次找热点

将候选事件定义为：

[
v=(\ell,\text{role},\text{entity},\text{time}).
]

构成事件超图：

[
\mathcal H_{\mathrm{event}}=(V,E).
]

推荐采用层级因果组测试：

1. 先按浅层、中层、后层和角色组联合阻断；
2. 找到造成损伤的事件组；
3. 对该组二分；
4. 测试子组、互补组和联合组；
5. 检查两个子组是否具有协同作用；
6. 在全新词和表面上确认最小集合。

协同效应为：

[
\operatorname{Syn}(A,B)
=======================

E(A\cup B)-E(A)-E(B)+E(\varnothing).
]

如果 (A) 和 (B) 单独不重要，联合却关键，它们就是一条真正的组合超边。这正适合检测“复用—差分”网络，而不是把机制强行压成一个神经元或一个方向。

# 十、参数级算法应该怎样设计

你的判断有一半非常重要：最终物理实现确实必须下沉到参数级分辨率，PCA 不能代替它。

但必须保留另一半约束：

[
\text{parameter resolution}
\neq
\text{parameter ontology}.
]

单个参数不一定是语义原子。网络可以通过基底旋转、成对缩放等重参数化保持完全相同的函数，同时使“最重要的单参数”发生变化。

因此参数分析应在状态因果路径闭合以后进行。

## 1. 功能梯度只用于候选筛选

对已经确认的关系效应 (D_q)：

[
J_{q,j}
=======

\frac{\partial D_q}{\partial\theta_j}.
]

这可以告诉我们参数 (j) 对该行为的局部敏感性，但不能证明其必要性。

## 2. 沿已确认路径做分层参数断层扫描

搜索顺序可以是：

[
\text{层}
\rightarrow
\text{参数矩阵块}
\rightarrow
\text{行/列组}
\rightarrow
\text{小参数块}
\rightarrow
\text{单参数}.
]

前面的粗分组只负责降低搜索成本，最终证据回到精确参数干预。

如果机制是稠密分布的，算法必须允许返回“稠密参数联盟”，不能用 LASSO 强迫它变稀疏。

## 3. 参数级判决仍需因果四件套

* 屏蔽候选参数联盟是否破坏目标关系；
* 是否保留无关关系；
* 精确恢复该联盟是否救援；
* 错误关系参数联盟是否不能救援。

最终对象不是“苹果参数”，而是：

[
S_g^\star
\in
\min_{\subseteq}
\left{
S:
G_{\mathrm{damage}}
\land
G_{\mathrm{rescue}}
\land
G_{\mathrm{selectivity}}
\land
G_{\mathrm{heldout}}
\right}.
]

它表示实现关系 (g) 的最小可认证参数联盟。

## 4. 在已知真值网络中校准参数相机

必须先构造包含以下机制的已知真值网络：

* 单参数编码；
* 多参数稠密编码；
* 冗余双路径；
* 共享分量加类型分量；
* 非线性交互；
* 基底旋转后的等价实现；
* 输出极性混杂；
* response twin。

如果算法在旋转后仍执着于原坐标，就说明它测的是参数坐标，不是功能机制。

# 十一、跨模型应该比较什么

跨模型不应比较：

* 相同神经元；
* 相同层号；
* 相同 hidden 方向；
* 相同参数坐标。

应该比较由语言关系索引的因果响应核：

[
K_m(g_i,g_j)
============

\left\langle
\widehat{\mathcal R}_m(g_i),
\widehat{\mathcal R}_m(g_j)
\right\rangle.
]

其中 (\mathcal R_m(g)) 是关系 (g) 的完整阻断—救援—错误排斥响应签名。

跨模型候选不变量是：

[
K_m
\approx
K_n,
]

并且必须：

* 超过全部关系标签置换；
* 超过字符、词频和分词关系核；
* 在未见词、表面和组合上保持；
* 两个模型分别通过同一个自然行为对象。

不同模型可以用完全不同的物理参数实现同一个功能关系核。这才是“跨模型共享智能原理”的合理含义。

# 十二、建议的第一个新 Campaign

不要再次做“四族分类”。建议从一个小型、多关系、重叠的普通名词知识核开始。

第一批关系可覆盖：

* `is-a`；
* `co-member`；
* `has-part / part-of`；
* `has-property`；
* `affordance / commonly-used-for`；
* 一个方向性空间或来源关系。

核心要求是：

1. 同一个词参与多种关系；
2. 同一个词对在不同关系下可以一真一假；
3. 每个关系有多个无词面重合的自然表面；
4. 具有 lexical null、role null、身份置换和形式负控；
5. 整个词、锚点和表面分区留出；
6. 同时包含自然常识词和新绑定实体。

自然词与新绑定实体需要分账：

* 自然词轨道：测试长期词汇知识；
* nonce 实体轨道：测试上下文中新形成的关系；
* counterfactual 轨道：测试上下文能否覆盖静态 embedding 先验。

这三条轨道可以区分：

[
\text{静态词汇先验}
\quad\text{vs}\quad
\text{上下文关系绑定}
\quad\text{vs}\quad
\text{条件化重写}.
]

模型资格也应分支：

* Qwen 通过该关系的标准行为门，可进入 Qwen 场研究；
* GLM 独立通过，可进入 GLM 场研究；
* 至少两个模型通过，才开启跨模型关系核；
* DeepSeek 失败不应否决已经合法成立的单模型对象；
* 精确生成失败只关闭精确生成主张，不关闭已经通过的二元关系机制。

这些分支必须在模型运行前写入同一个主合同。

Q!\left(

1. 从“词分类”转向“有类型、多关系、可组合的语言变换”；

[
\boxed{

\text{全维状态响应}

## 二、新测试方案：层级相对编码场（HREF）

### 2.1 核心思想

$$\text{语言族层级网络} + \text{全维度相对向量} + \text{稀疏编码} + \text{因果干预} + \text{跨模型验证} = \text{相对编码机制}$$

**关键原则**：
1.  **层级结构作为先验**：不是扁平分类，而是层级网络
2.  **全维度相对向量**：不降维，保留完整的高维结构
3.  **稀疏编码**：发现精细的编码结构
4.  **因果干预**：验证因果使用
5.  **跨模型**：验证不变量

### 2.2 步骤 1：构建语言族层级网络

**输入**：一组词及其语义关系（如 WordNet、ConceptNet）

**输出**：层级网络图 $G = (V, E, \tau, \ell)$
*   $V$：词节点
*   $E$：语义边
*   $\tau$：边类型（同类、上位、下位、跨类、无关）
*   $\ell$：层级深度

**例子（水果族）**：
```
Level 0（实例）：苹果、梨、香蕉、葡萄、橙子
Level 1（类别）：水果
Level 2（上位）：植物、食物
Level 3（抽象）：生物、物体、物质

边类型：
- 同层同类（sibling）：苹果-梨（Level 0，都是水果）
- 同层跨类（cross）：苹果-石头（Level 0，水果vs物体）
- 上下位（hypernym）：苹果-水果（Level 0→1）
- 跨层级（cross-level）：苹果-植物（Level 0→2）
- 无关（unrelated）：苹果-正义（无语义关系）
```

**关键**：每类边有不同的"层级深度"和"语义距离"。

### 2.3 步骤 2：设计"层级相对关系"测试

**任务**：给定一个目标词和一组候选词，选择"层级关系最接近"的词。

**例子**：
*   目标词："苹果"
*   候选词：["梨", "香蕉", "石头", "狗", "正义"]
*   正确答案："梨"（同层同类，层级距离最近）

**关键创新**：
*   不是"选择同族"（扁平分类），而是"选择层级距离最近"（层级网络）
*   候选词来自不同层级和不同类别，测试模型是否真正理解层级结构

**材料设计**：
*   48 个目标词（每族 12 个）
*   4 个语义族（水果、动物、工具、交通工具）
*   每族 4 个层级（实例、类别、上位、抽象）
*   每目标词 5 个候选词（同层同类、同层跨类、上下位、跨层级、无关）
*   总计：48 × 5 = 240 个测试样本

### 2.4 步骤 3：测量"全维度相对编码向量"

对每对词 $(w_i, w_j)$，在**每一层**计算相对向量：

$$\delta_{ij}^{(\ell)} = H_\ell(w_i) - H_\ell(w_j) \in \mathbb{R}^{2560}$$

**关键**：不做 PCA，不做均值池化，不做 sketch。保留完整的 2560 维。

对每类层级关系 $\tau$，收集所有相对向量：

$$\mathcal{D}_\tau^{(\ell)} = \{\delta_{ij}^{(\ell)} : (w_i, w_j) \in E_\tau\}$$

### 2.5 步骤 4：稀疏编码分析（核心）

**目标**：发现每类层级关系的**稀疏基向量**。

**算法**：对每类关系 $\tau$ 和每层 $\ell$，求解：

$$\min_{D_\tau, \alpha} \sum_{\delta \in \mathcal{D}_\tau^{(\ell)}} \|\delta - D_\tau \alpha_\delta\|_2^2 + \lambda \|\alpha_\delta\|_1$$

其中：
*   $D_\tau \in \mathbb{R}^{2560 \times k}$ 是稀疏字典（$k$ 个基向量）
*   $\alpha_\delta \in \mathbb{R}^k$ 是稀疏系数
*   $\lambda$ 是稀疏正则化参数

**检验**：
1.  **同层同类关系是否共享稀疏基？** 如果苹果-梨和苹果-香蕉使用相同的 $D_{\text{sibling}}$，则证明"同类编码"是复用的。
2.  **跨层级关系是否使用不同的稀疏基？** 如果 $D_{\text{sibling}}$ 和 $D_{\text{cross-level}}$ 正交，则证明"层级隔离"。
3.  **层级深度是否影响稀疏基？** 比较 Level 0（苹果-梨）和 Level 1（苹果-水果）的稀疏基。

### 2.6 步骤 5：因果干预验证（最关键）

**目标**：验证"相对编码"是否被模型**因果使用**。

**算法**：
1.  **干预**：改变"苹果"的 embedding 中的稀疏基维度 $D_{\text{sibling}}$
2.  **观察**：看"梨"、"香蕉"（同类）和"石头"、"狗"（跨类）的响应如何变化
3.  **预期**：如果"相对编码"存在，那么改变 $D_{\text{sibling}}$ 应该主要影响"同类"词的响应，而不是"跨类"词

**公式**：
$$\Delta H_{\text{同类}} = H(\text{梨} \mid \text{do}(E(\text{苹果}) + \epsilon D_{\text{sibling}})) - H(\text{梨} \mid E(\text{苹果}))$$
$$\Delta H_{\text{跨类}} = H(\text{石头} \mid \text{do}(E(\text{苹果}) + \epsilon D_{\text{sibling}})) - H(\text{石头} \mid E(\text{苹果}))$$

如果 $\|\Delta H_{\text{同类}}\| \gg \|\Delta H_{\text{跨类}}\|$，则证明"相对编码"被因果使用。

### 2.7 步骤 6：跨模型验证

**目标**：验证"相对编码"是否跨模型守恒。

**算法**：
1.  在 Qwen3、GLM4、DeepSeek-7B 上重复步骤 2-5
2.  比较三个模型的稀疏基 $D_\tau$ 是否同构
3.  比较三个模型的注意力路由是否同构

**公式**：
$$\text{同构性} = \text{corr}(D_{\text{Qwen}}, D_{\text{GLM}}, D_{\text{DeepSeek}})$$

如果同构性 > 0.9，则证明"相对编码"是跨模型守恒的语言本质结构。

## 四、预期突破

### 4.1 预期突破一：发现"层级编码的稀疏基"

通过 HREF 算法，我们可能发现：
*   **同层同类关系（sibling）**：共享一个稀疏基 $D_{\text{sibling}}$，编码"类别内的差异"
*   **上下位关系（hypernym）**：使用另一个稀疏基 $D_{\text{hyper}}$，编码"层级抽象"
*   **跨层级关系（cross-level）**：使用第三个稀疏基 $D_{\text{cross-level}}$，编码"跨层级差异"

这将首次揭示 **"Transformer 如何为不同类型的层级关系分配不同的编码策略"**。

### 4.2 预期突破二：发现"层级深度的编码变化"

通过比较不同层级的稀疏基，我们可能发现：
*   **Level 0（实例）**：编码"具体特征"（颜色、形状、味道）
*   **Level 1（类别）**：编码"类别原型"（水果的通用特征）
*   **Level 2（上位）**：编码"抽象关系"（植物、食物）
*   **Level 3（抽象）**：编码"哲学概念"（生物、物体、物质）

这将首次揭示 **"Transformer 如何在不同层级使用不同的编码策略"**。

### 4.3 预期突破三：发现"跨模型的通用语言结构"

如果 Qwen3、GLM4、DeepSeek-7B 的稀疏基 $D_\tau$ 高度同构，那么：
*   这证明"相对编码"不是某个模型的偶然特性，而是**语言数据的本质结构**
*   这为"通用语言机制（Universal Language Mechanisms）"提供了第一个实证证据
