# 计算图有向性与来源 K/V 因果审计

更新时间：2026-07-12 05:17 HDT

## 一、阶段目的

Phase386 在一次性物理留出中留下 `10` 条预测关系，其中 `9` 条位于目标词元到下一词元，只有 `1` 条位于答案前：关系绑定、晚深度、注意力头聚合、`source_encoded -> query_integrated`。

本轮没有把这条线直接当作因果边，而是连续完成：

```text
Phase387：计算图有向性审计；
Phase388：全新分母上的来源 K/V 因果干预；
Phase389：全部查询头和来源角色离线分解。
```

## 二、Phase387：计算图有向性审计

Decoder block 的局部顺序是：

$$
x_{L,p}\rightarrow(q_{L,p},k_{L,p},v_{L,p})
\rightarrow z_{L,p}\rightarrow a_{L,p}
\rightarrow m_{L,p}\rightarrow x_{L+1,p}
$$

同层后位置查询读取的是前位置由 `layer_input` 生成的 K/V：

$$
(k_{L,s},v_{L,s})\rightarrow z_{L,p},\qquad s\le p
$$

而来源位置刚产生的 `attention_head_state z_{L,s}` 不能在同层直接成为 `z_{L,p}` 的输入。增量 cache 保存的也是该层在注意力输出前生成的 K/V。

审计 Phase386 的十条物理留出预测关系：

```text
具有语义先后：10/10；
可登记预测轨迹：10/10；
按当前同层、同组件定义可直接执行的计算边：0/10；
答案前直接物理边：0/1；
已证明间接因果可达：0/10。
```

因此十条关系全部保留为 `physical_holdout_predictive_trajectory`，不再称为传播边。唯一答案前候选必须改写为可执行的 `source layer_input/K/V -> query attention state` 假设。

## 三、Phase388：新分母与协议校正

### 1. 案例设计

冻结 `24` 个关系绑定组，每组两个提示。实体集合和物品集合完全相同，只交换绑定：

```text
item_a -> entity_a, item_b -> entity_b
item_b -> entity_a, item_a -> entity_b
```

来源补丁位于第一事实末尾的 `entity_a`。该词元在 donor 和 recipient 中身份相同，但其左侧物品不同，因此转移的是上下文化绑定状态，不是直接替换物品词元。

### 2. 两次运行合同校正

纯文本 completion 的退役试运行中，Qwen3 为 `45/48`，GLM4 为 `18/48`；GLM4 有 `30` 例只生成感叹号。改用模型原生 answer-aligned chat 后，批量左填充仍使 GLM4 保持 `18/48`。

沿用 Phase386 已审计的单样本路径后：

```text
Qwen3：48/48 严格正确；
GLM4：48/48 严格正确；
DS7B：46/48 严格正确。
```

这说明失败来自接口和批量位置路径，不应误判为模型没有关系绑定能力。三模型都全量重跑，没有只补失败项。DS7B 经常用 `\boxed{...}` 或完整句子，因此目标决策位置按各模型自然输出定位，并通过真实增量 cache 回放，不要求目标是首个生成词元。

最终有 `22/24` 个组通过三模型双条件行为和位置合同。按预排序冻结 `2` 个仪器组和其后的 `16` 个正式因果组；干预开始后没有替换案例。

## 四、来源 K/V 干预

固定层：

| 模型 | 候选层 | 错误/终端控制层 |
| --- | ---: | ---: |
| Qwen3 | 31 | 18 |
| GLM4 | 34 | 20 |
| DS7B | 24 | 17 |

七种场景：

```text
无干预；恒等 K/V；K-only；V-only；
正确来源 K/V；错误来源 K/V；错误深度 K/V。
```

对每条 donor-recipient 方向，查询状态中介为：

$$
M_q=\frac{\langle q_{patch}-q_R,q_D-q_R\rangle}
{\|q_D-q_R\|^2+\varepsilon}
$$

目标 margin 变化为：

$$
\Delta m=
[\ell(t_D)-\ell(t_R)]_{patch}
-[\ell(t_D)-\ell(t_R)]_R
$$

仪器覆盖 `12` 条方向、`84` 个场景；每个补丁恰好命中一次，非目标位置误差为零，恒等补丁的查询状态和 margin 误差均为零。

正式因果分母：

```text
16 组 × 2 方向 × 3 模型 = 96 条方向；
7 场景/方向 = 672 个干预场景；
主 K/V 补丁生成 = 96 次；
候选替换 = 0；Phase386 留出复用 = 0。
```

## 六、Phase389：头和来源角色分解

使用 Phase386 的发现集和校准集，不复用物理留出，不新增模型运行。对候选层的全部 `92` 个头逐一计算来源位置与查询位置的四条件关系，并把查询注意力前缀精确分成：

```text
来源锚点；来源局部窗口；查询局部窗口；其余前文。
```

四个角色的向量和严格重建查询头状态，最大绝对误差 `2.86e-6`。

```text
发现头候选：59/92；
校准复制头：56/92；
Qwen3 / GLM4 / DS7B：21 / 21 / 14；
复制角色记录：92；
三模型共同出现角色：来源锚点、查询局部、其余前文。
```

候选过多，而且多个不相邻角色同时通过，不能解释为稀疏关键头。进一步要求来源锚点在发现、校准和两条词汇轴上都严格强于同头其他角色后，只剩：

```text
Qwen3：0；
GLM4：2；
DS7B：0。
```

没有跨模型来源锚点特异头，因此不授权新的头干预和单神经元扫描。

## 七、对当前研究的更新

新增的真实拼图：

1. 语义相邻关系必须经过计算图有向性审计；当前十条 Phase386 关系都不是按原节点定义的直接边。
2. GLM4 的批量左填充会造成大规模伪行为失败，三模型比较必须保持已审计的单样本接口。
3. 单来源位置 K/V 能在 Qwen3、DS7B 中产生局部查询位移，但这种位移不具备稳定控制优势，也没有传播到答案。
4. 晚深度关系绑定注意力差异分布在大量头和多个来源角色中，不像少量固定头构成的通道。

仍然不能确认：

```text
关系绑定的上游因果路径；
跨模型等价头；
固定神经元编码；
任何机制的完整语言路径；
智能理论闭合。
```

## 八、问题和硬伤

1. Phase388 只替换一个实体锚点的完整 K/V，真实机制可能需要多位置、多头和多层协同。
2. donor/recipient 都能正确回答，单位置补丁可能被分布式冗余和后续层补偿。
3. Phase389 的发现和校准此前已在聚合层面查看，不是全新独立留出。
4. 来源窗口宽度 `8` 是工程分区，不是已发现的自然模块。
5. 三个小模型可能比大模型更粗糙，也可能更容易出现局部补偿；结果不能直接外推。
6. 当前没有证据支持用一个线性状态向量描述完整关系绑定过程。
