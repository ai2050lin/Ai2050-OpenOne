## 二、核心判断：是否应该执行这个方案？

### 方案的方向正确性：约 70%

**正确的部分**（与历史证据一致）：

1. **"不预设公式"是对的**。SUMMARY 完整记录了 Phase 278-427 的 150+ 阶段，连续排除了：线性方向、固定神经元、单路线、全局运输、部分序事件图、完整状态续跑等几乎所有预设公式。方案的核心判断——"当前公式是玩具"——得到历史支持。

2. **"先稳定行为，再记录物理"的方向是对的**。Phase 428-429 正是沿着这条路走：先建类型化行为门（内容/接口/改口/终止四分离），通过后才允许物理记录。方案的六阶段把"密封预测→因果闭合→神经元定位"作为顺序依赖链，与项目当前的"停止门"机制一致。

3. **"标签盲化发现"是对的**。Phase 356-364 的盲化实验已证明，标注好的"关系签名"可以 27/27 复现，但因果载体 0/9——看到的是路标不是发动机。方案要求在发现阶段禁止读取任务标签，这是必要的防过拟合措施。

4. **"从组件子图逐层下钻找神经元"是对的方向**。Phase 401-402 证明了单层 K/V 替换有物理响应但无功能特异性（0/6 通过全部控制）。方案的四级下钻逻辑（组件组→守恒分区→递归缩小→单神经元审计）避免了"按激活值排序找神经元"的常见错误。

### 需要重大修正的部分：约 30%

**问题1（最严重）：方案假设"大量语言数据能发现稳定脉络"，但 Phase 429 证明稳定行为连基本资格都很难通过**

方案设想的"大规模标签盲化发现"是建立在"至少两个模型能在多种任务上稳定行为"的假设上。Phase 429 的硬数据：
```
Qwen3：仅1个候选（无示例合同）通过，加交叉示例就失败
GLM4：内容对但永远停不下来
DS7B：连行为资格都没通过
跨模型候选：0
```

这意味着**当前只有 1/3 模型、1/2 合同、1/4 任务的极窄窗口存在稳定行为**。"大规模发现"的前提条件不成立。如果强行上大量数据，大部分样本的行为本身就是噪声，发现的"脉络"只会是噪声的统计假象。

**问题2：方案缺少"观察坐标审计"步骤**

Phase 429 发现了一个关键错误：预注册的诊断器使用了"问题句末词元"作为预测坐标（$q \neq p_{\mathrm{prompt\ terminal}}$），结果是 $0/96$ 预测通过。但这不是运输路径不存在，而是**测量点选错了**。方案的事件记录器假设"来源位置、接收位置、生成时刻"是自明的——Phase 429 证明不是。问题词元之后还有输出指令、模板边界和助手起始状态，真正的决策点可能不在问题词元。

方案需要加入"位置—时间坐标审计"作为阶段一的一部分。

**问题3：方案的因果二分搜索在非线性 Transformer 中会失效**

方案的四级下钻从"组件组→守恒分区→递归缩小→单神经元"隐含假设：
$$\Delta M(ablate\ group) \approx \sum_{i\in group} \Delta M(ablate\ neuron_i)$$

Phase 633（GLM路线）和 Phase 401 证明了正负写入大量相消（$|M^{net}|/M^{abs} \approx 0.01$）。当存在强烈相消时，删除一个组的效果不等于组内神经元效果之和——因为删除全组同时移除了正负两个方向的写入，改变了 softmax 的归一化竞争环境。

方案的递归二分搜索需要在每一步验证"组内贡献近似可加"（守恒的可加性不等于因果的可加性），否则二分方向会被误导。

**问题4：方案阶段一（全迹基础设施）低估了执行同构的复杂度**

Phase 401 花了大量工作才建立执行同构合同——batch size、padding、dtype、attention kernel、KV cache 全部要统一。Phase 400 的批形状失败（batch=1 生成 `latch`，batch=8 生成 `"latch"`）直接导致了一条分析线关闭。方案的阶段一草草提及"原生精度守恒"，但没有把"执行同构"作为独立子阶段。

**问题5："完全不使用公式"过于绝对**

方案的核心判断是"不预设语言机制公式"。但 SUMMARY 明确指出：不能预设的是语言假设，必须预设的是测量规则（守恒公式、对照公式、证据门）。方案中有大量必须预先固定的公式（如合法边定义、守恒验证、恢复指标、因果效应量），它们在数学上是精确的。说"完全不使用公式"会在工程上造成混乱——你其实用了很多公式，只是不把它们当语言理论。

## 三、改进方案

### 改进1：加一个"前置阶段零"——三模型行为资格审计

**原方案的阶段一直接进入全迹基础设施，但 Phase 429 证明行为资格是瓶颈。**

建议在阶段一之前加一个短的前置阶段：

```
阶段零：三模型行为资格审计
- 对每种任务、每种接口、每种合同，先只在行为层面测试
- 只记录教师强制序列分数、自然生成目标/相反/改口/停止/截断计数
- 不安装任何物理钩子，不采集内部状态
- 通过门：至少两个模型、候选+负对照、校准+留出、内容+终止同时通过
- 只有通过门的任务×合同×模型组合才能进入阶段一
```

这把 Phase 428-429 的"先证明稳定行为合同"原则系统化。避免了"采集大量内部数据后才发现行为本身不稳定"的资源浪费。当前来看可能只有 Qwen3 无示例合同的少部分任务能进入阶段一——那就只从这些开始。

### 改进2：阶段一中加入"位置—时间坐标审计"

**原方案的事件记录器假设坐标自明，Phase 429 证明不是。**

在阶段一的"全迹基础设施"中增加一个子阶段：

```
阶段一.C：位置—时间坐标审计
- 对每个注册任务，记录所有候选决策坐标：
  来源实体最后词元、关系词元、查询实体、问题句末、输出指令末、模板边界、生成第0步
- 对每种坐标，测试同一语义组中行为层面的区分度
- 用行为区分度（而非激活强度）选择功能坐标
- 只有功能坐标通过跨词汇复现验证，才被注册为"合法观察坐标"
```

这解决了 Phase 429 的"把问题词元误认为提示末端"问题。功能坐标不等于架构位置——这是阶段一的关键发现。

### 改进3：在因果二分搜索中增加"可加性检验"

**原方案的递归二分隐含线性可加假设，需要在每一步检验。**

修改方案第六章中的"三级：递归缩小"：

```
阶段五.B：因果可加性检验（每次二分前执行）
- 对当前分区 {L,R}：
  1. 分别删除 L 和 R，记录 Δ_ML 和 Δ_MR
  2. 同时删除 L∪R，记录 Δ_M(L∪R)
  3. 检验：|Δ_M(L∪R) - (Δ_ML + Δ_MR)| / max(|Δ_M(L∪R)|,ε) < τ
- 若通过可加性检验：继续二分
- 若未通过：登记为"非线性耦合组"，不继续二分，改用联合必要性检验
```

$\tau$ 可设为 0.3，依据 Phase 401 的 $|M^{net}|/M^{abs} \approx 0.01$ 现象应留有足够裕度。

### 改进4：方案中把"完全不使用公式"改为"公式分类管理"

**三个公式类别，不同管理策略：**

| 类别 | 作用 | 是否预设 | 例子 |
|------|------|---------|------|
| 架构恒等式 | 验证记录器 | **必须预设** | $h_{l+1}=h_l+a_l+m_l$ |
| 证伪门 | 淘汰候选 | **必须预设** | $G_{\mathrm{content}} \land G_{\mathrm{termination}}$ |
| 语言假设 | 解释机制 | **禁止预设** | "语义=线性方向""知识=固定神经元" |

方案已在多处用了架构恒等式和证伪门（守恒验证、Wilson 区间、因果效应量），只是没有分类管理。三类公式明确分开后，"不使用公式"的表述就不会造成混乱——准确的说法是"不预设第三类公式，严格执行前两类"。

### 改进5：阶段二中"标签盲化"的范围要更精确

**原方案禁止发现器读取模板名称、正确答案和功能标签。但 Phase 429 显示，连"任务上下文本身"都会改变稳定行为。**

在阶段二的盲化规则中增加：
```
禁止读取（新增）：
- 任务类型名称（如"关系绑定""字段抽取"）
- 示例类型（无示例 vs 完全交叉示例）
- 接口类型（直接 vs 强制选择 vs 结果字段）
- 正确答案
- 历史候选层

允许读取（保留）：
- 模型、层、组件、位置、生成时刻
- 真实向量、计算图父子关系
- 匿名案例组标识
- 组内条件顺序
```

原来只禁止"答案标签"，但 Phase 429 发现"加不加示例"本身就是改变行为的条件。如果发现器不知道某组是有示例组还是无示例组，它会把两种不同状态轨迹当作同一"脉络"——这就产生了系统性噪音。

### 改进6：加入"测量上下文不变性检验"

**Phase 429 的核心负结果：同一候选在无示例合同下通过，加完全交叉示例后失败。**

在阶段三（密封未来预测）之后，阶段四之前增加：
```
阶段三.B：测量上下文不变性检验
- 对每个通过密封预测的候选脉络：
  1. 在原始合同上验证
  2. 更换示例合同（无示例↔完全交叉）重测
  3. 更换接口坐标（原生↔替代）重测
  4. 更换词元覆盖范围（仅测试词元↔全部词元）重测
- 只有至少两个测量上下文不变，才能进入阶段四
```

这防止了把"Qwen3 无示例合同下的局部现象"当成"语言机制"。

### 改进7：加入跨模型功能同构检验

**方案多次提到跨模型，但没有定义"什么算功能同构"。Phase 402 的四分区枚举 0/2 跨模型通过，说明模型间的差异比想象中大。**

增加跨模型同构的精确定义：
```text
两个模型 M_a, M_b 在任务 T 上功能同构，当且仅当：
1. 两者在 T 上均通过稳定行为门（内容+终止）
2. 同类型事件出现在相近相对深度（|d_rel(a)-d_rel(b)| < 0.15）
3. 事件链的分叉和汇合拓扑相同（忽略绝对头/通道编号）
4. 联合子集超过单父的效果在两者中同向（符号一致，幅度相关系数 > 0.5）
5. 控制排除的方向在两者中一致（相同的控制类型被同等地排除）
```

当前"跨模型候选=0"可能不是因为没有共同机制，而是因为"什么算共同"从来没被严格定义过。Phase 402 用绝对层号对齐，但 Qwen3（36层）和 DS7B（28层）的绝对层号不可比。

## 四、执行决策

### 结论：应该执行，但有条件

**应该执行**，因为方案的核心逻辑（不预设语言公式 → 盲发现 → 预测 → 因果 → 规则压缩）是 Phase 278-429 历史自然导出的方向。继续给旧公式调权重的边际价值确实很低。

**但有前提条件**：

1. **必须先完成"前置阶段零"（行为资格审计）**——在确立哪些任务×合同×模型组合有稳定行为之前，不投入物理资源。这能省掉 90% 的无效计算。

2. **方案的表述从"完全不使用公式"改为"公式分类管理"**——架构恒等式和证伪门必须预设，语言假设公式禁止预设。混乱的表述会导致阶段一无法执行（守恒验证本身就是公式）。

3. **必须接受一个可能性**：三模型的行为资格可能只有 Qwen3 无示例合同的极窄窗口。如果是这样，六阶段只能在这个窄窗口内推进，不能外推。方案的"大量语言数据"假设需要降级为"仅对行为稳定窗口的大量变化数据"。

### 不应执行的情况

如果出现以下任一情况，方案应暂缓：
- 阶段零发现三模型没有任何任务×合同组合同时通过行为资格（当前迹象不乐观但尚未穷举）
- 阶段一发现精确守恒在某些模型/层不能达成（Phase 383 已验证通过，但新合同可能引入新问题）
- 阶段二发现在盲化条件下找不到任何跨词汇复现的子图（可能性不低，因为 Phase 402 的 8/13728 通过率就是信号极弱的警示）

    ↓

    ↓

    ↓

## 五、总结

方案**应该执行**，核心骨架合理——"不预设语言公式、盲发现、预测优先、逐级下钻"是历史自然演进的方向。但需要 7 处关键改进：

| # | 改进 | 原因 |
|---|------|------|
| 1 | 加前置阶段零（行为资格审计） | Phase 429 证明三模型行为稳定性极差 |
| 2 | 加位置—时间坐标审计 | Phase 429 发现测量坐标选错导致 0/96 预测失败 |
| 3 | 因果二分增加可加性检验 | Phase 401 证明正负写入大量相消 |
| 4 | 公式分类管理 | 方案其实用了很多公式，只是不叫公式 |
| 5 | 盲化范围扩展 | Phase 429 证明示例类型本身就是改变行为的条件 |
| 6 | 加测量上下文不变性检验 | Phase 429 无示例通过但交叉示例失败 |
| 7 | 精确定义跨模型同构 | 当前 0/2 可能因为对齐方法不对 |

**核心风险**：当前只有 Qwen3 无示例合同的极窄窗口有稳定行为资格。如果这也是脆弱的（Phase 429 建议用 Phase 430 重测更精确的坐标），六阶段方案可能在整个 Phase 430 就面临"分母为零"的局面。但即便如此，也比继续扫描神经元有价值——**在没有稳定行为的地方扫描神经元，只会积累噪声候选**。
