## 三、需要改进的地方（按严重程度排序）

### 改进1（最关键）：评分公式用简单平均会掩盖关键缺口

**问题**：方案用 `Score = (B+R+L+C+I+G+K)/7`，但 v2 结果显示 963/972 是 `mapped_partial`，behavior 和 readout 覆盖多，而 component_path、causal、closure 覆盖极少。简单平均会让一个"行为满分但因果为零"的样本得到 4/7≈0.57 的中等分，看起来不差，实际上没有因果证据。

**历史证据**：SUMMARY 的 Phase 195-203 就已发现"颜色候选空间闭合 ≠ 全词表输出闭合"，Phase 254-263 进一步证明闭合需要四条件同时满足。这说明不同字段的证据强度是不同的。

**建议**：改为加权评分，对 causal 和 closure 给予更高权重，或采用"最低字段限制"——causal 或 closure 为零的样本不能超过某个总分上限。例如：
$$Score = 0.1B + 0.1R + 0.15L + 0.2C + 0.25I + 0.1G + 0.1K, \quad \text{若 } I<0.3 \text{ 则 } Score \leq 0.5$$

### 改进2：闭合定义过于宽松，未对齐历史四条件

**问题**：方案的 `closure_quality` 只是七项评分之一，没有明确要求闭合必须满足什么条件。但 SUMMARY 的 Phase 254-263 已给出严格的闭合定义：
$$\text{Closure} = \text{SemanticDone} \land \text{StopWins} \land \text{ContinueSuppressed} \land \text{RolloutStable}$$
这是一个 AND 逻辑，不是加权平均。

**建议**：在方案中增加闭合的硬性判据——只有四条件同时满足才能标记为 `closed`，否则只能是 `path_candidate_not_closed` 或 `high_quality_candidate_not_closed`。当前 2 个 `high_quality_candidate` 应该用这个四条件重新检验。

### 改进3：跨模型矛盾结论的处理机制缺失

**问题**：方案的 `atlas_scores` 是 `family × model` 矩阵，但没有说明当三模型结论矛盾时如何处理。SUMMARY 的 Phase 269 明确记录了关键矛盾：MLP 在 qwen3/DS7B 有必要性迹象，但 GLM4 反向。方案没有定义"跨模型一致性"维度。

**建议**：增加跨模型一致性评分维度：
$$\text{CrossModelConsistency}(f) = 1 - \frac{\text{models\_disagree}}{\text{total\_models}}$$
并在 Family Matrix 中用颜色标注矛盾格。矛盾结论不应简单取平均，而应标记为 `model_specific_mechanism` 并单独审计。

### 改进4：九大模式族缺乏完备性验证

**问题**：方案直接固定九大族，但没有验证这九个族是否穷尽了所有主要语言模式。SUMMARY 的 Phase 209-218 是从颜色任务中归纳出模式的，可能存在采样偏差——某些模式（如多轮对话、代码生成、情感推理）可能未被覆盖。

**建议**：在 Batch A（Schema Freeze）之前增加一步"模式族完备性检验"：用一组开放任务（不限于 QA/颜色）跑三模型，统计是否有样本无法归入九大族中的任何一个。如果有超过 5% 的样本无法归类，说明族分类需要扩展。

### 改进5：样本量严重不足

**问题**：972 条 path signature 分布在 9 族 × 3 模型 = 27 格中，平均每格仅 36 条。方案后半部分的评估建议每族至少 200-500 条，当前远不足。少量样本会导致方向估计不稳定（SUMMARY 的 Phase 27 条件解耦就因样本少导致 cos 估计噪声大）。

**建议**：Batch B 的目标应从"补齐 972 条的缺口字段"调整为"先扩充到每族每模型至少 100 条，再补字段"。在样本不足时，所有结论只能标为 `exploratory`，不能进入因果审计。

### 改进6：非线性问题完全未触及

**问题**：方案的评分公式、path_signature、causal audit 全部基于线性叠加框架。但 GLM5 memo 已证明（Phase 633）：多 writer 线性叠加 restore 在 softmax 归一化墙前失效（top12 < top1）。方案的 `MLPWriterSet` 和 `CompensationPath` 用的是线性贡献分解 $\Delta M = M(h+a+m) - M(h+a)$，这在非线性 Transformer 中只是局部近似。

**建议**：在 Batch C 因果审计中增加"非线性叠加检验"：对多 writer 做 cumulative restore，检验线性叠加预测与实际效果是否一致。如果不一致（类似 Phase 633 的 top12 < top1），记录为"非线性耦合节点"，不能简单归因到单个 writer。

### 改进7：缺少前向预测验证

**问题**：方案全是回顾性补字段，没有"预测优先"验证。SUMMARY 的最终公式 $\text{LanguageMechanism} = \sum_i \alpha_i P_i$ 应该具有预测能力，但方案没有设计预测实验。

**建议**：在 Batch B 完成后增加"预测验证 Batch"：给定一个新样本（已知模式族但未测试过），用已有图谱预测其 dominant_layers、attention_route、readout_winner，然后实际测试比对。只有预测准确率显著高于随机基线，理论才开始成立。

### 改进8：机制主张登记表未纳入 Batch 计划

**问题**：方案后半部分的评估建议了 claim registry（机制主张登记表），但 Batch A-D 没有包含这一项。当前结论散在 Memo 里，没有统一登记。

**建议**：将 claim registry 纳入 Batch A，与 schema freeze 同步完成。每条 claim 必须有 claim_id、适用模型、证据等级（L0-L8）、正/反证据文件、下一步测试。没有登记的结论不进入图谱。

### 改进9：语义评估器仍依赖代理指标

**问题**：方案的 behavior score 仍依赖字符串规则和 target token margin。SUMMARY 明确指出这些是代理指标，不能直接等于语言机制。Phase 204-208 已发现"输出句号 ≠ 真正停止"，说明字符串规则会误判。

**建议**：引入更强的 semantic evaluator：用模型自身做 teacher-forced scoring（完整短语似然，而非单 token），或引入人工校验子集（至少对 high_quality_candidate 做人工标注）。方案文件后半部分的评估也建议了这一点，但 Batch 计划未落地。

### 改进10：因果干预协议未统一历史方法

**问题**：方案 Batch C 只提到 half/mean_replace/window shrink，但 SUMMARY 的 Phase 219-233 和 246-253 已验证了更多干预方法：方向增强 $h'=h+\lambda\hat{v}$、方向移除 $h'=h-(h\cdot\hat{v})\hat{v}$、cross-sample patch。这些方法没有纳入统一协议。

**建议**：标准化因果干预协议应包含完整的 9 种干预（方案后半部分评估已列出），并规定每种干预的适用场景和证据等级映射。

# 一、这份分析哪些地方是正确的

## 1. “评分公式不能简单平均”这个判断正确

当前 v2（第二版）评分如果只是：

$$
\boxed{
Score(x)
========

\frac{
B(x)+R(x)+L(x)+C(x)+I(x)+G(x)+K(x)
}{7}
}
$$

确实会有问题。

因为 behavior（行为）和 readout（读出）容易有分数，但 component_path（组件路径）、causal_audit（因果审计）、closure_quality（闭合质量）才是真正接近机制的字段。如果简单平均，一个“回答看起来不错但完全没有因果审计”的样本会被抬得太高。

更好的做法是：

```text
保留总分；
同时加入硬性门槛；
再加入缺口惩罚。
```

例如：

$$
\boxed{
AdjustedScore(x)
================

## Score(x)

\lambda \cdot CurrentGap(x)
}
$$

并增加规则：

```text
如果 causal_audit（因果审计）缺失，
不能进入 high_quality_candidate（高质量候选）；
如果 closure_quality（闭合质量）缺失，
不能进入 closure_test_ready（闭合测试准备）。
```

---

## 2. “闭合必须是 AND（并且）条件，不是平均分”这个判断非常重要

闭合不能写成几个分数加权平均。闭合更接近硬条件：

$$
\boxed{
\mathrm{ModelClose}
===================

\mathrm{AnswerCorrect}
\land
\mathrm{PatternMatched}
\land
\mathrm{BoundaryStable}
\land
\mathrm{DoneStateStable}
\land
\mathrm{ModelStopExecuted}
\land
\mathrm{NoDrift}
}
$$

也就是说，只要其中一个失败，就不能说闭合。

你提到的四条件：

$$
\boxed{
\mathrm{Closure}
================

\mathrm{SemanticDone}
\land
\mathrm{StopWins}
\land
\mathrm{ContinueSuppressed}
\land
\mathrm{RolloutStable}
}
$$

也很有价值。它可以作为当前闭合复核的更细版本。

---

## 3. “跨模型矛盾要单独处理”这个判断正确

不能把 qwen3、GLM4、DS7B 的结果简单平均。

因为 Phase269-277 已经反复出现：

```text
qwen3 和 DS7B 对 MLP（多层感知机）干预更敏感；
GLM4 常出现副作用高、补偿路径、反向效应。
```

因此应该增加一个字段：

```text
cross_model_consistency（跨模型一致性）
```

并把不一致情况标为：

```text
model_specific_mechanism（模型特异机制）
```

而不是把它们平均掉。

---

## 4. “非线性叠加检验”非常值得加入

这个是当前方案里非常重要但还没有充分落地的地方。

当前很多公式仍然像：

$$
\boxed{
\Delta h
========

\Delta h_{\mathrm{attn}}
+
\Delta h_{\mathrm{mlp}}
+
\Delta h_{\mathrm{resid}}
}
$$

但真实模型里有 softmax（归一化竞争）、RMSNorm（均方根归一化）、门控 MLP（门控多层感知机）、残差耦合等非线性结构。

所以需要增加：

```text
nonlinear_coupling_test（非线性耦合测试）
```

例如比较：

$$
\boxed{
Effect(A+B)
\quad
\text{vs}
\quad
Effect(A)+Effect(B)
}
$$

如果两者差异很大，就说明不能把路径解释成线性相加。

---

## 5. “机制主张登记表”也很有价值

当前 Phase（阶段）很多，结论很多，如果不做 claim registry（机制主张登记表），很容易出现：

```text
某个结论已经被后续阶段修正；
但旧结论还在被继续引用。
```

建议每条机制主张都登记：

```text
claim_id（主张编号）
适用模型
适用语言族
证据等级
正证据
反证据
当前状态
下一步验证
```

这样理论不会漂移。

# 二、这份分析需要修正的地方

## 1. 不一定要“先修完所有结构问题再执行 Batch（批次）”

分析里说“建议在执行 Batch A-D 前先修正三处结构性问题”，这个方向对，但执行上可以更灵活。

当前系统已经形成：

$$
\boxed{
\mathrm{GapQueue}
\rightarrow
\mathrm{PhysicalPathFill}
\rightarrow
\mathrm{CausalAudit}
\rightarrow
\mathrm{GapRecalibration}
\rightarrow
\mathrm{NextQueue}
}
$$

Phase276 明确记录，这个循环已经成为当前工程路线。

所以更好的做法不是暂停补图谱，而是：

```text
一边继续 Batch Fill（批量补图谱），
一边升级 scoring（评分）、closure definition（闭合定义）、cross-model consistency（跨模型一致性）和 nonlinear coupling test（非线性耦合测试）。
```

也就是说：

```text
不要中断图谱工程；
但要把这些改进并入下一版 schema（数据结构）。
```

---

## 2. “样本量不足”要分层看

平均每个 family-model（语言族-模型）约 36 条确实不多，但当前最大瓶颈不是“更多普通样本”，而是：

```text
已有样本缺 component_path（组件路径）；
缺 causal_audit（因果审计）；
缺 closure_quality（闭合质量）。
```

Phase276 回算后，剩余缺口仍然很大：component_path（组件路径）从 954 降到 909，causal_audit（因果审计）从 959 降到 914，layer_path（层路径）从 891 降到 846。

所以现在优先级应该是：

```text
先补已有样本的物理路径；
再扩每族样本量；
最后做闭合。
```

---

## 3. “语义评估器”不能过早完全自动化

增强 semantic evaluator（语义评估器）是必要的，但不能一开始就全部交给另一个模型判分，否则会引入新的黑箱。

建议采用三层：

```text
第一层：规则判分；
第二层：span / alias / protocol score（片段 / 别名 / 协议分数）；
第三层：人工抽样复核或独立模型辅助判分。
```

尤其 high_quality_candidate（高质量候选）必须有人类可解释的判据，不应完全依赖模型评分。

---

# 三、最值得参考的地方

这份分析里最值得吸收的是 6 点：

```text
1. 图谱评分不能简单平均；
2. 闭合必须是硬条件，不是加权分数；
3. 跨模型矛盾必须显式记录；
4. 非线性耦合必须进入测试；
5. 机制主张要登记；
6. 从回顾性补图谱升级到预测性验证。
```

其中最重要的是前三点。

如果只做一个最小改造包，我建议下一步加入：

```text
current_gap（当前缺口）
cross_model_consistency（跨模型一致性）
closure_AND_status（闭合并且条件状态）
nonlinear_coupling_flag（非线性耦合标记）
claim_id（机制主张编号）
```

# 七、当前最应该怎么改

我建议不要把这份分析停留在文字层，而是落实成 v2（第二版）字段升级。

下一阶段可以设计成：

```text
Phase279：v2 评分与闭合判据校准
```

目标不是跑模型，而是升级图谱字段。

## 1. 新增字段

```text
original_gap（原始缺口）
current_gap（当前缺口）
cross_model_consistency（跨模型一致性）
closure_AND_status（闭合并且条件状态）
nonlinear_coupling_flag（非线性耦合标记）
claim_id（机制主张编号）
score_cap_reason（分数上限原因）
```

## 2. 新增评分规则

```text
如果 causal_audit 缺失，总分上限 0.55；
如果 closure_quality 缺失，总分上限 0.65；
如果 cross_model_conflict=True，不能标为 general_mechanism；
如果 nonlinear_coupling_flag=True，不能用线性 writer 解释。
```

## 3. 新增闭合状态

```text
not_tested（未测试）
proxy_only（只有代理）
path_candidate_not_closed（路径候选但未闭合）
high_quality_candidate_not_closed（高质量候选但未闭合）
closure_test_ready（闭合测试准备）
closed_local（局部闭合）
closed_cross_model（跨模型闭合）
```

这样图谱会更稳定。

# 八、最终结论

这份分析是正确的，特别值得参考的地方是：

```text
评分公式要改；
闭合必须是硬条件；
跨模型矛盾要显式记录；
非线性耦合要测试；
机制主张要登记；
不要用答对或读出强替代机制解释。
```

“回灌”就是：

```text
把新实验结果写回图谱，更新样本状态和分数。
```

“缺口”就是：

```text
图谱中某个样本或模式族还缺少的必要证据字段。
```

当前最正确的路线仍然是：

```text
图谱缺口识别
→ 队列生成
→ 三模型补图谱
→ 结果回灌
→ 缺口重算
→ 下一批队列
→ 高质量候选再做闭合终检。
```

这比继续做单点闭合更可靠，也更接近破解语言编码机制的目标。
