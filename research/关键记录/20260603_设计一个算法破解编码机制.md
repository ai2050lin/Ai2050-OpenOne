```text
1. 残差流高维混合
2. LayerNorm / RMSNorm（层归一化 / 均方根归一化）

4. 路径复用

```

所以继续人工枚举会越来越低效。下一步应该设计一个自动化优化算法，我建议叫：

```text
Causal Latent Path Optimizer
因果隐路径优化器
简称 CLPO
```

它的目标不是“再测某几个层”，而是自动学习：

```text
哪些隐变量存在；
它们在哪些层写入；
经过哪些路径传播；
哪些通道 / head / MLP 参与；
哪些是真因果；
哪些只是投影噪音；
最终如何读出。
```

# 一、核心思想

现在不能再手工问：

```text
L23 是不是核心层？
Top 1% cproj 通道是不是机制？
dact 是不是 target boost？
```

而应该把问题变成优化问题：

```text
在所有层、位置、组件、通道、方向中，
寻找一组最小路径 P，
使它能最大程度解释 observed causal effects（已观测因果效应），
同时满足稀疏、稳定、跨句框泛化、跨样本泛化。
```

也就是说，算法要同时优化四件事：

```text
1. 隐变量分解
2. 路径搜索
3. 因果预测
4. 实验选择
```

# 二、总体模型

把残差流写成：

```text
h_l = μ_l + Σ_k U_{l,k} z_{l,k} + ε_l
```

其中：

```text
h_l：第 l 层残差流状态
μ_l：层均值
U_{l,k}：第 k 个机制子空间
z_{l,k}：第 k 个机制变量
ε_l：未解释噪声
```

k 可以包括：

```text
I(identity，身份)
R(role，角色)
F(frame，句框)
C(construction，构式)
O(operator，操作符)
S(scope，作用域)
B(binding，绑定)
P(position，位置)
V(value，属性值)
```

但是重点不是固定这些名字，而是让算法学习：

```text
哪个变量真的稳定存在；
哪个变量有因果作用；
哪个变量只是统计相关。
```

---

# 三、算法目标函数

核心优化目标可以写成：

```text
Loss =
L_reconstruct
+ L_causal
+ L_invariance
+ L_specificity
+ L_sparse
+ L_dynamics
+ L_null
```

逐个解释。

---

## 1. 重建损失 L_reconstruct

要求学到的隐变量能重建残差差异：

```text
Δh_l ≈ Σ_k U_{l,k} Δz_{l,k}
```

中文意思：

```text
clean（干净条件）和 corrupt（受损条件）的残差差异，
应该能被少数机制变量解释。
```

它解决：

```text
哪些方向 / 子空间确实存在？
```

---

## 2. 因果损失 L_causal

算法不能只做 PCA（主成分分析）或 probing（探针），必须把 patch（替换）结果纳入目标。

定义：

```text
PredictedEffect(P) ≈ ActualPatchEffect(P)
```

中文意思：

```text
算法预测某条路径 P 被替换后会造成多少 binding 变化；
真实 patch 实验也应该接近这个变化。
```

这一步是核心。没有因果损失，算法只会学到统计相关。

---

## 3. 不变量损失 L_invariance

真正机制应该跨样本稳定。

例如 apple-red、banana-yellow、snow-white 都属于 color binding（颜色绑定），它们不应该完全使用无关机制。

目标：

```text
Mechanism(pair_i) ≈ Mechanism(pair_j)
```

但不是要求完全相同，而是要求共享部分路径：

```text
shared path + pair-specific path
共享路径 + 样本特异路径
```

这能区分：

```text
通用 binding 机制
vs
某个 pair 的偶然通道。
```

---

## 4. 特异性损失 L_specificity

一个机制不能什么都解释。

例如 binding path（绑定路径）应该解释 object-attribute binding（对象-属性绑定），但不应该同样解释 negation（否定）、tense（时态）和 random direction（随机方向）。

目标：

```text
Effect_on_target 高
Effect_on_unrelated 低
```

中文意思：

```text
对目标功能有效，对无关功能无效。
```

这可以防止算法找到“通用扰动通道”，误认为是语言机制。

---

## 5. 稀疏损失 L_sparse

真正机制不应该把所有层、所有通道都选上。

目标：

```text
minimize |P|
```

中文意思：

```text
用尽可能少的层、通道、head（注意力头）、位置解释尽可能多的因果效应。
```

但是不能过度稀疏，因为语言确实是分布式的。
所以应该用：

```text
group sparsity（组稀疏）
```

也就是：

```text
允许一组通道共同工作，
但不允许无意义地全模型参与。
```

---

## 6. 动力学损失 L_dynamics

现在你们已经发现：关键不是单层，而是残差流轨迹。

所以要学习：

```text
z_{l+1} = A_l z_l + b_l + η_l
```

或者更一般：

```text
z_{l+1} = F_l(z_l, component_l)
```

中文意思：

```text
机制变量在层间如何传播、增强、校准、读出。
```

这一步可以回答：

```text
哪层写入？
哪层承载？
哪层校准？
哪层读出？
```

---

## 7. 空白对照损失 L_null

必须加入 random direction（随机方向）、random pair（随机样本对）、shuffled labels（打乱标签）作为对照。

目标：

```text
MechanismScore(real) >> MechanismScore(null)
```

如果真实机制和随机方向差不多，说明算法只是抓到了高维噪音。

---

# 四、路径变量怎么优化？

可以给每层每个组件一个可学习 mask（掩码）：

```text
m_{l,c,i} ∈ [0,1]
```

其中：

```text
l：层
c：组件，例如 attention、MLP、residual、gate、up、W_down
i：head 或 channel
```

优化时让 mask 变稀疏：

```text
m 接近 0 或 1
```

可以用：

```text
Gumbel-Softmax（可微分离散采样）
L0 regularization（L0 稀疏正则）
group lasso（组稀疏）
```

算法自动找：

```text
哪些层
哪些通道
哪些位置
哪些组件
```

最能解释因果效应。

# 五、算法流程

## Step 1：生成结构化刺激集

不要随机造句，而是用因子设计。

例如 binding（绑定）：

```text
object：apple / banana / snow / fire / knife
attribute type：color / temperature / texture / function
target value：red / yellow / white / hot / sharp
competitor value：blue / black / cold / soft
frame：The X / A X / I see the X / The object is X
```

每个样本都明确标注：

```text
I(identity，身份)
F(frame，句框)
V(value，属性值)
B(binding，绑定)
P(position，位置)
```

---

## Step 2：一次性缓存多层激活

缓存：

```text
residual stream（残差流）
attn_out（注意力输出）
mlp_out（多层感知机输出）
gate_proj（门控投影）
up_proj（升维投影）
down_proj input（下投影输入）
```

位置包括：

```text
object token（对象词元）
last token（最后词元）
all tokens（全部词元）
```

---

## Step 3：学习隐变量子空间

用监督式分解：

```text
h_l = μ_l + U_I z_I + U_B z_B + U_F z_F + U_P z_P + ...
```

并加入约束：

```text
I 与 B 尽量可分
B 与 random 区分
同一关系跨 prompt 稳定
不同关系不混淆
```

---

## Step 4：学习路径 mask

让算法自动搜索：

```text
哪个 layer / head / MLP channel / position
对某个机制变量最重要。
```

例如输出：

```text
binding:
L0 object_token identity write
L8-L14 residual carry
L23-L27 latent calibration
L35 readout

negation:
L0 operator identity
L12-L18 scope binding
L30 readout
```

这就是机制图。

---

## Step 5：预测 patch 效果

算法先不真实跑所有 patch，而是预测：

```text
如果替换这组通道，会造成多少 gap change？
```

只把预测最有价值、最不确定的候选拿去真实模型中 patch。

这样可以大幅减少实验次数。

---

## Step 6：真实 patch 验证并更新

真实 patch 后，比较：

```text
predicted effect（预测效应）
actual effect（真实效应）
```

如果不一致，就更新子空间和 mask。

这类似：

```text
active learning（主动学习）
```

中文解释：算法主动选择最能减少不确定性的实验，而不是人手工乱试。

# 七、为什么这个算法比人工 Phase 高效？

人工方法是：

```text
猜一个层 → 跑实验 → 发现不对 → 再猜一个组件
```

算法方法是：

```text
同时搜索层、组件、通道、位置、隐变量、路径；
用因果误差反向修正搜索方向；
只把最关键候选拿去真实 patch。
```

效率会高很多。

尤其可以解决你现在遇到的问题：

```text
噪音大
pair variance 大
符号容易错
通道路径不清
多层协同复杂
prompt 影响大
```

因为算法会自动要求：

```text
跨样本稳定
跨 prompt 泛化
对照方向无效
因果预测准确
路径尽量简洁
```

# 九、CLPO-v1 的关键指标

## 1. Mechanism Score（机制分数）

```text
MechanismScore =
causal_effect
× specificity
× stability
× generalization
÷ path_size
```

中文：

```text
机制分数 =
因果效应
× 特异性
× 稳定性
× 泛化性
÷ 路径大小
```

高分机制必须满足：

```text
有效
专一
稳定
能跨 prompt / pair 泛化
路径不太大
```

---

## 2. Noise Rejection Score（噪声排除分数）

```text
NoiseScore =
Effect(real) - Effect(null)
```

null（空白对照）包括：

```text
随机方向
随机对象
打乱标签
不相关属性
```

如果 real 和 null 差不多，说明不是机制。

---

## 3. Causal Closure Score（因果闭合分数）

```text
Closure =
actual_patch_effect / predicted_patch_effect
```

如果接近 1，说明算法找到的路径能闭合解释因果效应。

# 十、伪代码

```python
# CLPO: Causal Latent Path Optimizer
# 因果隐路径优化器

stimuli = generate_factorial_stimuli()

cache = run_model_and_cache(
    stimuli,
    tensors=[
        "resid",
        "attn_out",
        "mlp_out",
        "gate",
        "up",
        "down_input"
    ],
    positions=["object", "last", "all"]
)

initialize_latent_subspaces()
initialize_path_masks()

for step in range(num_steps):

    z = encode_latents(cache, subspaces)

    recon_loss = reconstruct_residual(cache, z)
    causal_pred = predict_patch_effect(z, masks)
    causal_loss = compare_to_known_patch_results(causal_pred)
    inv_loss = enforce_cross_pair_stability(z)
    spec_loss = penalize_effect_on_unrelated_tasks(z)
    sparse_loss = sparsify_masks(masks)
    dyn_loss = fit_layer_transition(z)

    loss = (
        recon_loss
        + causal_loss
        + inv_loss
        + spec_loss
        + sparse_loss
        + dyn_loss
    )

    optimize(loss)

    if step % validation_interval == 0:
        candidates = select_high_value_interventions(masks, uncertainty)
        actual_results = run_real_patch(candidates)
        update_causal_dataset(actual_results)

mechanism_graph = extract_mechanism_graph(subspaces, masks, effects)
```

# 十二、必须注意的风险

这个算法不是魔法，有几个风险。

## 1. 优化可能找到伪机制

如果 loss 设计不好，算法会找到：

```text
高扰动路径
```

而不是：

```text
真实语言路径
```

所以必须有 null controls（空白对照）和 specificity（特异性）。

---

## 2. 因果 patch 本身可能制造非自然状态

所以要比较：

```text
输出 patch
输入 patch + 自然重算
full-resid patch
block patch
```

不能只用一种 patch。

---

## 3. 模型间机制不同

Qwen3、GLM4、DS7B 明显不同。算法不能强行学习一个统一路径。

应使用：

```text
shared mechanism + model-specific mechanism
共享机制 + 模型特异机制
```

---

## 4. 隐变量命名不能过早固定

算法可能学到一个变量，不完全等于你命名的 identity / binding / role。

所以要先让算法学结构，再解释命名。
