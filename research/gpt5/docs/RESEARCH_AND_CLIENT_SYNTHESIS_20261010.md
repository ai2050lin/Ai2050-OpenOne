## 第一部分：研究综合分析

### 1.1 项目定位与当前证据地图

项目目标三层：**外部语言族图谱**（词义—关系—角色—组合—语境）、**内部响应图谱**（embedding→HiddenState 场→unembedding）、**两图谱关联机制**（可执行算法 + 数学规律）。当前 G 线处于「图谱制度化」阶段，证据地图如下：

| 维度 | 现状 | 代表证据 |
|---|---|---|
| 特征登记表 | 23 特征 ×3 模型（qwen3-4b/14b/glm4-9b）全 scope | registry v1.6 `bebdf38d`，atlas_v1_7 `b2bcec66`，698 字段 0/0/0/0 |
| 证据分级 | E2_predictive ×16、E3 协议内因果 ×3、E1_repeatable ×4 | E 级 taxonomy：E0 候选→E1 可重复→E2 可预测（cross_model+held_out）→E3 因果 |
| 失败账本 | F1–F16（失败与成功同等入册） | F16 = FTR-14 held_out 门失败 → 3178 归因定量 → FTR-23 正面立项 |
| 缺口账本 | GAP-1/2/3 closed；GAP-4 quantified_collapse | 谱外类读出崩塌 2.54×：端口缺失 29%（干预校准可恢复）+ 结构性残留 ~1.8× |
| 跨线账本 | atlas_ledger n=331，append-only，双线共享 | 每条 measurement 带 prereg_id + res/seal sha8 双锁 |

### 1.2 关键机制成果（按条件化齿轮组主线组织）

1. **读出主干的份额分解**（3154）：KOUT 多因素份额 [Layer5.6, Syntax19.4, Content57.6, Grammar1.16, Depth0.31, Relation15.9]%——**内容主导但语法/关系合计 ~35%**，读出不是纯内容查表。
2. **T_C 变换代数**（3157/3159）：共享变换算子 T_C 三模型 cos≈0.56，注入消耗 91–94%，exch 交换带 partial（均值 1.27 ∈ [1.0,1.3]）——存在跨样本复用的算子骨架，但非完全对易。
3. **关系特异残差**（3177/3178/3179，最新拼图）：实体留出 null 标定下纯采样惩罚 p 仅 0.019–0.026（fold 级常为负），关系残差 r 0.072–0.131 ×3 模型——**T_C 按关系分解：关系内自洽、跨关系系统性偏移**。这是"条件化齿轮"最直接的量化指纹：共享算子 + 每关系一个偏移分量。
4. **可分性与接口**（3165/3166）：知识族与语法族编码子空间几何可分（top-1 主角 67–86°，远超 30° 门）——不同语义关系使用不同编码拓扑，不是同一空间里的强度差异。
5. **类别轴的样本边界**（3169–3175）：谱外类读出崩塌 2.54×，端口校准曲线证明 29% 是"端口缺训练信号"（少量校准行可恢复），残留 1.8× 是结构性成分——**读出端口的可插拔性有了干预级证据**。
6. **残差流全流分布式**（3163）：机制链收官——单点读出不存在（3161 无单点头），执行靠 attention 再分配（3160），写入端分布式（3162）。

### 1.3 方法论评价（这套制度做对了什么）

- **预注册 + 门冻结不移动**：每个 phase 的门在观测前钉定，失败如实登记（F 账本），杜绝事后挪门。3177 门失败 → 3178 归因 → 3179 正面立项，是"失败变现"的完整闭环。
- **双锁封存 + drift 0 复现**：res/seal sha8 内容锁 + 文件锁，任何后续 phase 对旧锚逐位复现（本轮 12 源 drift 0）。图谱每一条都可回查到具体 npz 与脚本。
- **append-only immutable 版本链**：registry/gap vN 逐版字节保全，升级只追加——图谱是审计级可追溯的，不是叙事级的。

### 1.4 硬伤与瓶颈（严格审视）

1. **覆盖面严重偏科**：23 特征集中在知识读出族 + 语法轴族 + 位置平移族 + 关系变换族。**推理族几乎空白**（G 线 logic tag 有材料未立表）、**角色/组合族空白**（施事/否定/语序）、**语境/多义族空白**（一词多义切换）。外部语言族图谱的"组合"与"语境"两大维度目前没有内部对应物。
2. **E2≠机制**：16 个 E2_predictive 特征是"cross_model+held_out 可预测"，不是"知道内部怎么算"。读得出≠控得住、指纹≠机制——3178 的 r(m) 是指纹级证据，偏移分量的参数来源（哪些层/头/参数承载）尚未定位。
3. **GAP-4 结构性残留未解**：1.8× 残留崩塌意味着类别系统在权重里有更深缺口，当前只有现象学定量，没有机制定位。
4. **模型面窄**：3 模型全为 4–14B 级、两家架构（qwen 系 + glm）。结论的外推边界（更大模型、 instruct vs base、其他架构）未测量。
5. **组合性未攻**：现有特征都是"单条件"测量；条件×条件的组合（知识内容×语法条件×语序）如何协同/竞争——这正是条件化齿轮组"组装"层，目前只有 exch 交换带一个雏形。
6. **零 GPU 依赖封存数据的隐性风险**：近 5 个 phase 全部零 GPU 复用 3157/3169 封存 npz，效率高但新材料摄入停滞；若封存材料本身有未察觉的采集偏差，会被多 phase 放大。

### 1.5 关键洞察：语言编码数学理论的第一性原理之路

当前证据收敛到一个候选图景：**LLM 用"低秩共享算子 + 关系/条件特异偏移"实现无限组合**——T_C cos≈0.56 说明存在跨样本复用的变换骨架（有限参数），r(m) 与 exch 带说明组合性来自偏移分量的可加叠加（无限组合），族间 67–86° 可分说明不同语言维度用不同子空间拓扑（维度分工）。下一步理论突破点是把 r(m) **参数化**：若能从"关系名 + 两端实体"预测偏移方向，就从指纹跃迁到预测理论，直接服务第三图谱（预测未见组合的内部响应）。

## 第二部分：研究建议（阶段性大任务，避免小功能堆叠）

### 大任务 T1：三族补全（图谱横向闭合，~10 phase 量级）
推理族（logic tag 材料已在手，零 GPU 起步）→ 角色/组合族（需新采集，GPU）→ 语境/多义族。每个新特征走完整五段式 + E 级阶梯。完成判据：外部语言族图谱六大维度（词义/关系/角色/组合/语境/任务）每维 ≥2 个 E1+ 特征。

### 大任务 T2：关系残差参数化（理论跃迁，最高优先级）
FTR-23 的 r(m) 目前是每关系每模型三个标量。预注册一组实验：(a) r(m) 的低秩结构——16 关系 × d 维偏移向量的谱分解；(b) 跨模型偏移方向对应性；(c) 用未测关系验证"从关系定义预测偏移"。产出候选数学表述：**ΔM_rel = T_C + R_rel，R_rel ∈ 低秩偏移子空间**。这是通向"语言背后数学结构"的第一性原理最短路径。

### 大任务 T3：GAP-4 结构性残留定位（缺口纵向闭合）
残留 1.8× 的机制假设二选一：类别端口子空间维度不足 vs 读出锥外无支撑。用 3171/3172 已验证的投影能量 + 干预校准组合拳，GPU 需求小。

### 大任务 T4：条件组合矩阵（齿轮组装）
从单条件走向 2×2 组合（知识×语法、关系×语序），检查组合响应可否由单条件响应叠加预测——不可加处即"条件齿轮啮合点"。这直接回应 AGENTS.md 5.2 条件统计路线。

### 纪律建议
- 恢复**新材料摄入**：每 3–4 个零 GPU phase 穿插一个 GPU 新采集 phase，防止封存偏差放大。
- 模型面扩展排在三族补全之后（同架构内跨规模已有 4b/14b 对照，架构外推缓行）。

## 第三部分：客户端优化方案

### 3.1 现状盘点

- **已落地**（ui_decoupled_plan v1/v2，M2+M3，e2e 27/27 + playwright 18/18）：LensProcess v3（流程骨架内容无关：五证据门/模型配置/composer/SSE 实时事件流）、RdcFusionWorkspace v5.1（URL 即状态、四透镜、⌘K 对象路由）、LIVE/DEMO 双模、内容层协议化（队列/文件树/工件三插槽全数据驱动）。
- **核心架构原则已验证**：协议是唯一稳定契约，界面是协议的通用渲染器；JSX 零实验字面量红线。
- **排队中**：UI v1.6 零 script 版改造（对应 atlas 渲染链的客户端化）。

### 3.2 主要缺口

1. **可视化空间缺失**：目标要求"可视化空间显示编码机制"，当前客户端是**卡片/表格/工件查看器**范式，atlas 仍以静态 HTML（698 字段）呈现——特征子空间几何（67–86° 主角谱、T_C 偏移、崩塌曲线）没有交互式视图。
2. **图谱与客户端脱节**：registry v1.6/atlas HTML 每轮重渲染，但客户端没有 `/api/atlas` 端点消费 registry JSON——23 特征卡、F 账本、GAP 账本、E 级徽章未进客户端。
3. **分布式拼图未闭环**：`GET /api/ai-rnd/queue` 只读 deepseek 线 phase_queue；G 线五段式循环（freeze→SMOKE→正式→verdict→closeout）没有队列/状态端点，终端无法认领 phase。
4. **证据链不可交互回溯**：res/seal sha8 双锁是研究侧强项，客户端未展示"点击特征→逐锚回查 npz/脚本/hash"的钻取路径。

### 3.3 优化方案（三阶段）

**阶段 A：图谱接入（对应 UI v1.6，纯读，~1 周量级）**
1. 服务端新增 `GET /api/atlas/registry`（读 atlas_registry_v1_6.json + 版本列表）、`GET /api/atlas/feature/{id}`（特征卡 + 锚 + counter_evidence）、`GET /api/atlas/ledger`（measurements 只读分页）。
2. 前端新增 AtlasLens（第五透镜）：特征卡瀑布（E 级徽章/family/模型 scope）、F 账本与 GAP 账本视图、每卡"证据链"侧栏 = anchors 逐条列 res/seal sha8。零 script 红线延续：组件只认协议键。
3. 版本切换器：v1.0→v1.6 registry 版本下拉，直观呈现"图谱生长史"。

**阶段 B：可视化空间（核心增量）**
4. **特征子空间地图**（WebGL/Three.js 或 ECharts gl）：以 3165/3166 主角谱为边、族为社区、特征为节点画知识/语法/推理/位置四族分离球——把 67–86° 可分性变成可旋转的几何对象；节点点击 → 阶段 A 特征卡。
5. **偏移向量场视图**（服务 T2）：T_C 共享骨架 + 每关系偏移 r(m) 画成"主干 + 须"的向量场，叠加 exch 带 [1.0,1.3] 着色——关系特异残差从表格变成形态。
6. **崩塌/校准曲线交互件**：GAP-4 的 ratio_B(k) 恢复曲线（k=0..8）与 2.54×/1.8× 分解条，参数滑块可回放 3169–3175 各锚数值。
7. 全部视图数据源 = registry/gap JSON 的协议键；demo 回退集中在 demoData.js（延续 M3 红线）。

**阶段 C：分布式拼图闭环（平台化）**
8. G 线队列端点：`GET /api/ai-rnd/queue/gline`（preregistered phase 列表 + 状态：preregistered/frozen/smoke/full/closed），与 deepseek 队列同构，双 tab 已预留。
9. 终端任务认领协议：终端 POST 认领 phase → 平台下发该 phase 的 execution.json + 锚清单 → 完成后 POST result sha8 → 五段式状态机推进。这是"大量终端完成图谱拼图"的机制基础：**拼图单位 = 特征升级臂（E1→E2）或新特征立表**，天然可并行（不同特征互不依赖，账本 append-only 天然合并）。
10. 冲突与质量：终端回传结果必须带 prereg_id + res/seal，服务端按 ledger sha 断言合并；重复测量同一特征 → 独立复核臂（天然复现性检查）。
11. 查询库三件套落地（AGENTS.md §10.1）：语言模式库/内部响应库/理论库以 fid/tm_id 路由（对象卡体系已备），状态徽章四档（有数据/已有观察/通过推广检查/有机制证据）。

### 3.4 优先级裁决

先 A 后 B 再 C。理由：A 是把已有最成熟资产（registry v1.6）接入客户端的最短路径，直接兑现"理论库"；B 依赖 A 的数据通道；C 的终端认领协议依赖 A/B 提供的"拼图单位"清晰化——当前图谱的 E 级制度恰好就是拼图任务的天然粒度。

## 结语

研究侧已建立罕见的审计级制度（预注册门 + 双锁封存 + append-only 账本），23 特征的图谱是真积累而非叙事积累；最大的科学缺口在**覆盖面（推理/角色/语境三族）与组合性（条件×条件）**，最大的理论机会在**关系残差参数化（T2）**。客户端的骨架与协议纪律已经正确，缺的是把图谱资产变成可交互空间（阶段 A/B）和把五段式循环变成可分布式认领的任务流（阶段 C）——两者合起来，"用大量终端拼完语言编码图谱"才从口号变成可执行的工程路径。
