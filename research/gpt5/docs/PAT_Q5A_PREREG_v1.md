# Q5-A 预注册：融合的形状是「赢家通吃」还是「加权」

日期：2026-11-01
上游：`PAT_Q5_CODING_SIGNATURE_PLAN_v1.md` §4（签名 S 位）
上游证据：Q4-R 边际中位 0.816（top1/top2 ≈ 5.4×）、置换一致 48/48
状态：**判据在跑前冻结**（本文档写入后不得修改阈值）。

---

## 0 要判什么

签名 S 位的唯一问题：**同一次前向里，多个候选模式是「加权求和」还是「争出一个赢家」**。

这个答案决定后面一切：若是加权，编码机制是稀疏线性组合；若是赢家，是路由串联。
两种类型的下游预测完全不同，所以必须先判它，且只能判一次。

---

## 1 三个量（各测一个侧面，互相印证）

设某格在某层的注意力为 `A ∈ R^{QH×T}`（每个 query 头在位置上独立 softmax，`A[h,:].sum()=1`），
三实体槽的跨度集合 `S_role`（多 token 人名跨 2 个位置）。

| 量 | 定义 | 测什么 |
|---|---|---|
| **三槽分布** `p3` | `mean_h A[h, S_·]`，在三个槽上重新归一化 | 槽与槽之间是否均分 |
| **三槽熵** `h3` | `H(p3)/log 3` ∈ [0,1] | 0=独占，1=均分 |
| **单点质量** `maxpos` | `max_pos mean_h A[h,pos]` | 0=全句均匀，1=所有头都钉在一个位置 |
| **头一致性** `unanim` | `max_k |{h: argmax_slot(h)=k}| / QH` | 1=全头同向，低=头间分工 |
| **三槽覆盖** `cover` | `mean_h Σ_{S} A[h,·]` | 三槽占全部注意力的多少 |

`unanim` 是**直接检验"多维度"假设**的量：若不同头负责语言/风格/逻辑等不同维度，
它们在同一句的同一查询下应当指向不同槽，`unanim` 会显著低于 1。
Q4-R 只看了**跨头求和后**的 argmax，从未看过逐头。

## 2 判据（跑前冻结）

主读数层：**L21–L23（Q4-R 确定的路由带）+ L28（l\*）**，共 4 层 × 144 格 = 576 个观测。
同时报全部 36 层剖面（D25：不许抽样打印）。

| 编号 | 判据 | 阈值 |
|---|---|---|
| **A1** | `median h3 ≤ 0.35` | 槽级：一个槽独占大部分质量 |
| **A2** | `median maxpos ≥ 0.60` | token 级：注意力钉在少数位置上 |
| **A3** | `median unanim ≥ 0.80` | 头级：全部头指向同一槽，**无维度分工** |
| **A4（框架前置）** | `median cover ≥ 0.40` | 三槽确实是注意力主战场 |
| **A5（冲突臂）** | 双查询句的 `h3` 减去单查询 `h3`，中位 **≥ 0.30** 判融合 | 见 §3 |

### 判决表

| 条件 | 判决 |

| `¬A4` | `FRAMEWORK_INVALID` —— 注意力大头不在实体槽上，"三槽竞争"这个词本身用错了，须换框架 |

## 3 冲突臂（A5）：真双查询

**构造**：`ctx + '是谁送的？送给了谁？'`（语言上合法，真的问了两件事）。
24 三元组 × 2 句式 = 48 次前向。

**逻辑**：
- 若 S=`argmax`，两个查询争同一个决策点 ⇒ 只能有一个赢 ⇒ 注意力仍集中在**一个**槽，
  `h3` 与单查询同量级。
- 若 S=`Σ`，两个查询的模式应可叠加 ⇒ 两个槽各得显著质量，`h3` 明显升高。

**备择解释（必须先排除）**：双查询句比单查询长，绝对位置偏移会让 RoPE 相位变化。
⇒ 同时跑一个**等长对照**：`ctx + '是谁送的？随便说说。'`（长度相当但第二个分句不是查询）。
A5 的差值用 **双查询 − 等长非查询**，而不是 − 单查询。这是防"长度混杂"的必要控制。

## 5 不能声称什么

即使判 `WINNER_TAKE_ALL`：

- 只判了 **S 位**，X / D / C 三位未测 ⇒ 不能写"编码机制已破解"。
- 只测了关系抽取句式 ⇒ 属于 t1 范围，T-v1 其余 7 个变换未做。
- `argmax` 是在 **32 头聚合后**观察到的。若 A3 成立（头一致），才可说"系统层面单选"；
  若 A3 不成立而 A1 成立，只能说"聚合后单选"，两层含义不同，必须分开写。
