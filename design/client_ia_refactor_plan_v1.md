## 2 问题清单（按严重度）

### P0-1 职责重叠：同一信息出现在 2–3 处

| 信息 | 出现位置 | 冲突 |
| --- | --- | --- |
| 研发队列/闭环 | 研发透镜（操作台）＋图谱透镜「研发闭环」tab＋总览「进行中」 | 3 处 |
| Phase 时间线/账本 | 图谱透镜「账本」＋脉络透镜「当前机器进度」（MAINLINE 硬编码） | 2 处，且脉络版是过期手工数据 |
| 技术覆盖度矩阵 | 总览「技术版图」＋研发透镜「缺口任务」＋LensData 按技术筛选 | 3 处 |
| 特征聚类视图 | 空间透镜「特征点云」＋图谱透镜「族地图」 | 2 处（一个几何、一个示意，缺互链说明） |

### P0-2 红线违规（零实验字面量）

- `LensProgress.jsx` 的 `MAINLINE` 数组硬编码 P4–P7 / Q03–Q06 等实验结论（Phase 12 处注释也自认 demo 接入点）——已过期（真账本已到 P3206），属"第二事实源腐化"，正是总览瘦身注释里防过的问题。

### P1-3 定位混乱：透镜命名与内容不符

- 「脉络透镜」实为 730 行大杂烩：行业进展 + 平台运维 + 教程文档 + 技术成熟度 + 协议说明 + 机器进度，六个不同受众的东西堆在一个透镜。
- 「分析技术」顶栏名叫透镜、导航叫"技术"，与「图谱」的从属关系（技术产出的结果进图谱）没有在界面上表达。
- AtlasLens 昨日新增的「研发闭环」tab 与研发透镜职责冲突（当时为回答整合问题快速叠加，加剧了重叠——本方案将其撤销改链）。

### P1-4 结构性混乱：10 个专项图谱页是孤岛

- 同一研究项目的 10 张图谱被切成 10 个独立全页：无统一壳、无返回工作台、互相跳转靠记忆 URL。
- 工作台的图谱透镜（registry 协议渲染器）与这 10 页（各自定制渲染）是两套并行的"图谱 UI 哲学"。

### P2-5 杂项

- 顶栏两个"演示选择器"（模型/特征源）不可用仍占首位；`fw-bell` 通知徽标硬编码 2；分享按钮是 alert 占位。
- demo 数据文件（demoData/distributedData 1097 行）承载了已被 LIVE 端点取代的内容。

## 3 目标信息架构：五轴模型

**核心主张：一个对象、五条轴、每条信息只有一个家。**

```
               ┌─────────────────────────────────────────────┐
               │  对象轴（看什么）                              │
               │  空间透镜 = 结构几何      图谱透镜 = 语义/证据   │
               ├─────────────────────────────────────────────┤
  顶栏对象路由  │  生产轴（正在进行）    研发透镜（唯一队列）      │
  ──────────→  ├─────────────────────────────────────────────┤
               │  知识轴（已经沉淀）    图谱透镜·账本（唯一时间线）│
               ├─────────────────────────────────────────────┤
               │  技术轴（用什么工具）  技术透镜（唯一技术/结果）  │
               ├─────────────────────────────────────────────┤
               │  外部轴（别人在哪）    进展透镜（行业+平台，纯外部）│
               └─────────────────────────────────────────────┘
```

### 3.1 分工规则（唯一归属）

| 信息 | 唯一归属 | 其他位置只允许"摘要 + 跳转" |
| --- | --- | --- |
| 研发队列/闭环流程 | 研发透镜 | 总览 1 条 next；图谱特征详情放锚点（P 链接） |
| Phase 账本/时间线 | 图谱透镜·账本 | 脉络透镜删除机器进度 |
| 技术覆盖度矩阵 | 技术透镜 | 总览只留 4 张入口卡 |
| 特征聚类 | 空间透镜（几何）；族地图保留但注明"语义示意，几何看空间透镜"并加互链 | — |
| 行业/平台动态 | 进展透镜 | — |
| 教程/协议说明 | 总览底部折叠区（或 ？帮助键） | 从脉络透镜迁出 |

### 3.2 目标导航（fw-rail，6 项变 5 项 + 分组）

```
总览        （使命 + 入口 + 关键数字，删技术版图矩阵）
─ 对象 ─
空间        （结构几何，不变）
图谱        （registry / 族地图 / 账本 / 专项视图…）
─ 生产 ─
研发        （队列/工作区/终端，不变）
技术        （技术注册表 + 结果 + 覆盖度矩阵，从总览迁入）
─ 外部 ─
进展        （行业进展 + 平台进度两个 tab，删机器进度/教程/协议卡）
```

### 3.3 专项图谱页的归宿（分三步，不返工）

1. **P2 加壳**：10 个专项页套统一壳（顶栏 + 返回工作台 + 左右页互链），路由表化；工作台图谱透镜加「专项视图」目录页（第 5 个 tab），列出 10 页按研究主题分组的入口。
2. **P3 协议化**：逐页把定制渲染改为 registry 协议渲染器（同 AtlasLens 范式），每完成一页就从独立路由降级为图谱透镜子视图。
3. **终态**：main.jsx 只剩 `/`（工作台）与 `/legacy`；10 页全部成为图谱透镜的「专项视图」子页。

## 5 验收标准

- 任何一条信息在导航中只有一个"家"，其余出现处必须带跳转链接。
- 每个透镜一屏内能说清自己回答什么问题（透镜头部加一句定位语）。
- 零实验字面量：LensProgress MAINLINE 类硬编码清零；JSX 中的数字全部来自协议端点。
- 从任何页面（含 10 个专项页）≤2 次点击回到总览。
