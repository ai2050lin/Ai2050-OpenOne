# 路线-图谱界面重构 · 三版本方案（v1）

> 2026-10-11。针对 AtlasLens v1.6 现状不满意的三个方向性重构方案。
> 现状：4 tab（图谱全景三模 / 跨线账本 / 结果库 / 模板与技术），全景=三域泳道 SVG，详情=遮挡式抽屉。

---

## 0. 现状痛点（三个方案的共同靶子）

1. **跨 tab 跳转割裂证据链**：从特征（全景）→ 它的证据（账本）→ 它的产物（结果库）要切 3 个 tab，上下文丢失。
2. **详情抽屉是遮挡式**：点开特征详情盖住全景，失去"这个特征在图谱里处于什么位置"的参照。
3. **全景是静态海报**：三域泳道 SVG 一次画死，26 特征密度下节点小、无缩放、无局部聚焦。
4. **账本与特征两个世界**：账本按 Phase 组织，特征按族组织，二者只靠 anchors 文本弱关联。

三个方案分别以 **作业效率（A）/ 空间认知（B）/ 时间演化（C）** 为主轴，取其一或组合。

---

## 方案 A · 研究工作台（三栏联动，IDE 式）

**主轴：以特征为作业中心。**

```
┌─────────────┬──────────────────────────┬────────────┐
│ 图谱树导航    │ 详情画布（选中对象主角）      │ 上下文面板   │
│ 搜索/过滤     │ 陈述·读数·复现协议·证据链     │ 账本 tail   │
│ 域→族→特征    │ 模式:特征|账本条目|结果|模板  │ 相关结果     │
│ 交叉 X1-X3   │                           │ 覆盖度      │
└─────────────┴──────────────────────────┴────────────┘
```

- **左栏**：域→族→特征树 + 全文搜索 + E 级/机制过滤器（树节点=一次点击唯一入口）。
- **中栏**：选中对象的完整详情（不再是遮挡抽屉）；无选中时显示三域全景缩略（复用 AtlasPanorama）。
- **右栏**：账本 tail（n=374 最近 N 条）、该特征关联结果（npz/sha8）、域覆盖度。
- **tab 全部消失**：账本/结果库/模板与技术 = 中栏的内容模式（由左栏或面包屑切换）。
- **URL**：`?lens=atlas&sel=FTR-23&mode=feature` 全状态可分享。
- **数据结构**：零改动——纯前端重组，tree/registry/ledger 三端点照旧。
- **成本**：中。AtlasLens 大改（~1 个会话），AtlasTree 变左栏、AtlasPanorama 变中栏缩略、FeatureDetail 变画布主体。

**优点**：查证效率最高，特征→证据→结果一屏打通；与总览驾驶舱、顶栏特征源选择器天然衔接。
**缺点**：全景从主角降为配角，"看图谱整体"的观感弱化。

## 方案 B · 沉浸式图谱画布（地图式）

**主轴：空间认知优先，画布即界面。**

- 三域泳道放大为**占满全高的唯一主视图**：节点按域/族聚簇布局，支持滚轮缩放、拖拽平移、框选族聚焦。
- **左上浮动卡**：域覆盖度（三域进度条常驻）；**顶栏浮动**：机制横切过滤 chips（MEC-01–07）。
- **点击节点 → 悬浮卡**（锚定节点旁，非遮挡式）：陈述摘要 + 读数 + `展开证据链 ↓` 就地内联展开。
- **底部 dock**：账本 n=374 / 结果库 / 模板×技术三个入口，点击上滑为半屏抽屉（可再拖高）。
- **URL**：`?lens=atlas&sel=FTR-08&zoom=1.6&xy=…`（视口状态可分享）。
- **数据结构**：零端点改动；画布布局器需新增（确定性坐标，延续零实验字面量红线——坐标由域/族/索引公式派生）。
- **成本**：大（~2 个会话）：缩放画布 + 布局器 + dock 抽屉体系。

**优点**：最符合"机制图谱是使命主产物"的定位，演示/大屏/截图汇报效果最强；探索式浏览体验最好。
**缺点**：实施最重；缩放交互在右栏 400px 宽度下受限（需给路线-图谱更宽的画幅或全屏模式）；作业效率不如 A。

## 方案 C · 证据流叙事（时间线驱动）

**主轴：研究是过程，图谱是累积的结果。**

```
┌──────────────────────────────────────────────┐
│ 当前态条: KN 11/12 · AR 3/3 · GR 6/8 [展开全景] │
├──────────────────────────────────────────────┤
│ P3222 ● 会话总结封存          SEALED 52ba5d3a  │
│ P3215 ● GAP-4 closed（五连闭环）  → FTR-05/19/20│
│ P3180 ● FTR-15 E1→E2 PASS（16 fold 全过）      │
│ P3179 ● FTR-23 立项入册 → 升级链在同一根线上    │
│ … ↓ 回溯 n=374（虚拟滚动）                     │
└──────────────────────────────────────────────┘
```

- 主体 = **垂直证据流**：每个 Phase 一张卡（verdict / 交付物 / 关联特征 chips / res·seal sha8），虚拟滚动回溯全账本。
- **特征的升级链内联在流中**：P3179 立项 → P3180 升级在同一根时间线上连续呈现——"一个特征怎么长出 E2"第一次可直接看见。
- **顶部当前态条**：三域覆盖度 + E 级分布，点击展开三域全景（此时全景是"当前快照"，证据流是"如何到达这里"）。
- **过滤器**：按特征 FTR-xx 过滤流（= 该特征的完整生命史）、按线（G/N）、按 verdict。
- **URL**：`?lens=atlas&stream=FTR-23`。
- **数据结构**：ledger 已含全部所需（phase/name/line/verdict/date + anchors 反查），零端点改动；虚拟滚动需引入列表虚拟化（26→374 条无压力，普通分页亦可）。
- **成本**：中低（~1 个会话）。

**优点**：最适合"研究进展回顾/汇报/写作素材"；升级链可视化是另外两个方案没有的独有价值；实现最轻。
**缺点**：空间结构弱化（图谱退化为一根时间线）；找"某个特征现在什么状态"不如 A 直接。

## 对比与组合建议

| 维度 | A 工作台 | B 沉浸画布 | C 证据流 |
|---|---|---|---|
| 主轴 | 特征作业 | 空间认知 | 时间演化 |
| 跨证据链跳转 | ★★★ | ★★ | ★★★ |
| 整体观感/演示 | ★ | ★★★ | ★ |
| 研究回顾/汇报 | ★ | ★ | ★★★ |
| 实施成本 | 中 | 大 | 中低 |
| 数据端点改动 | 零 | 零 | 零 |

**组合路线（推荐分两步）**：
1. **先落 A**（解决日常查证割裂，最痛）；A 的中栏保留"全景缩略"作为无选中态默认。
2. **A 稳定后把 C 做成 A 的一个中栏模式**（`mode=stream`）——A 管"现在什么状态"，C 管"怎么来的"，二者天然互补；B 的缩放画布作为远期项（等 Phase C 的 SAM-xx token 样本锚定后，画布才有真正的下钻深度）。

**不变项（三案共同）**：全部数据端点（tree/registry/ledger/results）、LIVE/DEMO 双模、零实验字面量红线、`?atlasSel=` 协议键、总览驾驶舱与顶栏特征源选择器复用关系。

**选择即回复**：「方案 A」「方案 B」「方案 C」「A+C 组合」或指定混搭（如"A 的骨架 + B 的悬浮卡"）。
