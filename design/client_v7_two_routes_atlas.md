# 客户端与中心 v7 系统方案：语言为主的两路线拼图图谱

> 2026-10-26 · 新设计。M1（语言树、路线 T 拼图、四个只读端点）与 M2（客户端三界面，入口 `/atlas`，暂不替换默认首页）已实现，M3–M4 未实现。M2 实现时：3D 层结构用零依赖 canvas 投影（与 Space3D 同一方式），每个语言项占层板一条通道、条长按该语言项各层最大值归一化，下方配同一数值的二维热力表与逐层数值表。M1 实现时的两处修订：嵌入层基线从宽判定（见 §2.1 注）；可读出判据复制在 `pieces.py`，不改 `analysis.py`。基于 1.0.7（离线客户端 + 数据包）、catalog.v1、analysis.v1、atlas.v1、mlp_census.v1 与 Phase 254–260 的神经元解释 / 消融结果。
> 前身：`atlas_domain_tree_scheme_v1.md`（三域树）、`client_v6_pipeline_ia.md`（四界面工作台）。本方案取代 v6 的信息架构，数据层仍是现有真源端点的派生。

## 0. 目标

1. **以语言为主**：用户先选「类型 → 类别 → 语言项」（可按语种筛选），再看该语言项在 LLM 内部对应什么规则。
2. **两条路线都能积累拼图**：
   - 路线 T（自顶向下，语言 → 内部）：受控模板对照，产出「某层某读出位置的方向 / 可读出层段」。
   - 路线 N（自底向上，内部 → 语言）：原生 MLP 单元普查、解释与消融，产出「某层某单元的职能」。
   两条路线写入同一种拼图记录，挂到同一棵语言树上，覆盖知识网络、功能推理、语法规则三种类型。
3. **客户端只剩三个界面**：
   - 图谱：看各语言的研究情况。
   - 3D 空间：在一个多层 LLM 模型上看各语言的编码。
   - 进展：了解进度、参与操作、观察研究。

## 1. 语言组织：lang_tree.v1

### 1.1 四级结构

```
类型 type      KN 知识网络 / RS 功能推理 / GR 语法规则（三种主类型）
类别 category  例：KN.分类关系、KN.属性、RS.否定与真值、RS.因果与条件、GR.句类、GR.论元角色……
语言项 item    可被一个或多个模式族检验的具体语言现象：KN.ISA 上下位、GR.Q 疑问、GR.NEG 否定、GR.ROLE 施事/受事……
实例 example   该语言项的具体例句与 token（来自冻结模板材料与单元卡片段），只作展示与回查，不单独评级
```

- **语种**（中文 / English / 其他）是语言项上的筛选维度，不另成一层：同一语言项可在多语种上各自记录结果。
- 现有 `module` 中的 SQ（序列）、ST（风格）、TK（任务功能）先放进「扩展」分组并默认折叠；只有在证据足够时才升为第四种类型。
- **交叉项**（如「否定」既是语法也是真值推理）只存储一次：有一个主类型，另以 `also_in` 列出其他类型，在树上可以多处出现。这一点沿用三域树方案的 H1 结论。

### 1.2 存储

- 新文件 `shared/dist_protocol/lang_tree.json`：人工维护，带版本号，随中心发布。
  - 每个语言项包含 `id`、`name`、`type`、`category`、`also_in`、`languages`、`desc`、`examples` 和 `neuron_tags`。`neuron_tags` 是路线 N 的解释标签词表。
- 文法新增可选字段 `lang_items: {factor: item_id}`，声明每个因子检验哪个语言项，并在冻结时随 design_sha 记录。
  - 旧文法没有这个字段时，由 `lang_tree.json` 里的 `family_map` 补映射。这样旧结果不需要重跑。

## 2. 拼图记录：piece.v1（两条路线共用）

AGENTS §5.3 的「特征卡」在本方案中落地为 piece。一张 piece 只描述一个模型快照上的一处内部结构。

| 字段 | 路线 T（模板） | 路线 N（神经元） |
| --- | --- | --- |
| `id` | `T:<tm_id>:<factor>:<model_key>` | `N:<model_key>:L<block>:u<unit>` |
| `lang_item` | 文法 `lang_items` 映射 | 解释标签 → 语言项；只有经过模板确认的才计入（见 §2.2） |
| `locus` | 读出位置 + 可读出层段 + 峰值层；方向本体存放在 tm 附加包 | 层 + 单元索引 + 符号区（++ / −−） |
| `layer_curve` | 逐层留出投影间隔与 η²，并给出 hs[0] 嵌入基线 | 无（单元只在一层），记录所在层 |
| `readout` | logit-lens 读出 | W_U(γ⊙W_down[:,j]) 的前后 token |
| `evidence` | 三轴分开：读出 / 控制 / 解释（见 §2.1） | 同左 |
| `counter` | 未通过的句式、行为门失败的格 | 远距强激活、近似反例失败 |
| `source` | tm_id、结果 sha、analysis 缓存名 | 普查 run、EXPL / L30 研究文件、预注册 sha |

### 2.1 证据等级（两条路线用同一把尺，三轴分开显示，不合并成一个分数）

| 级 | 读出轴（是否编码） | 控制轴（是否被使用） |
| --- | --- | --- |
| 0 | 未研究 | 未检验 |
| 1 | 有数据（行为门通过 / 普查已覆盖） | — |
| 2 | discovery 上可读出 / 有可检验解释 | — |
| 3 | 留出划分复现（未见词表 / 未见句式；解释在检验集上胜出） | 条件化消融显著 |
| 4 | 跨族或跨模型复现 | 预注册干预在留出材料上显著 |

注（M1 实现）：路线 T 的等级 3 要求同一读出位置的 hs[0] 各样本相同或不可分；hs[0] 探针高于机会 + margin 即视为 token 身份（不要求置换检验，基线从宽），没有 hs[0] 记录时也不升到 3。实测：GR-NEG 的 mood 在 final 位置 hs[0] 探针已达 1.0（句末标点不同），因此不计；EXT.LANG（语种）在 hs[0] 已可分，停在 2。

**解释轴**单独记录：解释是否通过三方隔离检验，以及是否只能在语料中识别。等级由 `pieces.py` 中固定的 `CRITERIA` 判定，判据随结果返回；不由任务数或上传次数自动晋级。

### 2.2 路线 N 进入语言树的条件（新算法，计划）

单元解释是自由文本，不能直接当作语言项的证据。分两步：

1. **标签**：解释代理在 `lang_tree.neuron_tags` 的固定词表中选 0–2 个标签，没有合适的就选「未归类」。这一步只是候选。
2. **模板确认**：用该语言项已冻结的模板材料，对单元跑 neurons.v1 选择性检验（discovery 拟合，留出同号复现）。
   - 通过的单元才挂到语言项下，读出轴记为 3。
   - 未通过的单元留在「未归类 / 候选」区，不计入该语言项的覆盖。

### 2.3 两路线会合（新算法，计划）

对同一模型、同一层、同一语言项，计算单元写出方向 W_down[:,j] 与路线 T 白化方向 d 的 cos，并与随机单元构成的零分布比较：

$$
z_j = \frac{\cos(W_{\text{down}}[:,j],\ d^{(L)}_{\text{item}}) - \mu_{\text{null}}}{\sigma_{\text{null}}}
$$

- z 超过固定阈值且该单元通过 §2.2 的模板确认时，记一条 `meet` 边。这条边连接了「语言变量的方向」和「承载它的单元」，是两张图谱之间最直接的关联。
- 会合只说明方向相近。说该单元承载了这个变量，需要另做累积消融（Q2）。

## 3. 中心服务（服务器）

### 3.1 新模块

| 文件 | 职责 |
| --- | --- |
| `shared/dist_protocol/lang_tree.json` | 语言树与旧族映射 |
| `shared/dist_protocol/pieces.py`（pieces.v1） | 从 analysis 缓存、atlas、普查清单、研究产物（EXPL / L30 的 JSON）生成 piece；固定 `CRITERIA`；计算 §2.3 的会合 |
| `deploy/snapshot_worker.py` | 新增 `lang_atlas` 与 `space_overlay` 两个快照阶段，沿用 Guard 崩溃跳过与数据指纹 |
| `deploy/platform_service.py` | 新路由（见下），都是读快照文件 |

### 3.2 端点（都是只读的快照，小体积，进主数据包）

| 端点 | 内容 | 体积预估 |
| --- | --- | --- |
| `/api/lang/tree` | 语言树 + 每个语言项在每个模型上的两路线状态（等级、piece 数、最近更新时间） | < 200 KB |
| `/api/lang/item/{item_id}` | 该语言项的全部 piece、会合边、反例、回查链接 | 每项 < 100 KB |
| `/api/model/skeleton?model_key=` | 真实模型结构：层数、d_model、MLP 宽度、attention 头数、归一化位置，来自 summary / 普查 manifest 中记录的 config | < 5 KB |
| `/api/space/overlay?model_key=` | 每个语言项的逐层曲线（路线 T）与单元位置（路线 N），只含标量和索引，不含原始向量 | 每模型 < 1 MB |

- 离线客户端：这四类都进主数据包，所以 3D 默认场景不需要下载附加包。
- 点云、方向本体、单元卡全文仍在已有的 `tm:<family>` / `cards:<model>` 附加包里，属于次要视图，按需下载。

### 3.3 不变的部分

- 分布式协议、合并口径、审计、普查分片、账号、数据包机制都不改。
- 写操作（冻结、审计、普查、自动测试）继续只在网页版，离线客户端只读。

## 4. 客户端：三个界面

```
┌ 顶栏：Ai2050 · [图谱] [3D 空间] [进展] ············ 模型▾  语种▾  数据包状态  账号 ┐
```

模型与语种是全局选择，三个界面共用；切换界面时保留所选语言项。

### 4.1 图谱（默认首页）

```
┌──────────────┬─────────────────────────────────────────┬──────────────────┐
│ 语言树        │ 该类别的语言项卡片                          │ 语言项详情          │
│ ▾ 知识网络     │ ┌ 上下位 ─────┐ ┌ 属性 ──────┐           │ 疑问（GR.Q）        │
│   分类关系     │ │ T ●●●○ N ●○○ │ │ T ●●○○ N ○  │           │ 内部规则：           │
│   属性        │ └──────────────┘ └────────────┘           │ · T：L12–L24 可读出，│
│ ▾ 功能推理     │   （T = 模板路线等级，N = 神经元路线等级）   │   峰值 L18，超出 hs[0]│
│ ▾ 语法规则     │                                           │ · N：3 个单元经模板确认│
│ ▸ 扩展        │ 空白项显示「未研究」与「领题」入口              │ · 会合：L18 u4412   │
│              │                                           │ [在 3D 中查看] [反例] │
└──────────────┴─────────────────────────────────────────┴──────────────────┘
```

- 卡片同时显示两条路线的等级。读出轴与控制轴用符号加文字标示，不用一个合成百分比。
- 详情面板用文字写出「该语言在 LLM 内部的规则」：每条规则都来自一个 piece，带证据等级和回查链接（运行、结果 sha、研究文件）。
- 类型下的空白区域本身就是研究缺口。目前功能推理类几乎是空的，界面如实显示为「未研究」。

### 4.2 3D 空间

**默认场景：一个模型的多层结构，加上所选语言项的编码。**

- **骨架**来自 `/api/model/skeleton` 的真实结构，例如 Qwen3-4B 有 36 层。
  - 每层画一块薄板，纵轴为层序（hs[0] 在最下面）。
  - 板内位置 = 单元索引排布（9728 个单元按固定网格排列），图例写明「层序真实；板内位置是索引排布，不代表模型几何」。
  - 没有数据的模型只显示骨架和空态说明，不画假激活。
- **路线 T 叠加**：板边沿的色带表示该语言项在该层的留出投影间隔（单色相，由浅到深），hs[0] 基线单独标出，峰值层加描边。
- **路线 N 叠加**：通过模板确认的单元在对应层板上显示为点，按符号区上色；候选单元显示为空心点，默认隐藏。
- **会合边**：路线 T 峰值标记与对应单元之间画连线，标明「方向相近，不等于计算连接」。
- 左侧是紧凑的语言树，可以多选语言项进行对照（最多 4 个，按固定顺序分配颜色）。
- 点击任一层、单元或色带，弹出数值面板（原始数值、所在运行、回查链接）。

### 4.3 进展

一页，三段：

1. **进度**：按类型列出两条路线的语言项覆盖。数据来源分开计数，不拼成转化率。另列最近新增的 piece 和等级变化。
2. **参与**：题库（领题命令、一键包）、数据包下载与更新。网页版额外提供管理员工位的入口链接。
3. **观察研究**：选一个已有运行，查看材料、行为门、规律分析报告，这是现有研究包内容。以后接入「输入一句话」：节点前向后显示被激活的 piece，并与模型真实输出对比，这是 AGENTS §10.2 的设计要求。

## 6. 风险与边界

- 骨架与板内排布是示意，必须在图上写明，不能当作 HiddenState 几何。
- 语言树的分类是展示层组织，不是模型内部结构的事实；交叉项和「扩展」类会长期存在。
- 路线 N 目前只有 Qwen3-4B 的普查数据；路线 T 有三个模型。3D 场景按模型切换，方向和单元不跨模型比较。
- 功能推理类目前几乎没有已冻结的模式族；图谱会如实显示大片「未研究」，这本身就是选题依据。
- 路线 N 的解释标签来自代理，必须经过模板确认才计入覆盖，否则图谱会被未经检验的解释填满。
