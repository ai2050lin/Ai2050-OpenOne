# AI2050 分布式语言测试平台规范 v1

日期：2026-10-14 · 状态：服务器端与客户端均已实现并通过测试；客户端实施状态见第 8.5 节

本规范把平台的四件事定成可执行的约定：**怎样测**（测试方法）、**交什么**（结果格式）、**怎样看**（3D 可视化）、
**怎样从分布式结果里挖出语言谱图**（挖掘算法）。所有数字判据都固定在代码里并随结果返回，看到结果后不得修改。

## 0. 参与方式：任何用户的完整路径

```text
客户端连接中心 ──► 题库（GET /api/catalog）：按类别看题目、冻结版本、各模型的测试状态
   │
   ├─► 本地测试：领取分片（node_agent --tm-id）→ 本机 GPU 运行 runner_v3 → 回传充分统计量
   │      或在中心所在机器上「研发 · 自动测试」一键跑「模型 × 模式族」
   │
   ├─► 下载研究包（GET /api/export/{tm}?bucket=）→ 本地 3D 观察、复算（不需要再连服务器）
   │
   └─► 语言谱图（GET /api/atlas）→ 跨模式族的共享编码轴、概念假设、跨模型一致性
          └─► AI 解读（POST /api/atlas/interpret）→ 可检验假设（未检验）→ 写成新模式族 → 回到题库
```

- 任何人都可以注册节点（`POST /api/nodes/register`，返回节点令牌），领取分片并回传；结果先过自动检查与审计，才进入合并。
- 写操作（冻结模板、审计裁决、自动测试、AI 解读）需要中心管理令牌。
- 题库中的「已完成」只描述数据：至少一个模型桶的分片齐全、可以合并。它不是证据等级。

## 1. 测试方法

### 1.1 题目 = 模式族文法（template_grammar.v1）

一个题目是一个**模式族**：句式框架 × 填充词表 × 因子水平。每个「框架 × 填充」组合生成一条样本，
条件 = 框架水平 ∪ 填充水平。文法放在 `shared/dist_protocol/grammars/`，类别由 `module` 决定：

| module | 类别 | 现有模式族 |
|---|---|---|
| KN | 知识网络 | KN-ISA（上下位）、KN-ATTR（属性绑定） |
| GR | 语法系统 | GR-NEG（否定 × 语气）、GR-ROLE（施事/受事 × 构式） |
| RS / SQ / ST / TK | 分析推理 / 序列与多维 / 风格与语用 / 任务功能 | 待建 |

必备字段：`family_id`、`module`、`factors`、`frames`（含 `levels`、`target` 槽位、行为 `probe`）、`fillers`、
`splits`、`layers`、`shards`、`prereg`。新增可选字段：

- **`concepts`**：`{"因子=水平": "概念"}`，**预注册跨族假设**。例如 KN-ISA 的 `frame=interrog`、KN-ATTR 的
  `frame=question`、GR-NEG 的 `mood=interrog` 都声明为「疑问」：研究者事先声明这些水平应共享编码，谱图挖掘
  检验它，而不是事后找关联。键必须对应已定义的因子水平（`grammar.validate` 检查）。

### 1.2 切分与防泄漏

- 按**填充词**确定性切分 discovery / confirm / lockbox（同一个词的全部句式落在同一划分），lockbox = 未见词表。
- `heldout_frames` 进入 lockbox_frame = 未见句式。
- 发现只用 discovery；所有「预测」只在没参与发现的划分上检验。

### 1.3 行为门

每个句式配 probe（prompt → answer），runner 记录答案首 token 是否 top-1。条件格准确率低于
`prereg.min_behavior_acc`（默认 0.8）时，该格不进入任何内部分析：模型没做对的任务，不能作为它具备对应内部机制的正例。
冻结正式模板前先冻结**试跑版**看逐格行为门。

### 1.4 采集口径（runner_v3）

- 位置：目标槽位的最后一个 token（按字符偏移定位，不用字符串查找）。
- 层：`layers`（first / mid / last 或整数层号）对应 `hidden_states` 下标；0 = 嵌入输出。
- 精度：bf16 / fp16 / fp32，与 `model_id`、`model_rev` 一起构成**模型桶**；不同桶不合并、不跨桶平均方向。
- 每个模板包附 4 条金丝雀输入：同一模型桶内各节点的金丝雀摘要必须在容差内一致，否则结果记为漂移并排除。

### 1.5 冻结、分片、审计

- 冻结 = 语料 + runner 写入 `design_sha`；看到结果后不得改阈值；改文法或 runner 会升 version，旧版本结果不再合并。
- 模板 `shards` 个分片；中心优先派发「该模型尚无结果」的分片，其中完成次数最少者；重复分片只做一致性检查。
- 每份结果自动检查（设计一致、真实运行、产物齐全、金丝雀、行为门、分片、Work Unit），再人工裁决；
  有 fail 项时不能判通过。审计只决定能否进入合并。

## 2. 结果格式

| schema | 谁产生 | 内容 |
|---|---|---|

| `catalog.v1` | 中心 | 题库：类别、题目、冻结版本、按模型的状态、领取命令、研究包地址、贡献者 |

## 3. 3D 可视化方案

平台有两个 3D 空间，回答不同的问题，坐标含义必须在界面上写明。

### 3.1 样本响应空间（单模式族，analysis.v1）——已实现

- **每个点 = 一条样本**在某层的表示。坐标：在白化空间中按某因子的 LDA 判别方向（只用 discovery 拟合，
  所有划分投影到同一组轴），或原始空间 PCA，或「层堆叠」（各层 2D LDA 沿 z 轴排列，Procrustes 对齐相邻层，
  画出各水平质心的跨层轨迹）。
- **编码**：颜色 = 因子水平 / 划分 / 作答对错（类别色板固定顺序）；形状 = 划分（实心点 discovery/confirm、
  空心环 lockbox 未见词表、菱形 lockbox_frame 未见句式）；大圆 = discovery 质心。
- **交互**：拖动旋转、滚轮缩放、悬停显示原句与条件。
- **读图规则**：轴长与方向只表示相对结构，不是模型原生坐标；「未见」的点落进对应质心附近 = 推广成立。

### 3.2 特征谱图空间（跨模式族，atlas.v1）——服务器已提供数据，客户端待实现

- **每个点 = 一个特征**：某模式族某因子某水平在某层的对比方向（第 4.2 节）。坐标 = 该层全部特征单位方向的
  经典 MDS（距离 √(2−2cos)），前三维。方向相近的特征靠在一起。
- **编码**：颜色 = 模式族；实心 = 稳定特征（未见词表复现），空心 = 不稳定，菱形 = 只出现在留出句式的水平；
  点大小 = 效应/噪声；**边** = 跨族边，颜色 = 所属共享编码轴，线宽 = cos；轴成员外加半透明包络与轴标签
  （概念名，未预注册的轴标「新发现候选」）。
- **交互**：层选择（first/mid/last）、模型选择；点击轴 → 侧栏显示成员、平均 cos、留一族迁移、跨模型复现、
  对应规律陈述；点击特征 → 跳到该模式族的样本响应空间并选中对应层与因子。
- **读图规则**：靠得近 = 表示方向相近；只在同一模型内有意义。共享方向不等于共享机制。

### 3.3 共同规则

- 真实数据与合成/演示数据分开：合成模型桶常驻黄色横幅；没有数据时显示空态，不回退演示值。
- 状态始终「符号 + 文字」；顺序量用单色蓝阶，正负量用蓝↔红加灰中点；类别色板固定顺序。
- 研究包可离线载入：客户端读 `analysis.json`（样本响应空间）与 `atlas.json`（特征谱图空间）即可完整渲染。

## 4. 挖掘算法

两级：先在每个模式族内部找稳定特征（analysis.v1，已有），再跨模式族把稳定特征连成语言谱图（atlas.v1，新增）。

### 4.1 单模式族（analysis.v1）

在 discovery 上拟合、留出划分上检验：校正迹 η²（因子、词身份）、白化方向复现 cos、最近质心探针准确率、
按单位（填充词 / 句式 / 样本）整体打乱标签的置换零分布、句式不变性矩阵、split-half 可靠交互（可加性）、
词身份超额方差、格内长度偏相关；按固定判据生成「支持 / 未支持 / 注意 / 描述」规律陈述。

### 4.2 跨模式族语言谱图（atlas.v1，`shared/dist_protocol/atlas.py`）

输入：同一模型桶下、分片齐全的各模式族合并统计量（行为门已排除不达标格）。同一模型、同一层的 HiddenState
在同一坐标系里，所以不同模式族的方向可以直接比较；不同模型之间只比较图结构。

1. **特征**。模式族 f 的因子 F 的水平 ℓ：先按条件格求均值，再对含 ℓ 的格等权平均得 m_ℓ（平衡其他因子）。
   对比方向 v_ℓ = m_ℓ − μ，μ 为该组的基线。discovery 与 lockbox 各估一次；
   **稳定特征**：cos(v^disc, v^lock) ≥ 0.5（在没参与发现的词上复现）。
2. **基线与共享轴交替估计**。模型：m_ℓ = μ + a_k（ℓ 属于共享轴 k）或 μ + b_ℓ（未解释，Σb = 0）。
   μ 只由未解释的水平定义；已并入共享轴的水平不进入基线，于是共享成分不会经由本族平均泄漏到其他水平的对比里。
   未解释水平少于 2 个时，μ = 平均(m_ℓ − a_k(ℓ))。每找到一条轴，就交替更新 μ 与 a_k 再继续找下一条。
3. **边**（同层、跨族的稳定特征对）：discovery 与 lockbox 两次估计的 cos 都 ≥ 0.3（两组互不重叠的词各自复现），
   且相对该层全部跨族特征对 cos 的**经验零分布**（中位数 ± 1.4826·MAD；绝大多数特征对互不相关）的稳健 z ≥ 3。
   跨族特征对少于 20 时不用零分布，并在结果中标注。
4. **共享编码轴**：以最强的边为种子贪心生长，每次加入「与当前成员中严格过半成边」的特征，每个（模式族, 因子）
   至多一个水平，至少覆盖 2 个模式族。**留一族迁移**：用其他族成员的 discovery 方向预测留出族在 lockbox 上的方向，
   平均 cos ≥ 0.5 → 「支持」。
5. **预注册概念假设**：对 `concepts` 中出现在 ≥ 2 个模式族的概念，检查被声明的跨族特征对是否全部成边；
   只出现在留出句式的水平做**未见句式预测**（其他族同概念方向 vs 该水平在 lockbox_frame 上的方向，cos ≥ 0.5）。
   全部成边且留出预测通过 → 支持；部分 → 部分支持；无 → 未支持。没被声明的边记为「新发现（未预注册）」。
6. **跨模型**：同一特征对（族/因子/水平/层）在其他模型中是否也成边 → 复现率；轴按成员重叠（Jaccard ≥ 0.5）匹配。
7. **3D 坐标**：每层全部特征单位方向的经典 MDS（第 3.2 节）。

判据（`atlas.CRITERIA`，随结果返回）：`min_rep 0.5 · min_cos 0.3 · min_z 3.0 · min_null_pairs 20 · min_transfer 0.5 · min_families 2`。

**验证**（`tests/dist_protocol/test_atlas.py`）：
- 在三个模式族植入共享「疑问」方向（只在 mid/last），找回两层的共享轴、概念假设支持、迁移通过、first 层不出现；
- 负对照（各族疑问方向独立）不报告任何共享轴、概念假设「未支持」；
- 同时植入「疑问」「陈述」且一族只有两个水平（基线泄漏最严重的情形）：每条轴只对应一个概念，
  未声明的水平不被并入；留出句式水平的预测通过；
- 跨模型复现、AI 摘要/提示词/回复解析、维度不一致的族被排除。

沙盒端到端（2 个合成模型 × 4 个模式族，合成 runner 按 `concepts` 植入共享方向，属于阳性对照）：每个模型
在三层各找回「疑问」「陈述」两条轴且无多余轴，留一族迁移 0.78–0.90，KN-ATTR 留出句式「question」预测 cos 0.75，
跨模型边复现率 100%。**这只验证方法与流程，不代表任何真实模型。**

**证据边界**：共享方向说明这些条件在该层用了相近的表示方向；是否共享同一计算机制，需要沿轴做干预
（选择性：只改变对应条件；必要性：消去后对应行为下降），这属于证据门链 8–9，当前协议不判定。

### 4.3 AI 分析的规范

1. 中心生成**谱图摘要**（只含统计结果与 id，不含原始向量）和提示词；提示词要求输出 ≤ 5 个 JSON 假设，每个必须有
   可被推翻的预测、建议的新模式族（因子、水平、句式示例、`concepts` 预注册）、主要替代解释。
2. 用「研发 · Agent 工作流」配置的主模型回答；不可用时返回提示词，用户可复制到任何 AI。
3. 解析出的假设一律标「未检验」，追加保存到 `<AI2050_DIST_DIR>/atlas/hypotheses.jsonl`，不进入证据。
4. 假设 → 写成新模式族文法（concepts 预注册）→ 冻结 → 测试 → 谱图检验。只有这一步之后才有结论。

### 5.1 账号（accounts.v1，`shared/dist_protocol/accounts.py`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/auth/status` | `{has_users, registration, can_register, first_user_becomes_admin, user}`；带有效会话时附当前用户 |
| POST | `/api/auth/register` `{username, password, display_name?, email?}` | 自助注册（第一个账号为管理员；`AI2050_REGISTRATION=closed` 时只允许第一个账号），返回 `{token, user}` |
| POST | `/api/auth/login` `{username, password}` | 返回 `{token, user}`；连续 5 次失败锁定 5 分钟（423） |
| GET | `/api/auth/me` · POST `/api/auth/logout` | 当前用户 / 注销当前会话 |
| POST | `/api/auth/password` `{old_password, new_password}` | 修改密码；保留当前会话，其他会话失效 |
| GET/POST | `/api/auth/users` · POST `/api/auth/users/{user_id}` `{role?, disabled?}` | 管理员：账号列表、创建账号、改角色、停用（至少保留一个管理员） |
| POST | `/api/auth/node-code` · GET `/api/auth/my-nodes` | 一次性节点绑定码（30 分钟）/ 我的节点 |

- 会话：`Authorization: Bearer <token>`，32 字节随机令牌，库中只存 sha256，30 天无活动过期（滑动续期）。
- 授权：所有写接口的 `X-Admin-Token` 既接受中心管理令牌，也接受**管理员账号的会话令牌**；成员会话不能做写操作。读接口不要求登录（研究包、谱图保持开放）。
- 节点：`/api/nodes/register` 可带 `bind_code`，节点 `owner_user_id` 归属该账号；`/api/catalog` 贡献者带 `owner`。
- 客户端：`AuthGate` 启动时调 `/api/auth/status`：有效会话 → 主界面；无会话 → 注册（第一次打开 / 没有账号时默认注册页）或登录；中心不可达但本机有会话 → 进入主界面并标记离线。顶栏账号菜单：我的节点、修改密码、账号管理（管理员）、退出登录。

## 6. 版本与兼容

- 三个文法增加了 `concepts`（KN-ISA、KN-ATTR、GR-NEG：疑问 / 陈述），runner_v3 的合成模式按概念植入共享方向。
  文法与 runner 都进入 design_sha：**这些模式族下次冻结会升 version**，旧版本结果不再参与合并（真实结果需按新版本重跑）。
- atlas 只用分片齐全的模型桶；不齐的在 `sources` 中列出原因。

---

## 7. 已知限制

- 谱图只比较「同层同坐标」的水平对比方向；同一概念若在不同模式族里落在不同层，需要逐层查看，当前不做跨层匹配。
- 只有两个水平的因子，两个水平的对比方向互为相反数，它们不能各自独立成为两个概念的证据。
- 经验零分布假设大多数跨族特征对互不相关；模式族很少时（跨族特征对 < 20）只用 cos 阈值。
- 开放参与目前靠节点令牌 + 金丝雀 + 审计保证数据可信；还没有用户账户、配额与信誉体系。

同时修正的服务器问题：
- 中心服务改为每个线程一个 SQLite 连接（客户端同时请求总览、题库、谱图时，共用连接会报 `sqlite3.InterfaceError`）；40 个并发读请求零失败。

### 8.6 交付顺序（原计划）

1. 研发 · 题库 + 总览 · 题库概览（让所有用户先能「看到题、领到题」）。
2. 空间 · 下载 / 打开研究包（本地观察闭环）。
3. 空间 · 语言谱图 3D + 路线 · 跨族机制候选链（谱图挖掘的主界面）。
4. AI 解读 → 模板草稿 → 假设队列（AI 辅助闭环）。
