# 图谱界面方案评估：对照 2026 机制可解释性进展与项目核心目标

日期：2026-10-13 06:10 ｜ 评估对象：`atlas_module_view_scheme_v1.md`（三模块视图）+ `atlas_template_space3d_mockup_v1.html`（模板 3D 空间）
评估基准：核心目标 = **通过大量语言模板，找到 LLM 内部语言编码机制的规律，破解语言原理**

---

## 1. 行业现状对照（2026-10 联网核实）

| 行业进展 | 要点 | 与本项目/本方案的关系 |

## 2. 项目自身证据链对 UI 方案的约束

1. **FTR-16 / F20（读得出≠控得住 ×2 配方）**：任何「模板 → 机制」关联展示都必须携带 E 级与 scope_limits，否则界面会制度化「读出即机制」的谬误——这是本方案最大的认识论风险，也是 E 级着色设计的价值所在。
2. **GAP-4 / u*（谱外崩塌共享方向，跨类共享几何）**：共享几何结构横跨模块边界，模块硬分法必须让位于「横切结构一等公民」（现方案的 MEC strip 和交叉边方向正确，但权重太低）。
3. **E_read=0.3734（5% 门 0/3）**：读出误差基线远未闭合，模板卡的指标展示必须显示「距闭合有多远」，而不只是「有指标」。
4. **F 账本制度（F1–F20）**：行业 2026 才进入 SAE 自我批判期，项目的失败入账本纪律是超前实践；UI 应把失败/反证渲染为与特征同级的信息（现方案仅在详情抽屉里）。
5. **AGENTS.md §2**：模式族分类「可重叠、嵌套、随语境变化」——三模块 + 归位表预注册有冻结早产本体论的风险，须保留修订通道。

## 3. 方案评估

### 3.1 做对了什么（与目标对齐的部分）

- **关联边一等公民**：行业从 features → circuits/relations 的转向证明「关系」才是规律载体；方案把「模板↔机制关联」从两个孤立 tab 提升为核心数据结构，方向与 attribution graph 范式兼容。
- **缺口可视化**（part_of、TM-06 无锚定；AR 仅 FTR-03）：把「覆盖度会计」做成首屏信息。若此机制早存在，水果类 OOV（GAP-4）会更早浮出水面。**这是方案对「找规律」最实质的贡献**。
- **E 级证据着色入 UI**：Neuronpedia / Gemma Scope 系工具均无证据分级；项目把 E1/E2/E3 渲染进每个节点，是对行业工具的一个真实增量。
- **协议键驱动、零实验字面量、LIVE/DEMO 空态**：与「interpretation 必须可回查」的行业标准（causal abstraction）一致。

### 3.2 硬伤与瓶颈（按严重度排序）

**H1 · 规模断层（致命，直接冲突核心目标）。** 目标是「大量语言模板」（千级才谈得上统计规律），方案是 12 个模板 + 手工归位表 + 逐条预注册的关联表。行业教训（auto-interp、circuit identification 的人力瓶颈）表明：**任何需要人工逐条登记的关联制度都无法跨越两个数量级**。归位表预注册纪律在 26 特征时代是优点，在 2000 模板时代是堵点。

**H2 · 关联是回溯性标签，不是发现引擎。** 现有关联全部派生自已知 anchors——UI 回答「我们已知什么」，不能回答「跨 500 个模板反复出现的同一种内部结构是什么」。**「找规律」需要的是跨模板不变量挖掘层**（同一提取算法 × N 模板 → 复发结构聚类），方案中没有这一层。这是从「图谱浏览器」到「规律发现机器」的关键缺失。

**H3 · 行为闭环缺位。** 项目自己的两个配方（FTR-16 C_steer=0、F20 dR 失败）+ 行业 SAE steering 不稳定性共同证明：没有干预臂的「机制」关联可信度有上限。模板卡没有 E3/干预状态位，3D 空间里 E3 特征（仅 3 个）淹没在 E2 海洋中，界面会系统性高估已有证据强度。

**H4 · 3D 聚簇布局的认识论风险（中）。** 模块聚簇 + 黄金角布点是决策表的可视化，但 3D 形态天然邀请「距离=关系」的几何解读。AGENTS.md §10.2 已立规「图布局距离不能当作真实几何」，界面虽有标注，但三模块硬分法被空间化后，本体论冻结风险被放大（对照 LHE 2026：机制域特异但几何跨域共享——共享几何在聚簇布局里恰恰最难看清）。

**H5 · 与行业工具链零互操作（中低）。** attribution graph 工具已开源且覆盖 12+ 开源模型；Gemma Scope 2 提供全层 transcoder。项目的 qwen3/glm4 无公共 SAE/transcoder 套件，自训成本高。方案没有为「per-template 电路视图」预留挂载点，等于在静态图谱上另起炉灶，放弃了站在行业基础设施上的可能。

**H6 · 模板家族的近重复泄漏控制未入 UI（低但真实）。** AGENTS.md §5.1 要求改写/翻译/实体替换保留家族关系防泄漏；模板 3D 空间的「同族边」只画了关系族/最小对标签，没有承载「训练/留出划分」信息——模板规模化后这会变成真问题。

## 4. 改进路线（分阶段，对应硬伤）

| 阶段 | 动作 | 对应硬伤 |
| --- | --- | --- |
| **P0 关联自动派生** | 废手工归位表主路径：从 ledger/anchors 反查自动建模板↔特征反向索引，关联置信度 = 底层 anchor 的 E 级聚合；手工表降级为「争议仲裁」通道 | H1 |
| **P1 规律挖掘视图（核心增量）** | 新增「不变量面板」：提取算法 × 模板 的复发矩阵（哪种方向/子空间/门控在多少模板、多少模型、多少 held-out 折上复现）；面板按复发强度排序——这才是「找规律」的引擎 | H2 |
| **P2 模板规模化管线** | 组合式模板族生成（实体×关系×句式×风格×语言 网格）+ 近重复家族划分入协议；UI 改聚合优先（模块→族→模板三级钻取），平面 3D 千节点不可行，3D 空间只渲染聚合层 | H1/H6 |
| **P3 行为臂入卡** | 每模板卡增 E3/干预状态芯片（steer/patch/消融结果挂载）；E3 特征在全景中升视觉权重；「距闭合距离」替代裸指标（对照 E_read 0.3734 vs 5% 门） | H3 |
| **P4 行业互操作** | 预留 attribution-graph 挂载点（per-template 电路视图）；评估 Jacobian-lens 式因果读出升级 KOUT 面板；NLA 式自动解释作为辅助标注层 | H5 |
| **P5 本体论保护** | 归位表版本化 + 修订历史入 UI；横切结构（u* 类共享几何）提升为与三模块平行的第一视图，而非底部 strip | H4 |

## 5. 结论

**方案作为「证据组织与缺口管理层」：合格，且 E 级着色 + 缺口可视化是对行业工具的真实增量，建议采纳为 v1 信息架构。**

**方案作为「通过大量模板发现语言编码规律」的引擎：不完整。** 三个结构性缺失——关联自动派生（H1）、跨模板不变量挖掘视图（H2）、行为闭环（H3）——恰好都在「发现」一侧而不在「展示」一侧。若按现方案落地，得到的会是一个高质量的**已知证据浏览器**，而不是**规律发现机器**；继续美化展示层的边际收益已递减。

**下一步的最高杠杆不是 UI 迭代，而是 P1（不变量面板）+ P2（模板规模化管线）**：前者定义「规律」在数据里的可操作形态（复发矩阵），后者解决统计功效。UI 应围绕这两个数据产物重组，而不是反过来。

与行业的相对位置：项目规避了 SAE 不稳定性整类风险（原生坐标路线），在「读得出≠控得住」上是行业共识的独立先验证据；短板是模型规模小（4B–14B）与工具链孤立——P4 互操作是低成本补位。
