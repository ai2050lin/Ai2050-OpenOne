# 客户端 v8 方案：两条主线 + 分支（待确认）

> 2026-10-27 · 第 5 节的方向已确认，已实施：服务端 neuron_layers.v1（/api/neurons/layer、/api/neurons/tower）与 lang_atlas 扩展（例句、行为门、点云、选择性、config），客户端 `frontend/src/components/v8/`（/atlas，取代 v7）。2026-10-27 追加：开放平台首页（/）并入同一外壳——顶部导航「首页 · ① 语言图谱 · ② 神经元 · 参与」，网页版另有「研究工作台 ↗」；学习方法、进展、响应点云、谱图关系进「更多」；首页精简为定位 + 两条主线入口（带真实计数）+ 参与 + 普查进度；旧 `?tab=` 链接自动换算。实施时的差异：单元卡复用已有的 NeuronUnitCard，上方另加「对应的语言特征」；分型对全部块按 L30-v1 规则计算（块 30 与 L30-v1 计数一致），其他块标为描述性应用。原型：`design/mockups/client_v8_mainline_prototype.html`（嵌入真实数据片段，可点击）。
> 取代 v7 的「图谱 / 3D 空间 / 进展」三页结构；v7 已实现的端点（lang_atlas.v1）与组件尽量复用。

## 0. 为什么要改

v7 及之前的客户端按「研究流程」组织（总览、空间、研发、路线、进展），同一份数据在多个页面以不同形式出现，新用户不知道从哪里看起。v8 只保留两条主线，其余功能都作为主线上的分支，从主线的具体位置跳过去。

## 1. 结构

```
顶栏： AI2050 │ ① 语言图谱 │ ② 神经元 │ ············ 模型▾ │ 更多▾（进展 · 参与 · 工作台）
```

| 主线 | 用户问题 | 页面主体 |
| --- | --- | --- |
| ① 语言图谱 | 某种语言现象在 LLM 里是怎样编码的 | 大类 → 语言族 → 语言项；语言项页按固定六节从「是什么」讲到「由哪些神经元承载」 |
| ② 神经元 | 模型某一层里面有什么，某个神经元在做什么 | 3D 层塔（全部层）→ 点击层：层内结构 + 神经元阵列 → 点击神经元：单元卡（特征） |

两条主线互相连接：
- 语言项页「由哪些神经元承载」中，点击一个神经元，会跳到主线 ②，定位到该层与该神经元。
- 单元卡「对应的语言特征」中，点击一个语言项，会跳回主线 ①。

分支（不进主导航，从主线内的按钮或「更多」进入）：
- 进展（覆盖统计）
- 参与（领题、一键包）
- 本地包
- 工作台（管理操作，只在网页版提供）
- 次要视图（谱图关系、证据门链）

## 2. 主线 ① 语言图谱

### 2.1 语言分类

| 层级 | 内容 | 例 |
| --- | --- | --- |
| 大类 | 知识网络 / 功能推理 / 语法规则（另有「扩展」默认折叠） | 语法规则 |
| 语言族 | 大类下的语言族（即 lang_tree 的类别） | 句类、论元角色、句式 |
| 语言项 | 可用一个或多个模式族检验的具体现象 | 疑问 / 陈述 |

- 大类用左侧三个大按钮切换。
- 语言族与语言项显示为一棵树，每个语言项前带状态符号：○ 未研究，◔ 有数据，◑ 可读出，◕ 留出复现，● 跨模型。
- 没有模式族的语言项也显示出来，作为研究缺口。

### 2.2 语言项页（固定六节，自上而下阅读）

| 节 | 回答 | 可视化 | 数据来源 |
| --- | --- | --- | --- |
| A 这是什么 | 语言现象的定义与最小对 | 对照例句，高亮读出 token；标出区分信息出现的位置 | 文法 frames + 填充词 |
| B 模型能不能做到 | 行为门：模型是否答对 | 探针问题、可接受答案与对照答案、逐格准确率 | behavior（合并统计） |
| C 在哪一层被编码 | 哪些层能读出、峰值在哪、是否只是 token 身份 | 层曲线：每个读出位置一条线，实心点 = 未见词表上可读出，hs[0] 基线单独标出 | lang_atlas piece 曲线 |
| D 编码长什么样 | 峰值层上两类样本是否分开、留出样本落在哪里 | 二维点云（LDA），留出样本用空心环 | analysis coords |
| E 由哪些神经元承载 | 每层有多少神经元对该变量有选择性、最强的是哪些 | 逐层柱状图 + 峰值层前列单元列表，单元可点击跳到主线 ② | neurons.v1 选择性 |
| F 证据与结论 | 每条规则的证据等级、跨模型情况、反例 | 规则列表 + 等级标记（读出 / 控制 / 解释三轴） | lang_atlas rules |

某一节没有数据时显示「未测」及下一步做法，例如领题或设计模板，不留空白，也不用示意数据填充。

## 3. 主线 ② 神经元

### 3.1 3D 层塔
- 一块板代表一层：嵌入层在底部，输出头在顶部，中间是全部 Transformer 块（Qwen3-4B 为 36 块）。层数来自模型骨架。
- 板的颜色表示一个可切换的叠加量（单一色相，从浅到深）：
  - 已解释单元数
  - 某语言项的选择性单元数（从主线 ① 带过来）
  - 无
- 可以拖动旋转、滚轮缩放。点击某块板即选中该层，旁边显示该层详情。

### 3.2 层详情（右侧）

**层内结构图**：按真实配置画出一个块内部的计算顺序：
```
输入残差 → RMSNorm → 自注意力（32 个查询头 / 8 组 KV，每头 128 维，RoPE）→ ＋残差
         → RMSNorm → MLP：gate / up 2560→9728，SwiGLU A = silu(G)⊙V，down 9728→2560 → ＋残差 → 输出残差
```
- 图中每个模块都可以点击。
- MLP 中间单元有普查数据，点开显示神经元阵列。
- 注意力头目前没有逐头分析，显示「规划中」。

**神经元阵列**：9,728 个 MLP 中间单元，按真实索引排成网格，每格一个单元。
- 着色可选：
  - 单元类型（T1 单 token 检测器 … T6 其他；目前只有第 30 层分了类型）
  - 解释等级
  - 选择性（当前语言项）
  - 激活密度
- 可以按着色量排序；排序是显式操作，会标明「已排序」。
- 悬停显示编号与一句话摘要，点击打开单元卡。

### 3.3 单元卡（神经元对应的特征）

| 区块 | 内容 |
| --- | --- |
| 身份 | 模型快照、块号、单元号；注明这是「MLP 中间单元，不是残差流坐标」 |
| 一句话解释 | 解释文本、等级（文本可复现 / 只在语料中可识别 / 未解释），附预注册与检验结果 |
| 激活分布 | 1,900 万 token 上的直方图（symlog 横轴，按 ++ / −− / +− / −+ 符号区分色堆叠），以及强激活频率（如「约每 3 页一次」） |
| 极值上下文 | 正极与负极前若干段原文，高亮命中 token |
| 直接读出 | 推高 / 压低的 token（W_U(γ⊙W_down[:,j])，直接通路近似） |
| 对应的语言特征 | 在哪些模式族上有选择性（语言项、读出位置、效应量），可点击跳回主线 ① |
| 因果检验 | 消融、归因、触发点检验结果；没有就写「未检验」 |
| 注意事项 | 极值片段的选择偏差等说明 |

## 4. 需要新增的服务端数据（实现时）

| 新增 | 内容 | 来源 |
| --- | --- | --- |
| `/api/neurons/layer?model_key&block` | 一个块的逐单元摘要：激活密度、最大值、主导符号区、读出首 token、是否已解释、类型（有则给） | 普查合并结果 mlp_census.v1（每块 9,728 行，约 0.3 MB） |
| `/api/neurons/tower?model_key` | 每块的叠加量：已解释数、各模式族的选择性单元数 | 解释检验结果 + neurons.v1 选择性 |
| 模型骨架补充 | 注意力头数、KV 组数、head_dim、RoPE、词表大小 | 模型快照中的 config.json（只记录配置，不读权重） |
| 语言项详情补充 | 行为门逐格准确率、峰值层二维坐标（抽样 ≤ 400 点）、对照例句 | 合并统计 + analysis 缓存 + 文法 |

以上都由后台子进程生成快照，进入主数据包或按模型分开的附加包；离线客户端照常可用。

## 6. 原待确认问题（已在第 5 节作答）

1. **语言分类的第一层**：用「知识网络 / 功能推理 / 语法规则」三大类，还是先按语种（中文 / 英文）分，再按大类分？原型用前者，语种作为筛选条件。
2. **神经元阵列的排列**：按真实索引排（不失真，但相邻格子没有功能关系），还是按功能聚类布局（直观，但布局本身会失真）？原型默认按索引排列，另提供「按着色量排序」。
3. **注意力头**：目前没有逐头数据。v8 先只画结构，还是把逐头分析（Q3）列为下一步研究？
4. **默认入口**：v8 是否替换开放平台首页（/）成为默认入口？原来的首页、学习页和 /workbench 是否收进「更多」？
5. **模型范围**：神经元主线目前只有 Qwen3-4B 有普查数据。其他模型在主线 ② 是显示「未普查」，还是暂时只提供 Qwen3-4B？
