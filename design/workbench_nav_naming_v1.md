涉及：`frontend/src/components/app/workbenchUtil.js` 的 `LENSES`、`frontend/src/components/app/Workbench.jsx` 左轨与子导航

## 1. 三个入口现在装的是什么（按代码实读）

| 现名 | id | 实际内容（来源文件） |
|---|---|---|
| 进展 | `route` | `v8/RouteLens.jsx`：自然语料普查 → 逐层摘要与分型 → 解释检验 → 模板选择性（各项分开计数）；语言项在各模型上的读出轴等级；路线板 |
| 空间 | `spatial` | `v8/SpaceLens.jsx`：左侧常驻 3D 层塔（页内自称「LLM 多层结构」）+ 模型选择 + 叠加量；右侧神经元阵列/单元卡、语言图谱、响应点云、谱图关系、本地包 |
| 研发 | `process` | 题库、模板工作室、试跑与冻结、分发与节点、审计队列、普查作业（自动测试仅本机中心） |

## 2. 诊断：三个词不在同一维度

1. **维度混用**：`进展`＝完成度（时间轴）、`空间`＝结构、`研发`＝活动。并列时读者会本能寻找共同点，找不到就只记住三个模糊标签。
2. **「空间」与页内自称打架**：`SpaceLens.jsx:69` 左侧标题写的就是「LLM 多层结构」，一级入口却叫「空间」。空间是大词罩小事，真正指向的是模型内部结构。
3. **「研发」易被读成写代码**：图标是 `</>` 尖括号（`Workbench.jsx` 的 `LensIcon.process`），暗示更强。实际是出题→冻结→分发→审计的实验生产与治理链。
4. **「进展」把结论说成过程**：读者要的是「你们发现了什么」，看到的是「做到哪一步」。它对页面里的计数与等级最贴，但与另外两词不同类。二级 tab 已改为「神经元逆向分析」「语言图谱」（去掉「进展」二字），说明该词在两层间重复。

## 3. 候选方案

| 方案 | 三词 | 读法 | 适合 | 短板 |
|---|---|---|---|---|
| **A（推荐）** | 证据 / 结构 / 实验 | 已知什么 → 它在哪 → 怎么验 | 与内部术语一一对应：证据等级 E0–E3、LLM 多层结构、题库→审计实验链；二级标题无需再解释 | 「证据」略学术，外部读者需一次说明 |
| **B（最小改动）** | 进展 / 结构 / 实验 | 只换两个词 | 风险最低，保留「进展」与计数/分型的贴合 | 三词仍不同维度，仍显别扭 |
| **C（口语）** | 进度 / 模型 / 作业 | 新人零学习成本 | 对外/新人友好 | 「模型」歧义大（模型管理？下载？）；「作业」偏运维 |
| **D（叙事）** | 发现 / 图谱 / 流水线 | 最有叙事感 | 对外介绍页好看 | 「发现」与失败账本、未接入状态不符；「流水线」三字破坏左轨 2 字整齐 |

推荐 A 的核心理由：三个词都是「可指认的对象」而不是「程度/活动」，并列才平；且能把一级名与页面内既有自称统一（结构 = LLM 多层结构），消除自相矛盾。

## 4. 若实施，改动清单（方案 A）

| 位置 | 改动 |
|---|---|
| `workbenchUtil.js` `LENSES` | `label` 三处 + `desc` 写准；**`id` 一律不动**（`route`/`spatial`/`process`） |
| `Workbench.jsx:129` | 子导航 aria-label「空间视图」→「结构视图」 |

**成本与风险**：id 不变 ⇒ `?lens=route&view=neuron` 深链、书签、旧入口全部照旧；顶栏标题 `研究工作台 · ${label}` 自动跟随；无数据结构与接口改动。风险仅剩视觉回归（左轨 2 字宽度、图标视觉权重），五视图冒烟即可覆盖。
