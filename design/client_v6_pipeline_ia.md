# 客户端 v6：分布式测试闭环与五个一级界面

日期：2026-10-14 · 状态：已实现（dist_protocol v3 + 客户端 v6）

## 1. 为什么改

原流程是「大量语言模板 → 分布式测试 → 稳定特征 → 图谱 → 破解编码」。审查时发现四个卡点：

1. **稳定特征不等于机制**：runner 只产出 η²、cos、head Jaccard 等相关统计，测得再多也只能停在 E1（可复现）。
2. **模板规模与统计功效不足**：TM-01…06 每个模板只有 6–16 条手写句子，在 2560 维上逐维算 η² 基本是噪声。
3. **分布式结果无法精确合并**：节点只回传 summary 摘要，中心只能并列展示，不能合成更大样本。
4. **没有可量化的终点**：「破解」没有对应指标。

## 2. 协议 v3（shared/dist_protocol）

| 环节 | 实现 |
|---|---|
| 生成式模板 | `template_grammar.v1`：句式框架（带因子水平、目标槽、行为 probe）× 填充词表（带因子水平、槽位文本）。按**填充**分层确定性切分 discovery / confirm / lockbox（lockbox = 未见词表）；`heldout_frames` 进入 lockbox_frame（未见句式）。目标位置按槽位字符偏移定位，不用 `text.find`。 |
| 功效估算 | `grammar.preview`：逐格 × 划分计数、Bonferroni 到隐藏维度数的最小可检测 η²（大样本近似，只用于设计阶段）。 |
| 行为门 | 每条样本可带 probe（prompt → answer）；runner 记录答案首 token 是否 top-1。合并时排除准确率低于 `prereg.min_behavior_acc` 的条件格。 |
| 充分统计量 | runner_v3 回传 `suffstats.npz`：每 (split, 条件格, 层, 维) 的 n、Σx、Σx²（float64）。中心相加后得到与单机计算逐位等价的 η² 分解、因子水平方向、格均值 cos。 |
| 金丝雀 | 每个模板包附 4 条固定输入；runner 记录目标位置向量摘要。中心按 (model_id, model_rev, precision) 登记首个 real 结果为参考，其后超出容差记为 drift，自动排除出合并。 |
| 分片 | 模板 `shards` 个分片；中心按「done+claimed 次数最少」分配；同一分片的第二次运行只用于一致性检查（字节相同记入 `result_replicas`）。 |
| 审计 | 每份结果自动检查（设计一致 / 真实运行 / 产物齐全 / 金丝雀 / 行为门 / 分片 / Work Unit 绑定）+ 人工裁决 passed / rejected / needs_rerun。有 fail 项时服务端拒绝 passed。审计只决定能否进入合并，不创建 Evidence。 |
| 证据门链 | 行为 → 仪器 → 重复 → 留出复现 → 未见词表预测 → 未见句式预测 → 跨模型（1–7 自动判定）→ 选择性/充分性 → 必要性与负控制 → 自然生成（8–10 需干预实验，显示「未运行」）。按顺序判定。 |
| 逐样本向量与规律分析 | runner 写 `items.npz`（`items.v1`：各采样层 float16 向量，过大时 JL 投影，种子来自语料）；`analysis.py`（`analysis.v1`）在 discovery 拟合、留出划分检验：校正迹 η²、白化方向复现、最近质心探针、按单位置换零分布、句式不变性、split-half 可靠交互、词身份超额、格内长度偏相关；按固定判据生成规律陈述，并给出 LDA/PCA 3D 坐标与 Procrustes 对齐的层堆叠。 |
| 沙盒合成模式 | 中心以 `AI2050_DIST_ALLOW_SYNTHETIC=1` 启动时才合并 `kind=synthetic` 结果（模型桶加「合成·」前缀、总览与实验响应显示横幅），只用于验证流程；正式中心拒绝。 |
| 预测记分板 | discovery 因子水平方向与留出划分同一水平方向的平均 cos，与冻结的 `prereg.min_lockbox_cos` 比较；另给共享条件格的 RDM 相关。 |

中心端点（deploy/distributed_service.py，挂载到 :5001 或独立 :5010）：
`/api/grammar/library|preview|register`、`/api/grammar/{tm}/report`、`/api/agg/{tm}/v2`、`/api/analysis/{tm}?bucket=&gate=`、`/api/coverage`、
`/api/audit/queue`、`POST /api/audit/{sha}`、`/api/pipeline/overview`、`/api/scoreboard`。

## 3. 五个一级界面

| 界面 | 回答的问题 | 主要内容 | 数据源 |
|---|---|---|---|
| 总览 | 闭环推进到哪、今天要我决定什么 | 闭环漏斗（各阶段独立计数，不算转化率）、覆盖矩阵（模板 × 阶段，点击空格进研发、点击数据进空间）、数据健康、待我决策、最近研究裁决 | pipeline/overview、coverage、atlas ledger |
| 空间 | 模型内部对条件怎样响应 | **实验响应**（默认）：3D 响应空间（逐样本，LDA·因子 / PCA / 层堆叠轨迹；按因子、划分、作答对错着色；拖动旋转、悬停看原句）、规律分析（规律陈述、按层探针准确率与 η² 曲线、置换零分布、句式不变性矩阵、判据表）、η² 剖面（层 × 因子 × 维度分箱，可取逐维完整值并下载 CSV）、条件结构（格均值 cos + 经典 MDS）、留出复现、跨模型、行为门；legacy 模板回看单节点结果。默认打开 3D 响应空间。**模型资产**：本机权重浏览（层平铺 / 参数热图）。原「结构示意」（四个演示与示意 3D 视图）已在 v6.1 移除，空间只保留真实实验结果与本机权重。 | analysis、agg v2、results |
| 研发 | 下一批测什么、怎样保证数据可信 | **自动测试**（默认工位）：被测模型登记（本机模型库选择 / 目录检查）× 模式族勾选 → 一键运行；结果矩阵（模型 × 模式族，点击进空间并预选模型桶）、运行队列（7 段进度、日志、取消、重跑）· ① 模板工作室 ② 试跑与冻结 ③ 分发与节点（分片覆盖 + PlatformOps + Research OS 执行链）④ 审计队列 · Agent 工作流 | autotest/*、grammar/*、templates、audit、work-units、ai-rnd |
| 图谱 | 语言—响应关联与证据来源 | 原「路线 → 研究工作区」升为一级：研究图谱 / 证据中心 / 资源目录 | ai-rnd atlas |
| 路线 | 每个假设卡在哪一道门 | 目标树（模板族证据门链 + 语言图谱目标 + 方法与账本）、预测记分板、参考（行业方法，按需展开，不作为证据） | scoreboard、work-units |

## 6. 一个模式族的完整流程（analysis.v1）

`scripts/run_language_family.py` 驱动：① 文法预览 → ② 冻结试跑版 → ③ 节点跑试跑分片（行为门；达标比例低于 `--min-pilot-pass` 即停止）→ ④ 冻结正式模板 → ⑤ `node_agent.py run --tm-id` 逐分片采集 → ⑥ 中心合并 + `/api/analysis` → ⑦ Markdown + JSON 报告。全部通过中心 HTTP 接口，与客户端读取同一份数据。

验证：`tests/dist_protocol/test_analysis.py` 在合成数据中植入「早层句式与词身份主导 → 中层类别可读、跨句式不变、组合可加」，分析须找回这些规律；打乱类别标签后「类别可读」必须为「未支持」。沙盒端到端：KN-ISA 4 分片 420 条，行为门排除 14 条，8 条规律陈述；客户端五个界面与实验响应 7 个子视图逐一打开，无控制台错误。

## 7. 研发 · 自动测试（autotest.v1）

目标：配置多个被测模型，勾选模式族，点击后自动运行全部测试。

- **被测模型**：本机 HF 权重目录（config.json + *.safetensors），登记 model_id / 精度 / GPU / 快照；「检查」只读配置与文件列表。沙盒中心另可登记合成模型。只有 API 的模型拿不到内部状态，不作为被测对象（API 模型仍用于 Agent 工作流）。
- **作业**：一次点击 = 一个批次，按「模型 → 模式族」展开为作业；已在队列中的同一组合跳过。单工作线程顺序执行 `scripts/run_language_family.py --progress`，解析 `@@progress {step,label,detail,tm_id,bucket}` 与 `@@result {tm_id,bucket,report,findings,headlines}`；退出码 3 = 行为门停止。状态：排队 / 运行中 / 完成 / 失败 / 行为门停止 / 已取消 / 中断。
- **调度修正**：同一冻结模板被多个模型使用时，`_next_shard` 先选该模型快照尚无结果的分片；重复冻结同一文法返回现有版本（含 shards），其他模型继续补齐自己的分片。
- **界面**：① 被测模型 ② 模式族 ③ 运行（试跑开关、每格条数、最低达标比例、作业数预估）；结果矩阵；运行队列。完成作业可「查看 3D 与规律」，跳到空间并预选模板与模型桶。
- **验证**：`tests/dist_protocol/test_autotest.py`（6 项，假驱动）；沙盒端到端：2 个合成模型 × 2 个模式族 = 4 个作业全部完成，各自得到完整模型桶；界面登记、运行、日志、取消、结果矩阵跳转、760 宽度无横向滚动，无控制台错误。

## 11. 账号入口（accounts.v1）

- **入口**：`main.jsx` 用 `AuthGate` 包住主界面。第一次打开（本机无会话）显示注册界面；该中心还没有账号时注册页提示「第一个账号自动成为管理员」，并禁用登录页；关闭自助注册时只显示登录页。注册或登录成功后令牌存 localStorage，再次打开先用 `/api/auth/status` 校验，有效则直接进入主界面，失效则回到登录页（预填上次用户名）。
- **离线**：中心不可达且本机有会话 → 进入主界面，账号按钮带离线标记；无会话 → 登录页显示「连不上中心服务」与重试。
- **顶栏账号菜单**（`AccountMenu`）：账号与角色、我的节点、修改密码、账号管理（管理员：角色、启用 / 停用、创建账号）、退出登录。
- **管理授权**：管理员登录后，各写操作的管理令牌输入框替换为「管理员账号 …」标识，无需再粘贴令牌；成员仍看到令牌输入框。
- **参与测试**：登录后「参与测试」可生成一次性绑定码，注册命令自动带 `--bind-code`；节点归属账号，贡献者显示账号名。
- **验证**：沙盒全新数据下走通：首次打开 → 注册页（首个管理员提示）→ 弱密码报错 → 注册进入主界面 → 刷新直接进入 → 管理员免令牌登记自动测试模型 → 我的节点 → 账号管理创建成员 → 生成绑定码并注册节点 → 我的节点显示在线 → 退出 → 错误密码报错 → 登录；成员浏览器：无账号管理、令牌输入框、`/api/auth/users` 403；中心停止后有会话进入主界面并标记离线、无会话显示重试；390 宽度无横向溢出；无控制台错误。
