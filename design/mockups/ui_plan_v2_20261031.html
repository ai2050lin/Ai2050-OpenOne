默认展开的那一块就是这一页的主任务（实时分析页 = 注意力热力图；其余页全收起）。别让读者一进来就面对三个展开。

四、分布式研发流程：一个作业长什么样 这是「基于不同数据集和模型找普遍规律」的工程定义

现在的流程散在五个工位、四份文档、两套账本里。把它压成一个对象、五个状态、三道门，才能做到「换任何数据集和模型，走的都是同一条流水线」。

作业 = 四元组 + 五状态 + 三闸门
四元组
数据集 × 模型 × 机制 × 口径（口径含留出方式与分母定义）
五状态
待跑 → 运行 → 完成 → 复核 → 入账；另有「失败」直接入账
闸门一
启动前：预注册三栏填满（预期 / 判据 / 功效）
闸门二
完成前：provenance 五字段齐全（git / seed / 模型修订 / 设备 / 数据包哈希）
闸门三
入账前：独立复核（换人或多进程重算，不接受自我复核）

这三道门全部落在界面上（S2），不写在文档里——写在文档里的门，迟早会被绕过。

为什么这套能得出「普遍规律」

单个数据集上的一条结论，可能只是那个数据集的产物；单个模型上的一条结论，可能只是那个模型的偶然。只有当同一个机制在 ≥3 个模型上以同一口径复现，才写进「规律」。

所以每个结论都有两个附加字段：复现模型数与跨数据集一致性。界面上（S4、S5）这一列是常驻的，不是可选项。

3 / 4 复现 → 规律 2 / 4 → 待扩 1 / 4 → 个案
