# 三模块 3D 关系空间方案 v1（AtlasModuleSpace · module_space.v1）

> 日期：2026-10-13 · 状态：**已落地（2026-10-13 用户确认后实施）**
> 位置：路线 → 图谱 → 图谱全景，「模块空间」模式（与 2D 双栏对照互补，不替换）
> 数据：`research/gpt5/atlas/atlas_tree_v2.json` → `module_space` 段（registry 最新版 + ledger 派生，derive_atlas_tree.py build_module_space）
> 原型：`design/atlas_module_space3d_mockup_v1.html`（零依赖 Canvas 3D）
> 实施：`server/derive_atlas_tree.py`（module_space 派生段）+ `frontend/.../AtlasModuleSpace.jsx`（atms-* 样式）+ AtlasLens v1.11 四模（模块/模块空间/模板空间/卡片）
> 实施差异：桥 band 由 **registry 角度值对预注册 30° 门派生**（零实验字面量，比原型硬编码更严）；桥分离度读数详情面板直接展示 registry angle_*_deg 原值。

## 1 问题：现有模块视图为什么「简单」

AtlasModuleView 是 2D 双栏对照表——模板列 ↔ 特征列 + DOM 贝塞尔边。它回答「每个模块里有什么」，但三个**模块级**的关系只能压成 chip：

- 三座桥 X1/X2/X3 的**分离度读数**（67–81° separable vs 26.6° mixed）没有视觉权重差；
- 「三模块如何汇合成 next-token 预测」这一 RDC 主线（条件化输出场闭合）在 2D 上没有表达位置；
- 机制层 MEC（7 条）与模块的**跨模块服务关系**（如 FTR-12 同时服务 KN 的 tm05 与 GR 的 tm02）不可见。

## 2 方案总览：三舱一塔 + 三桥一核

空间结构（三角布局 + 中心机制塔）：

```
            ┌─ GR 环形舱（语法=序列/位置）
           / \
   三桥弧线    三桥弧线          ← X1/X2/X3 桥上载着跨域特征
         /       \
  KN 晶格舱 —— X3 桥 —— AR 链舱
         \       /
          \     /
        机制竖井塔（MEC-01..07 楼层盘）
             ↑
        汇合核（三主干边汇入 = next-token 条件化汇合点）
```

### 2.1 三模块舱体（几何形态 = 模块组织假说的示意）

| 模块 | 舱体形态 | 编码含义 | 舱内内容 |
|---|---|---|---|
| KN 知识网络 | **立方晶格**（线框盒+网格） | 实体×属性×关系的网格结构 | 6 模板 + 10 特征节点 |
| AR 推理功能 | **链式拱**（前提→门→结论三站连线） | 推理是链条传递 | 3 模板 + 1 特征 |
| GR 语法机制 | **环形序列**（圆环） | 语法是位置/顺序的循环 | 5 模板 + 6 特征 |

诚实口径：舱体形态是**组织假说的示意**（派生布局），非模型真实几何；npz 真实坐标接入后仅替换节点 pos，舱体骨架不变。

### 2.2 节点编码

- **模板节点**（14）：实心圆 + TM 编号，大小 ∝ prod.cells 对数；状态着色（measured 绿/done 绿/collecting 蓝/demo 灰蓝/pending 灰）。
- **特征节点**（20 舱内 + 3 桥上）：E 级着色 + **E 级分层高度**（E3 顶层 / E2·E2h 中层 / E1 底层）——证据结构立体可见。
- **缺口节点**（part_of、tm06）：灰色空心圆悬浮舱缘外侧 + 红色 gap 标注；FTR-05（有特征无模板）= 红点虚位标在 X1 桥上。

### 2.3 模块间关系（一等公民，四层）

1. **可分离桥 X1/X2/X3**（实测证据）：三角三条边各一座弧形桥，桥面节点 = 跨域特征（FTR-05/07/08）。
   **线宽/亮度编码分离度**：X3 RxK（26.6–46.0°，全表唯一 mixed/弱混合）画得最粗最亮 = AR↔KN 是唯一强耦合对；X1/X2（67–81° separable）细而半透明 = 几何可分。桥标签显示三模型角度读数。
2. **跨模块模板边**（kind='x'）：tm12(AR)→FTR-08(X3)、logic_tf(AR)→FTR-07(X2)，橙虚线从 AR 舱拉到桥上——推理模板的机制证据落在跨域桥上，一眼可见。
3. **机制竖井梁**：中心塔 7 层 MEC 楼层盘；某 MEC 的特征的模板跨模块时（MEC-02：FTR-12→tm05[KN]+tm02[GR]），从该层盘向两舱发横梁。
4. **三主干汇入**：KN/AR/GR 各一条粗边汇入塔基 = **内容轴 / 真值轴 / 形式轴**；塔顶汇合核 = next-token 预测（RDC 条件化输出场闭合的空间隐喻）。

### 2.4 交互

- 左键旋转 / 右键平移 / 滚轮缩放 / 闲置自转（与模板空间同范式）。
- 点击模板/特征/桥/MEC 盘 → 底部详情三段面板（对象档案 / 关联机制 / 缺口与边界），协议键渲染，零界面字面量。
- 工具栏：模块显隐 ×3、边类型过滤（a 实测 / c 采集 / x 跨模块 / 桥）、自动旋转、复位视角、着色切换（E 级 / 模块）。

## 3 数据协议扩展（module_space.v1）

`server/derive_atlas_tree.py` 在 v2 输出内新增 `module_space` 段（确定性派生，--check 幂等）：

```jsonc
"module_space": {
  "modules":  { "KN": {"shape":"lattice","center":[...],"n_tpl":6,"n_ftr":10},
                "AR": {"shape":"chain", ...}, "GR": {"shape":"ring", ...} },
  "nodes":    [ {"kind":"tpl|ftr|gap","ref":"is_a|FTR-01|...","mod":"KN","pos":[x,y,z],"y_band":"e3|e2|e1"} ],
  "bridges":  [ {"edge":"X3","type":"RxK","mods":["AR","KN"],"ftr":"FTR-08",
                 "angles":[45.8,26.6,46.0],"band":"mixed","mid":[...],"ctrl":[...]} ],
  "trunks":   [ {"from":"KN","to":"core","axis":"内容轴"} ],
  "mech_beams":[ {"mec":"MEC-02","mods":["KN","GR"],"ftr":"FTR-12","y":1.6} ],
  "core":     {"pos":[0,6.8,0],"note":"next-token 条件化汇合点（示意）"}
}
```

派生规则：模块中心三角（120°）+ 舱内黄金角确定性布点 + E 级分带高度；桥中点/控制点由两舱中心计算；MEC 楼层 = mechanisms 数组序。**零实验字面量，禁手写节点。**

## 4 客户端落地形态

- 新组件 `AtlasModuleSpace.jsx`（Canvas 3D，复用 AtlasTemplateSpace 的相机/投影骨架）；
- AtlasLens panMode 增加 `'modspace'`，按钮「模块空间」，放在「模块」与「模板空间」之间；
- 默认视图仍为 2D 模块对照（表格是查询工具），3D 空间是关系发现工具——二者经同一 `sel` 协议联动（点 3D 节点 → 2D 详情抽屉可开）。

## 5 与现有视图的分工（避免再造重复）

| 视图 | 回答的问题 |
|---|---|
| 模块（2D 双栏） | 模块里**有什么**（查询/对照/审计） |
| **模块空间（3D，本方案）** | 模块之间**怎么联结**（关系/耦合/缺口发现） |
| 模板空间（3D） | 模板之间的**成族与共享**（模板粒度） |
| 卡片 | 特征**扫读** |

三者数据同源（atlas_tree_v2），选中态协议一致，不引入第二事实源。

## 6 已知限制（严格审视）

1. 舱体形态（晶格/链/环）是**假说示意**——GR 是否真是环形、AR 是否真是链，需 npz 级证据；界面已标注，不得当结论引用。
2. 桥线宽编码分离度是**单指标映射**（主角角度），三模型角度 band（separable/mixed）才是判定，详情面板给出完整读数。
3. 模板大小 ∝ cells 是工作量信号不是机制强度信号——面板标注口径。
4. E 级分带高度把 E2h 与 E2 并层——严格说 E2_behavioral 与 E2_predictive/held_out 口径不同，图例须分开列出。
5. 23 特征中 7 条属 MEC 层独占（FTR-09/10/11/15/16/19 等），画在中心塔盘上而非舱内——它们当前无模块归属，视为「跨模块机制底座」，符合 gaps.note 口径。
