# 工作台「研发」工位梳理：哪些可以清理、哪些可以合并

日期：2026-10-30 · 范围：`lens=process`（研发）的 10 个工位 tab · 依据：本机实测数据 + 代码引用链

## 0. 口径

「研发」是工作台的四个一级界面之一，其子导航由 `frontend/src/components/app/workbenchUtil.js` 的 `STATIONS` 定义，共 10 项，由 `Workbench.jsx` 逐个渲染面板组件。本梳理只针对这 10 个工位，附带着指出非 tab 的死代码。

判断依据三条，均为可复验的实测：

1. **数据是否活着**——读 `/api/*` 与 `distributed_data/dist.sqlite3` 的真实行数与最后时间戳。
2. **功能是否重叠**——是否共享同一份状态、同一个数据源、同一条流水线。
3. **代码是否被引用**——`import` 链路是否还有活的入口。

## 2. 三类判断

### 2.1 可以清理（不改变任何现有行为）

**① AI 助手 → 移到「配置」界面**

它是「地址 / 模型名 / API Key / 每日上限」的配置表单，与「配置」界面的「被测模型、平台信息」同性质，放在「研发」里只是因为 v6 时期研发是默认界面。迁走后研发 10 → 9，且「配置」界面终于覆盖了它该覆盖的东西（模型与密钥）。

**② 贡献算力 → 并入「账号」菜单 / 配置**

网页版这个工位只做两件事：给出客户端下载入口、显示节点绑定码。节点归属本来就是账号属性（`AccountMenu` 已有「我的节点」）。留一个独立 tab 的成本（382 行）远高于它提供的信息量。研发 9 → 8。

**③ 非 tab 的死代码：v5.1 四透镜驾驶舱（约 1,040 行）**

`RdcFusionWorkspace.jsx`（146 行）在 `main.jsx` 里没有任何 import 路径能到达——`/rdc-fusion` 已经被 `Workbench` 接管。它连带 `LensProcess.jsx`（500）、`LensProgress.jsx`（219）、`PlatformOps.jsx`（175）一起失效。这四个文件建议直接删除或移到 `archive/`。

> 注意：`LensSpatial.jsx` **不能删**，`Workbench.jsx` 的「本机工具」还在用它。

### 2.2 可以合并（推荐）

**④ 模板工作室 + 试跑与冻结 + 分发与节点 + 审计队列 → 1 个「模板流水线」（4 → 1）**

这四项不是四个并列功能，是同一条流水线的四个阶段，代码里已经互相咬合：

- 共享 `Workbench.jsx` 顶层的 `draft` 状态：模板工作室 `onDraft` 写入，试跑与冻结读 `draft.family_id` 去冻结。
- 分发与节点直接 `import { NodeCommand } from './FreezePanel.jsx'`——节点命令面板本来就是同一个组件。
- 数据同源：`/api/grammar/library`、`/api/templates`、`/api/grammar/{tm}/report`，四个 tab 反复读同一批接口。
- 业务上必须来回跳：建完模板要冻结，冻结完要派发，派发完要审计。现在每跳一次就丢一次页面状态。

合并成一个带步骤条的页面（① 建模板 → ② 冻结 → ③ 分发 → ④ 审计），行数可从 599 行降到约 450 行，且状态不再需要跨 tab 传递。研发 8 → 5。

**⑤ 普查作业 + 自动测试 → 1 个「批量作业」（2 → 1）**

两者界面结构几乎相同：选批量对象（模型 / 语料切片）→ 排队 → 看进度与分片状态 → 看结果。差别只在驱动脚本（`run_language_family.py` vs 普查切片）。而两者的实际状态都是「没在跑」：普查 1 个残留作业、自动测试 0 作业。合成一个带「作业类型」切换的页面，比留两个都跑不起来的空壳诚实。研发 5 → 4。

### 2.3 保留

**⑥ 神经元测试（升为默认工位）**

这是当前研究（神经元编码破解、H6/H7 判决实验）唯一每天在用的研发工位：本机 GPU、S1–S9 找特征、结果只存本机。它应该是研发界面的第一屏，而不是排第三。

**⑦ 题库**

内容载体（12 个条目），是「下一批测什么」的入口，且网页版可见、对外开放。保留，但可以吸收「贡献算力」的下载入口。

## 3. 目标结构

```
研发
├── 神经元测试          ← 默认工位（原 #3）
├── 模板流水线          ← 合并 #5 #6 #7 #8，四步步骤条
├── 批量作业            ← 合并 #9 #10，作业类型切换
└── 题库                ← 保留 #1，吸收贡献入口

配置
├── 连接与运行形态
├── 账号与被测模型
├── AI 助手             ← 从研发迁入 #4
└── 我的节点 / 贡献     ← 从研发迁入 #2
```

10 个工位收敛到 4 个，研发界面从「分布式生产控制台」变回「当前研究在用的三件事 + 题库」。

## 4. 代价与风险

| 项 | 说明 |
|---|---|
| 旧链接 | `?station=studio|freeze|dispatch|audit|census|autotest|ai|contribute` 需要重定向到新工位（`workbenchUtil.resolveGo` 加一层映射即可，`OLD_VIEWS` 已有同类先例） |
| 权限混杂 | 题库 web 可见、审计仅管理员。合并后「模板流水线」含审计，需按权限隐藏第四步，不能整页放行 |
| 状态传递 | 合并后 `draft` 从 Workbench 顶层下沉到流水线页内部，`LensProcess` 那边的旧用法已随死代码一并消失，不冲突 |
| 可逆性 | 合并只是前端组合，不动后端接口与数据；回滚只需还原 `STATIONS` 与渲染分支 |
| 不建议动的 | `census` 后端（1 个残留作业要保留可查）、`results` 212 份产物、`audit` 派生逻辑 |

## 5. 附：其他界面的同类问题（本次不动，仅记录）

- **空间 · 本地包**：它是「打开一个 zip 文件」的工具，不是一种视图，长期看应做成顶栏按钮，而不是与「神经元」「语言图谱」并列的 tab。
- **空间 · relations**：已从导航隐藏但保留旧链接，`SpaceLens` 仍在渲染。若三个月内无人访问，可连同旧链接一并移除。
- **进展 · 三个 tab**（神经元逆向分析 / 语言图谱 / 规则账本）：三者回答不同问题，无重叠，不建议合并。

## 6. 建议执行顺序

1. **先做零风险的**：删死代码（1,040 行）、AI 助手迁配置、贡献算力并账号。这一步不改任何数据流。
2. **再做四合一流水线**：收益最大（省 150 行、消掉跨 tab 状态），风险中等（要处理旧链接与审计权限）。
3. **最后做批量作业合并**：等自动测试真的跑起来过一次之后再合，否则是在合并两个空壳。

### 7.2 与原计划的两处偏离

- **研发收到 5 个而非 4 个**：档位选的是「清理 + 四合一」，不含把普查作业与自动测试合成「批量作业」，两个空壳原样保留（等自动测试真跑过一次再合）。
- **多删四个文件**：清理时发现它们是待删文件的唯一消费者（`NewbieGuide`、`AtlasPanorama`、`TimelineBits`、`demoData.js`），删主文件后即变孤儿，一并清掉。

### 7.3 验证

- `npx vite build`：通过，无 error（两次，含最终态）。
- 浏览器实机（dev server 5173 + 本机中心 5001，vite 热更后）逐页验收，控制台 **Errors: 0**：
