# 研发透镜简化方案 v1（design/process_lens_simplify_plan_v1.md）

> 对象：`frontend/src/components/app/rdc_fusion/LensProcess.jsx`（630 行，三栏）
> 原则：沿用五轴模型与「每条信息只有一个家」；只动展示层，协议端点零改动；零实验字面量红线。

## 1 现状盘点（三栏共 13 个模块）

**左栏**（宽 344px，7 块）
| # | 模块 | 内容 | 数据源 |
|---|------|------|--------|
| L1 | AI 模型配置 | 主/辅模型 details 卡 ×N + 添加 + 保存 | /config |
| L2 | 任务队列（4 子 tab） | 研究线 / 分布式 / 调度 / 缺口 | 4 个端点 |
| L3 | 工作区浏览器 | 目录/文件树 + 上级导航 | /workspace |
| L4 | 运行配置 | 2 行静态文本 | ⚠️ 硬编码 |

**中栏**（5 块）
| # | 模块 | 内容 |
|---|------|------|
| M1 | Composer | 目标输入 + 自动/手动 + 轮数 + 5 个按钮 |
| M2 | 证据门 GATES | 6 步门进度条 |
| M3 | 主区 4 tab | 工件 / 实时事件 / 技术运行 / 平台运行 |
| M4 | 终端条 | 事件流的另一种渲染（slice(-14)） |

**右栏**（3 卡）
| # | 模块 | 内容 |
|---|------|------|
| R1 | 选中概览 | 点队列行后的 KVList |
| R2 | 证据链 | 6 行派生文本 |
| R3 | 跨透镜动作 | 2 按钮（1 个 = 切本透镜 tab） |

## 2 问题清单（按严重度）

1. **红线违规**：L4「运行配置」两行是硬编码实验字面量（`4b bf16 · 14B/9B NF4`、`drift 断言 · 预注册冻结`），且无端点支撑、语义与 GATES/队列重复。
2. **三处重复渲染**：
   - R1 选中概览 ≡ M3 工件 tab（同一 qSel 两次 KVList）；
   - M4 终端条 ≡ M3 实时事件 tab（同一 events 流两次渲染）；
   - L2·调度 ≡ M3·平台运行（PlatformOps 已有节点/租约视图）。
3. **四个「队列」概念并排**（研究线/分布式/调度/缺口），连界面自带的消歧注释都承认易混；实际上它们分属两层：**研究线队列**（phase 依赖序，本透镜核心）与**节点租约/模板结果**（基础设施监控，PlatformOps 的职责）。
4. **低频模块占高位**：AI 模型配置（一次性设置）占左栏首屏；工作区浏览器（运维工具）混在生产主流程。
5. **右栏价值密度低**：R3 的两个按钮一个是切本透镜 tab，一个是跳空间透镜；R2 证据链 6 行派生文本可与队列详情合并。
6. **技术债**：tab 状态用 index 存（`useState(0)`），存在 index/`activeKey` 混用。

## 3 目标结构（三栏 → 两栏）

```
研发透镜（简化后）
├─ 左栏（唯一列表列）
│   ├─ AI 模型 …折叠为一行状态（✓就绪/✗缺Key，点开才是 details 卡）
│   ├─ 研究线队列 …唯一队列（NEXT/QUEUED/BUILT/SEALED 行 + sealed 计数）
│   │   └─ 缺口 …降级为队列底部一行链接「缺口任务（N 格）→」跳技术运行
│   └─ （分布式/调度/工作区 全部移出左栏）
├─ 中栏（主流程列）
│   ├─ Composer（不变：目标/模式/按钮）
│   ├─ GATES 证据门（不变）
│   ├─ 主区 3 tab：运行（工件+事件合一） / 技术运行 / 平台运行
│   │   ├─ 运行：选中工件时上工件 KVList、下方实时事件流；无选中=纯事件流
│   │   ├─ 技术运行：ResultsExplorer mode="tech"（不动）
│   │   └─ 平台运行：PlatformOps + 吸收调度队列行 + 工作区浏览器（基础设施监控归此）
│   └─ （终端条删除）
└─ （右栏整栏删除）
    ├─ 选中概览 → 并入「运行」tab 工件视图（一处渲染）
    ├─ 证据链 → 并入研究线队列行展开（点行即见）
    └─ 跨透镜动作 → 删（3D 查看入口已在空间透镜；"技术运行→"本就是切 tab）
```

**信息归属对账**（简化后每条信息唯一）：
- 队列：研究线=左栏唯一队列；节点租约/模板矩阵=平台运行；
- 事件：实时事件流=「运行」tab 唯一渲染（终端删除）；
- 选中详情：工件 tab 唯一渲染（右栏删除）；
- 模型配置：折叠卡唯一位置（左栏顶部一行态）。

## 4 分阶段实施

### P1 纯减法（低风险，先做）
1. **删 M4 终端条**（与事件流重复）；
2. **删 L4 运行配置**（红线：硬编码实验字面量）；
3. **删右栏整栏**（R1 并入工件视图、R2 并入队列行、R3 删）；
4. **L1 AI 模型配置折叠**：收起为一行状态条（`AI 模型 ✓就绪`），点开才展开 details 卡与保存按钮；
5. tab 状态 index → key（`useState('events')`）。

### P2 队列收敛（P1 验证后）
6. 左栏 4 子 tab → 单一研究线队列；「缺口」降级为底部一行链接；
7. 「分布式」「调度」两个子 tab 移入平台运行 tab（PlatformOps 顶部加两小节）；
8. 工作区浏览器移入平台运行 tab 底部（运维归基础设施）。

### 终态
- 模块数 13 → 8；左栏 7 块 → 2 块；右栏删除；主区 4 tab → 3 tab；
- 每条信息唯一归属，重复渲染清零，红线清零；
- 不改任何协议端点与启动流程（/config、/project-agent/*、/session/* 全保留）。

## 5 风险与回滚

- P1 全部为删除/折叠，git 单提交可整体回滚；
- 事件流合并后「运行」tab 是启动研发后的默认落点（start 成功即 setTab('run')）；
- 平台运行吸收调度/工作区后信息密度上升，若过载可在 P2 后再加子折叠，不再回流主区。
