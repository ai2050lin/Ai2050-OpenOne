# 客户端方案 v3：按「神经网络本就已经干净」重排证据链

> 触发：https://already-clean.goodfire.com/ （Nick Cammarata / Goodfire，working hypothesis，65 分钟长文）
> 基准：`design/client_ia_review_v2.md`（结构层已稳，问题转到「口径与证据」）
> 日期：2026-10-19 · 状态：**G0 已落地**（代码 + 实测），G1–G3 待排期
> 本文只谈「这篇论文改变了我们什么」，不重复 v1/v2 已覆盖的结构问题。

## 0 一句话结论

这篇论文不会让我们改界面结构，但它把我们**默认的证据单位**判错了：它主张可解释性的基本单位是
「原生神经元 + 具体数据片段 + 正负极点」，而不是「先分解再命名的特征」。
我们实测发现：客户端现在画得最像「神经元」的那个视图（空间 → 封存激活 3D），画的其实是**残差流坐标**；
26 条在册特征里**没有一条登记了原生坐标**。所以 v3 的重点不是加视图，而是**把证据链从"命题级"下移到"片段级"**——
而这件事**不需要新跑模型**：封存数据里已经够了（下面 §3.3 有实测）。

## 3 我们自己的实测（这是本文与"读后感"的区别）

两个探针都只用**封存产物**（phase3169 `collect_*.npz` + `execution.json`），零 GPU、零新采集。
面板 = 73 实体 × 10 类别 × 3 句式模板 = **2190 格完全交叉**，因此方差可精确分解、份额和恒为 1。

### 3.1 残差坐标上几乎没有「单因子」坐标

`tests/gpt5_temp/_neuron_anova_probe.py`（严格全交叉 ANOVA）：

| 模型 | 层 | 句式 TS | 类别 CS | 实体 ES | T×C | C×E | 余项 | CS>0.5 的坐标占比 |
|---|---|---|---|---|---|---|---|---|
| qwen3-4b (37L) | 9 / 18 / 27 | 37.8 / 26.9 / 20.3% | 12.4 / 12.6 / 10.8% | 21.4 / 14.0 / 29.7% | 13.2 / 10.4 / 13.3% | 3.2 / 13.3 / 9.7% | 3.2 / 12.5 / 9.4% | **0.00** |
| qwen3-14b (41L) | 10 / 20 / 30 | 37.7 / 29.0 / 22.7% | 12.4 / 14.9 / 10.9% | 23.9 / 11.9 / 22.9% | 13.0 / 8.4 / 12.6% | 3.6 / 13.9 / 11.9% | 2.8 / 11.4 / 11.3% | **0.00** |
| glm4-9b (41L) | 10 / 20 / 30 | 34.9 / 27.2 / 17.9% | 18.1 / 14.5 / 21.3% | 12.0 / 9.3 / 20.9% | 10.0 / 9.2 / 7.7% | 7.8 / 14.2 / 12.1% | 7.3 / 16.3 / 12.2% | **0.00** |

读数（三模型一致）：
- **主导因子是句式（17.9–37.8%）**，且随深度下降；内容（类别）只占 10.8–21.3%；实体身份 9.3–29.7%。
- **类别份额 > 0.5 的坐标占比为 0.00**；整层统计里也只有 **0.08%**（2560 维里 2 维）。
- 交互项合计 17–30%，说明这些坐标做的是**组合**，不是单一概念。

结论（要连着读）：**这不是对论文的反驳，而是对"单位"的校准**。残差基是模型自己没有承诺过的坐标系
（每层被 LayerNorm/注意力旋转），本来就不该指望它单义。论文说的单义单元是 MLP 神经元。
我们目前没有 MLP 激活的封存件——所以「封存激活 3D」**必须正名**，否则读者会拿残差坐标去对标论文的 90%。

### 3.2 top-k 纯度法会骗人；片段法不会

`tests/gpt5_temp/_neuron_purview_probe.py`（先做的探针，保留作为反例）：
在 28 个样本坐标上，`class_purity` 均值 0.43 / 0.32 / 0.54（10 类基线 0.1），看起来像"弱类别偏好"。
但把**真实片段**打出来后，L27.D91 的正极是：

```
+18.50  西瓜，一种常见的金属。
+18.13  香蕉，一种常见的金属。
+18.00  梨，一种常见的金属。
```

这不是「编码金属」，也不是「编码水果」，而是**实体与类别矛盾的格子**。纯度法把它读成"弱类别"，片段法一眼看穿。
这就是论文说的"多义性常是观察者的问题"——**在我们自己的数据上找到了一个实例**。

### 3.3 证据片段可以零成本还原（这是最值钱的一条）

服务端原先在极点卡上写：「样例文本未封存于该 npz，回查挂账」。
**这句不成立**：`H[t, pair, layer, dim]` 的 `pair = 实体下标 × 10 + 类别下标`，而模板表、实体表、类别表
全都封存在同一 phase 的 `execution.json` 里。于是 `text = TPL[t].format(e=实体, c=类别)` 是**确定性还原**，
不是生成、不是标注、不是猜测。

已实现并实测（`server/neuron_panel.py`）：

```
L18.D219  正极 2.406 老虎，一种常见的天气。 / 2.250 大象是一种天气。
          负极 -2.766 床，一种常见的水果。 / -2.625 床，一种常见的金属。
          因子：句式 5% · 类别 54% · 实体 11% · 交互 30%
```

一个坐标 = 一句人话 + 一个因子构成 + 一个数值。这是论文交互式显微镜的最小单元，也是我们原来最缺的东西。

### 3.4 顺手挖出一处标签缺陷（论文说的"坏解释"）

`derive_neuron3d.py` 把 H 的第 0 维命名为 `n_seeds`，服务端写 `median_over_seed_row`，界面显示 `3 seeds`。
但采集代码是 `H16 = np.zeros((NT, NP_, NH, D))`，`NT = 3` 是**模板数**。三模型的形状都对得上（3×730×layers×dims），
所以数值没错、**标签错了**：读者会把「3 种句式」理解成「3 个随机种子」，从而高估统计稳健性。
已改为 `n_templates` + `axis_semantics`，并重生成派生档（`--check` 幂等通过）。

### 3.5 还有一处"坏工具"：演示神经元视图冒充实测

空间 → 实时分析 → 「神经元级」画的是 16,384 个点，布局与逐 unit 激活全部来自 `mulberry32` 合成
（`NeuronMode.jsx` 头注自述"布局与激活为 demo 种子"），但界面上**只有模板状态带 DEMO 徽标**，
数据本身没有。它与隔壁「封存激活 3D」（真 npz）并列，读者没有任何线索区分二者。
论文把"坏工具"列为假多义的第一因——这正是它的产品形态。已加常驻 `DEMO 数据` 标识（G0-7）。

## 4 由此确定的五条改造原则

1. **单位必须显式**：任何视图都要标出自己画的是 `MLP 神经元` / `残差坐标` / `注意力子空间`，并在图例里写清单义性前提。
2. **证据下移到片段**：能给出具体句子就不给抽象断言；给不出就写「该单位无封存片段」，不写"未封存"这种自我豁免。
3. **不确定性要有归因**：不清楚就分五因（工具/解释/训练/递归泛化/叠加），不要只留一个 E 级数字。
4. **读出与控制分轴**：E2 是"能读出/能预测"，E3 是"能控制"。把两者压成一个徽标等于隐藏 F20/F21。
5. **口径唯一派生**：分类法、配色、标签都从协议字段派生（本次已建 `core/evidence.js`），复制即腐化。

### G1 · 证据单位（1–2 天，纯派生，零 GPU）

- **registry v1.33 增 `unit_ref`**（append-only）：
  ```json
  "unit_ref": { "kind": "resid_coord | mlp_neuron | attn_subspace",
                "model": "qwen3-4b", "layer": 27, "index": 91,
                "basis": "native | readout_projection", "source": "p3238-A" }
  ```
  当前 26 条全是 `null`（诚实空态），等 3238-A 内在维度普查回填。
- **界面后果**：特征卡加「原生坐标」状态位（`有 / 无 / 待普查`）；详情抽屉在无坐标时**不画**片段区，
  只写「本特征尚未登记原生坐标」，而不是拿别的坐标的片段充数。
- **验收**：`unit_ref != null` 的特征数必须与 registry 一致；无坐标特征不出现任何片段。

### G2 · 不确定性的样子（2–3 天）

- registry 增三个字段（append-only）：
  - `gap_cause`: `tool | explanation | learning | recursive_generalization | superposition`
  - `read_status` / `control_status`: `established | partial | failed | not_tested`
  - `blocking_failures`: `["F20","F21"]`（把失败账本挂到特征上）
- 界面：详情抽屉加「证据状态」三行（读出 / 控制 / 未解原因），失败项直接链到 `failures` 条目；
  全景加一个「控制未建立」筛选（当前 23 条 E2+ 里有多少控不住，将成为最重要的一个数）。
- **验收**：F20/F21 能出现在其所属特征的详情里；「读出已建立 且 控制失败」的计数可从界面直接读出。
- 备注：这一批**只能**在 registry 有字段后做。若先用 `upgrade_log` 的散文解析，就是制造第二事实源——拒绝。

### G3 · 电路与泛化（按需，需要新采集）

- 单特征电路：沿层追踪上下游贡献（论文的 per-layer column 视图）。需要 MLP 激活或归因烘焙，**批前先预注册**。
- 泛化树：`parent_id` 表达递归泛化（"iy" → "diy" → "do it yourself"），在详情里用面包屑而非新视图。
- MLP 神经元普查（真正的单义性检验）：3 层 × 2190 行 × d_ff，三模型约 380 MB 封存件，
  单个 4b 采集约 10 分钟（与 phase3169 同量级）。**这是唯一能把论文数字与我们模型对齐的实验**。

## 6 明确不采纳

1. **不因为论文删掉 SAE/DAS/字典学习线**。论文把叠加列为五因之一，并未否认；我们的 `dictionary/` 与 DAS 臂继续。
2. **不把残差坐标改称神经元**（反过来也不行：不可为了"蹭结论"而重新命名）。正名方向是"降级称谓"。
3. **不让前端生成任何标签或摘要**。片段必须来自封存表，因子读数必须来自服务端分解。
4. **不新增一级导航、不再加 3D 视图**（沿用 v2 结论）。本次所有改动都挂进既有抽屉/面板。
5. **不在本批次引入 MLP 激活采集**。G3 需预注册 + 内存预算，本机当前余量不足以随手跑。
