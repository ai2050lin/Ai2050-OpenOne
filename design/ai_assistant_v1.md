# 客户端 AI 助手 v1（ai_assist.v1）

用户在桌面客户端里配置自己的 AI 模型（地址、模型名、API Key），然后在研究工作台的页面上请 AI 回答问题、协助研发。本文件是设计；实现状态以代码为准，分期见第 9 节。

## 1. 目标与边界

- **目标**：读者在看一个语言项、一个神经元或一次神经元测试结果时，可以就地问 AI。AI 看到的是这一页的真实数据，不是泛泛的知识。研发者可以让 AI 起草文法、最小对和可检验假设，再交给现有流程（模板工作室、神经元测试）运行。
- **证据边界**：AI 的回答、草稿和假设一律标为「未检验」，不进入证据等级，不改变合并口径（AGENTS.md §6.1 第 7 条、§6.1 第 12 条）。只有写成模板或测试并运行通过的结果才有证据。
- **只在桌面客户端**：网页只能浏览（AGENTS.md §10）。网页版的 AI 入口只显示「桌面客户端可用」，不在浏览器里保存或使用 Key。
- **中心不代理**：AI 请求从用户电脑直接发到用户配置的模型服务。中心不转发、不保存用户的 Key 和对话。

## 2. 架构

```
页面（React）                     Electron 主进程                     用户配置的模型服务
──────────────                    ──────────────────                 ──────────────────
设置页 ── ai.config.* ──IPC──▶   aiAssistant.js                     OpenAI 兼容 /chat/completions
问答侧栏 ─ ai.chat(…) ──IPC──▶     · 配置与 Key（safeStorage 加密）──▶ Anthropic /v1/messages
         ◀─ ai2050:ai-event ─      · 流式调用、取消、预算
页面登记上下文（useAiContext）      · 本机记录 ai_logs/*.jsonl
```

- **Key 只在主进程**：页面拿不到 Key，只能看到「已设置 · 尾号 ab12」。这和本机节点服务令牌不进页面的做法一致（`nodeSupervisor.js`）。
- **页面只发「问题 + 上下文」**：主进程补上 Key 和配置，发起请求，把增量文本经事件推回页面。
- **IPC 白名单**：preload 只暴露 `ai.config.get / save / remove / test`、`ai.chat / cancel` 和事件订阅，不暴露任意 HTTP 能力。

## 3. 模型配置

可以保存多个配置（profile），其中一个为缺省。字段如下：

| 字段 | 含义 |
| --- | --- |
| `name` | 显示名，如「DeepSeek」「本机 Ollama」 |
| `provider` | `openai`（OpenAI 兼容接口：OpenAI、DeepSeek、通义、Kimi、本机 Ollama / vLLM 等）或 `anthropic` |
| `base_url` | 如 `https://api.openai.com/v1`、`https://api.anthropic.com`、`http://127.0.0.1:11434/v1` |
| `model` | 模型名，如 `gpt-4o-mini`、`deepseek-chat`、`claude-sonnet-5-5` |
| `max_tokens` | 单次回答上限（缺省 2000） |
| `temperature` | 缺省 0.3 |
| Key | 只写不读：保存时加密，之后只显示是否已设置与尾号 |

- **存储**：`<userData>/ai_assistant.json`。Key 用 Electron `safeStorage` 加密（Windows 上是 DPAPI，绑定当前系统用户）。`safeStorage` 不可用时拒绝保存 Key，不落明文。Key 不进仓库，也不进 `~/.ai2050/ai_rnd_config.json` 以外的任何共享位置。
- **地址规则**：只接受 `https://`；`http://` 只允许 localhost、127.0.0.1、[::1]（本机模型）。地址里不能带用户名或密码。
- **测试连接**：用一条很短的请求检查地址、模型名和 Key，报告耗时与错误原文（Key 打码）。
- **全局设置**：每日 token 上限（缺省 200,000；按服务返回的用量累计，没有用量时按字符数 ÷ 2 估计）。超过上限时拒绝新请求，第二天自动恢复。
- **旧配置导入**（P2）：读取 `~/.ai2050/ai_rnd_config.json` 的主模型（本机研究服务 `server/ai_rnd_service.py` 用的配置），一键转成一个 profile。

## 4. 页面上下文

页面通过 `useAiContext({ kind, id, title, data })` 登记「当前看的是什么」。问答侧栏读取最近登记的上下文：

| 页面 | kind | 内容 |
| --- | --- | --- |
| 空间 · 语言图谱 · 语言项 | `lang_item` | 语言项说明、各模型等级、当前拼图（读出位置、峰值层、留出间隔）、行为门、规则、前几条对照例句 |
| 空间 · 神经元 · 单元 | `neuron_unit` | 模型、块、单元号、分型、强激活率、主导符号区、正极命中 token、直接读出首位 token、解释等级、对应的模板选择性 |
| 研发 · 神经元测试 · 报告 | `goodfire_probe` | 判据、各步数值与是否通过、两极上下文摘录、S6 词表读出、S7 / S8 / S9 结果（本机结果） |

- **发送前可见**：侧栏在发送前显示上下文的标题、字符数和目标主机（「将发送给 api.deepseek.com」），可以取消勾选不附带上下文。
- **本机结果要明确同意**：`goodfire_probe` 是本机测试结果，不在公开数据包里。附带它时侧栏注明「本机结果，会发送给 <主机>」。
- **长度上限**：上下文序列化后超过 12,000 字符时截断，并在侧栏注明已截断。
- **系统提示词**：固定说明项目术语（hs 序号、读出位置、行为门、留出复现、证据等级）和边界：只根据给出的数据回答，区分「数据显示」与「推测」；推测要写成可检验的形式；不把 AI 的话说成证据。

## 5. 问答（P1）

- 研究工作台右下角「问 AI」按钮（桌面客户端），打开右侧栏；网页版不显示。
- 会话内多轮对话，切换上下文时提示「上下文已变为 …」。流式显示，可以随时停止。
- 每条回答下方注明：配置名、模型、用量、耗时，以及「AI 回答 · 未检验，不是证据」。
- 没有配置时，侧栏引导到「研发 → AI 助手」设置页。

## 6. 记录与复现

每次请求在 `<userData>/ai_logs/<日期>.jsonl` 追加一行：时间、配置名、provider、模型、主机、上下文 kind / id / sha256 与长度、问题、回答、用量、耗时、错误。不记录 Key。这对应 AGENTS.md §10.3「保留原始结果、各模型分析及最终决策依据」。设置页显示今日用量，并可打开记录目录。

## 7. 研发辅助（P2）

在问答之上加只读工具和「起草」动作。AI 只能提议，写入都由用户点击完成：

- **只读工具**（function calling）：查询本机数据包里的语言项、神经元层摘要与单元卡、谱图、记分板。工具在页面执行（数据在 IndexedDB），结果再交给模型。
- **起草文法**：AI 生成 `template_grammar.v1` 草稿，用户点「在模板工作室打开」后照常预览、试跑、冻结。冻结仍要管理员。
- **起草最小对**：为神经元测试的 S9 生成「A || B」对，填进测试表单，由用户检查后运行。
- **谱图假设**：本地生成「未检验」假设并保存在本机；管理员可以提交到中心的 `atlas/hypotheses.jsonl`。公开中心没有 AI 模块，现在 `/api/atlas/interpret` 在那里不可用，客户端本地解读可以替代它。

## 8. 研发循环（P3）

对应 AGENTS.md §10.3 的自动研发循环。

- **组成**：主模型负责规划与整合，辅助模型做复核。分手动和自动两种模式，有预算、队列与恢复。
- **可用的动作**：起草文法、在本机运行神经元测试（经节点服务）、读取结果、写本机研究笔记。
- **需要逐次确认的动作**：冻结、审计、上传。
- **分轨显示**：与「贡献算力」的分布式运行分开显示，不共用状态。

## 9. 分期与验收

| 期 | 内容 | 验收 |
| --- | --- | --- |
| P1 | 模型配置（多 profile、Key 加密、地址规则、测试连接、每日上限）、问答侧栏（流式、停止、多轮）、三类页面上下文、本机记录 | 假模型服务上的单元测试：两种 provider 的流式解析、Key 不出现在公开配置与记录里、地址规则、预算、取消；浏览器里走通设置 → 提问 → 流式回答 → 停止 |
| P2 | 只读工具、起草文法与最小对、谱图假设、旧配置导入 | 工具调用往返测试；草稿只能经用户点击进入工作室与测试表单 |
| P3 | 研发循环 | 预算耗尽、取消、恢复与「未检验」标注的测试 |

## 10. 安全

- Key 只在主进程内存与加密文件里；日志、错误信息、页面里都不出现。错误信息中的 Key 打码。
- 页面只能调用白名单 IPC；主进程只向配置的 `base_url` 发请求，不接受页面传入的任意地址。
- 回答按纯文本显示（保留换行），不执行、不渲染 HTML。
- AI 不能直接调用会写入中心或运行任务的接口；P2 / P3 的动作都要用户确认。
