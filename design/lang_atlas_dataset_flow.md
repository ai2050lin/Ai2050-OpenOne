# 语言图谱 · 数据集实测流程（lang_atlas.v1）

> 修订缘起：原方案把「模式目录」当入口，先看 14 个语言现象的卡片，再说机制。
> 这个顺序错了——它从「已经认定有意义的模式」出发，而用户真正要问的是：
> **在某一批题目上，语言能力到底靠什么算出来的？哪些头是所有能力共用的，哪些只属于一种能力？**
>
> 新流程：**先选数据集 → 再对三个类型各测一遍 → 最后跨类型比，把「普遍规律」与「类型专属」分开。**

---

## 1 为什么要先选数据集

数据集不是「换个题库再刷一遍分」。它直接决定结论能不能成立：

| 数据集 | 题量 | 三大类型可选题量 | 说明 |
|---|---|---|---|
| CMExam train | 29 492 | 0 | 纯医学，无法映射到三大类型 → 只能做综合基线，**不参与类型对比** |
| CMMLU test | 11 579 | 2 301 | 知识网络 1 487、功能推理 282、语法规则 532 |
| C-Eval val | 169 | 169 | 知识网络 58、功能推理 69、语法规则 42 |

同一批头，在 42 题的语法规则上 t 值是 5.6，在 532 题上可能是 14——**样本量决定你能不能看见它**。
反过来，如果一个头只在 169 题上过阈、在 2 301 题上掉下去，那不是规律，是小样本涨落。
所以「选数据集」这一步的真正作用，是**复现检验**：两个数据集都过阈的头，才算稳定。

## 2 类型 ↔ 科目：显式表，不是模型推断

题库里的 `category` 字段只覆盖 C-Eval 的 169 题；CMMLU 的 11 579 题全被标成「综合知识」。
直接把 `category` 当类型用，会得到「CMMLU 没有三大类型」的错误结论。

实际做法是在服务端写一张映射表（`CATEGORY_SUBJECTS`），把科目按语义归到三个类型，接口把依据一起返回：

| 类型 | C-Eval val | CMMLU test |
|---|---|---|
| 知识网络 | 高中生物 19 + 高中地理 19 + 高中历史 20 | 高中生物 169 + 高中地理 118 + 世界历史 161 + 中国历史 323 + 全球事实 149 + 天文学 165 + 世界宗教 160 + 高中化学 132 + 高中物理 110 |
| 功能推理（分析推理） | 公务员考试 47 + 逻辑学 22 | 逻辑学 122 + 公务员考试 160 |
| 语法规则 | 汉语言文学 23 + 高中语文 19 | 现代汉语 116 + 古代汉语 164 + 小学语文 252 |

这张表是**结论的一部分**，必须可审阅：改动会影响所有下游数字，所以放在服务端常量里、随接口下发，
而不是散在前端或分析脚本里。

## 3 测什么：两个量，一个主一个辅

单选题的答案位置（prompt 末尾的「答案：」之后）有两种可测量：

**主指标 · dla（direct logit attribution）**
把每个注意力头在答案位置的输出，经 `o_proj` 分块还原成它对残差的贡献，再与「该选项字母」的
unembedding 方向点积，得到**这个头把这个字母推上去多少**。

```
c_h = W_O[:, h·d_head:(h+1)·d_head] · head_out_h        # 该头对残差的贡献
dla_h(letter) = c_h · (g ⊙ W_U[letter])                  # 与读出方向对齐（g = final norm 的增益）
net_h = dla_h(正确) − mean(dla_h(干扰))
```

为什么用它作主指标：它是连续量、可加和，并且**不受「注意力总量很小」的干扰**。
实测中答案位置对选项文本的注意力总质量中位数只有 0.05–0.2，用「注意力最大落在哪个选项」判断，
信号基本被噪声吃掉。

**辅指标 · 落点（hit）**
该头注意力质量最大的选项，恰是正确选项的比例。四选一随机基线 0.25。
它只说明「这个头有没有在看选项」，**不作承载判据**——一个头可以落点很准但贡献很小（实测 L30H6：
hit 0.40，全局贡献只有 3.65）。

**归一化**
`net` 用**层内**归一化（除以该层头的平均绝对贡献）。原因：深层的绝对贡献天然更大（离输出更近），
用全局分母会让「通用头全在最后几层」变成一个归一化假象。层内归一化把「这一层里谁最强」单独拎出来，
再用 `net_global` 单独报告绝对量级，两个数分工不同。

## 4 判据：什么算「普遍规律」

对每个 (层, 头)，在**每个类型内**做跨题 t 检验：

```
t = mean(net) / (std(net)/√n)
```

- 同一头在 **≥2 个类型**上 t 同号且 `|t| > 4.0` → **普遍头**
- 只在 1 个类型过阈，且反方向无强头 → **类型专属头**
- 阈值 4.0 按 1152 个头（36×32）做 Bonferroni 修正（双侧 α≈0.05 → ≈3.9）

判据写死在服务端 `_aggregate()`，界面不重算、不允许人工挑选头。**这条纪律比结果重要**：
一旦允许「我看着像就记一条」，图谱就退化成观点。

## 5 实测结果

### 5.1 行为基线

| 类型 | C-Eval val（n=58/69/42） | CMMLU test（n=1487/282/532） |
|---|---|---|
| 知识网络 | 82.8% | 73.9% |
| 功能推理 | 72.5% | 74.8% |
| 语法规则 | 71.4% | 56.4% |

CMMLU 的语法规则只有 56.4%，比 C-Eval 低 15 个百分点。原因是科目构成不同：CMMLU 的语法规则含
古代汉语 164 题与小学语文 252 题，前者的文言用法在后训练数据里更稀薄。**这不是机制失效**——
同一批头在 CMMLU 语法规则上的 t 值仍是 −17.1/+17.3，机制照常在跑，掉的是知识覆盖。

### 5.2 普遍规律

C-Eval val 全量 169 题、18 秒、扫描 1152 个头：

**28 个普遍头，全部落在 L24–L35，前 24 层一个都没有。**

| 头 | 知识网络 | 功能推理 | 语法规则 | 方向 |
|---|---|---|---|---|
| L34H29 | −12.9 | −9.4 | −6.4 | 压制 |
| L24H31 | +12.1 | +9.2 | +6.3 | 推高 |
| L34H28 | +11.8 | +9.5 | +5.8 | 推高 |
| L30H6 | +11.4 | +6.6 | +5.7 | 推高 |
| L34H30 | +11.4 | +9.5 | +5.8 | 推高 |
| L24H29 | +11.3 | +7.8 | +6.0 | 推高 |
| L35H24 | −10.5 | −9.2 | −6.2 | 压制 |
| L35H27 | −10.5 | −8.8 | −5.6 | 压制 |
| L35H25 | +9.7 | +8.7 | +5.3 | 推高 |

三层读法：

1. **答案收口集中在最后三分之一网络。** 36 层模型的 L24–L35 承担了全部跨类型一致的答案选择，
   前面 24 层没有共同结构。这意味着「知识网络 vs 语法规则」的差别不在早期层，而在收口层怎么读。
2. **同一层内存在正负对抗。** L34 的 H28/H30 推高、H29 压制，三类型的符号都一致。
   最自然的解释是「取证据」与「排除干扰」分工，但这是假设，还没做消融。
3. **t 值随类型单调递减**：知识网络 −12.9/+12.1 → 功能推理 −9.4/+9.2 → 语法规则 −6.4/+6.3。
   三个类型的行为正确率是 82.8/72.5/71.4，同序。所以这批头更像「在答对的题上推答案」，
   而不是「承载知识本身」——这也正是它跨类型普遍的原因。

### 5.3 复现：换数据集，同一批头还在

CMMLU test 全量 2301 题（知识网络 1487、功能推理 282、语法规则 532），耗时 731 秒：

| 量 | C-Eval val（169 题） | CMMLU test（2301 题） |
|---|---|---|
| 普遍头数 | 28 | ≥40（展示截断到 40） |
| 最强头 | L34H29（−12.9 / −9.4 / −6.4） | L34H29（−47.5 / −20.6 / −17.1） |
| 普遍头层范围 | L24–L35 | L24–L35 |
| 前 24 层普遍头 | **0** | **0** |

**C-Eval 的 28 个普遍头，在 CMMLU 上 28 个全部复现。** 两个数据集的题量差 13 倍、科目构成不同、
题目长度不同，交出的普遍头集合却完全包含——这是「答案收口集中在最后三分之一、且跨语言能力类型共用」
这一结论目前最硬的证据。

同时注意 t 值的绝对量级从 12.9 涨到 47.5：样本量从 58 到 1487，t 按 √n 放大，符合预期。
这说明 169 题上「刚好过阈」的头并不可靠（3.9 的阈值在 n=42 时很容易被涨落推过），
**只有两个数据集都过阈的才写进结论**。

### 5.4 类型专属头

11 个，其中 5 个归功能推理，且集中在 **L32/L33**（L32H8、L32H9、L33H15、L33H31、L24H5）。
这是「分析推理」有自己专用层的一个具体线索，也是下一步该做消融的第一批候选。

**但这一条必须先打折扣再看。** 在 CMMLU 上，专属头变成了 40 个里绝大多数归「知识网络」
（L33H23、L35H9、L26H25、L25H15、L33H10 …），原因是知识网络在 CMMLU 有 1487 题、
功能推理只有 282 题、语法规则 532 题——**样本量大的一类更容易「独占」专属头**。

所以「谁有专属头」这个结论，在小样本类型上是不可靠的。正确的读法是：
- 通用头（跨类型同号显著）**稳定**，两个数据集都复现；
- 专属头的归属**受功效支配**，只有在该类型样本量与其他类型可比时才能解读。

这条也解释了为什么必须先选数据集：**同一套指标，换数据集会换出一批不同的「专属」结论**，
而通用结论不动。这正是把「普遍规律」和「数据集特性」分开的唯一办法。

## 6 界面流程

入口改在语言图谱的**第一屏**，三个数字步骤：

```
① 选数据集        卡片：题量 / 科目数 / 三类型可选题量 / 是否可测（不可测的置灰并说明原因）
② 选类型与样本量   三个类型勾选（各自显示可用题量）+ 每类题数（全部 / 10 / 20 / 40）+ 开始实测
③ 结果与普遍规律   三类型正确率卡 → 判据说明 → 结论句 → 层分布条 → 普遍头表 + 专属头表
```

头表每次点击展开两个量（层内相对推力、全局量级），并给出读法；表格按 t 值着色，
正（推高）蓝、负（压制）橙——**不画注意力热图**，因为注意力图漂亮但会误导（见 §7）。

原有的「模式目录 A–F」保留为第二个标签页：它适合单点取证，不适合做入口。

## 7 边界（写进界面折叠面板，不藏起来）

1. **dla 是线性化量。** RMSNorm 严格非线性，用该位置 rms 作常数是标准近似，只看头间相对大小，不当绝对 logit 用。
2. **相关不是因果。** 贡献大 ≠ 模型必须用它。判定承载要消融该头看正确率与 Δlogit 掉多少——**还没做**，
   所以界面上写「参与」，不写「承载」。
3. **只测了一种能力用法。** 选字母依赖「选项文本可读 + 与题干匹配」，不覆盖生成、翻译、多步推理。
4. **样本量影响结论。** 对比两个数据集的结果，只有都复现的头写进规律。

```bash
# 跑 C-Eval 三大类型全量（169 题，约 20 秒）
curl -s -X POST "http://127.0.0.1:5001/api/lang/atlas/run?dataset=C-Eval%20val&categories=%E7%9F%A5%E8%AF%86%E7%BD%91%E7%BB%9C&n_per_category=0"

# 看进度与结果
curl -s "http://127.0.0.1:5001/api/lang/atlas/status"
```

结果落盘：`data/lang_bench/atlas_last.json`。

## 9 一个必须记住的坑

`server/lang_atlas_service.py` 里对 `live_analysis_service` 的导入必须走
`from server import live_analysis_service as las`。

写成裸名 `import live_analysis_service` 会创建**第二份模块副本**：它有独立的 `_state`，
读到 `status=idle`，于是试图再加载一份 Qwen3-4B 权重，把 16 GB 显存打满，实测卡在 `loading` 不动。
同样的 bug 在 `lang_bench_service.py` 里也存在，已一并修掉。
