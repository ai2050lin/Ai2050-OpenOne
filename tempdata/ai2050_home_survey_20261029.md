## 4 建议动作

**先停服务，再删，然后让客户端重启服务**（运行中删 `service.json` 会让旧进程与新进程端口/令牌不一致）。

```powershell
# 1. 停节点服务（客户端「本机节点」里的停止按钮更安全；否则结束进程树）
Stop-Process -Id 13676, 35196 -Force -ErrorAction SilentlyContinue

# 2. 保住 2 个未上传成功任务的结果，其余任务目录清空
$k = 'C:\Users\Admin\.ai2050\node_service\work\tasks'
Get-ChildItem $k -Directory | Where-Object { $_.Name -notin 'T-0e7a46e1b4','T-2eece84f4b' } | Remove-Item -Recurse -Force

# 3. 清 native_fields（整目录；当前版本的数据 D:\ai2050_native 已有，旧版本已被取代）
Remove-Item 'C:\Users\Admin\.ai2050\native_fields' -Recurse -Force

# 4. 重启：打开桌面客户端 → 节点页 → 启动本机节点
```

只清任务、暂不动 native_fields（回收 11 GB）就跳过第 3 步。

## 5 顺带发现的两个设计问题

1. **任务工作区没有保留策略。** `node_service.py` 通篇没有 `cleanup/prune`，`work/tasks` 只增不减：12 小时 172 个任务就堆了 11 GB。按这个速度，跑一个月约 600 GB。应在 `complete` 成功后按「保留最近 N 个 + 永久保留 failed」清理。
2. **上传失败的结果是单点。** 2 个 failed 任务的 `outputs/` 只存在于本机，`history.jsonl` 里只有错误原因没有重投机制，一旦清目录就彻底丢失。应在 `failed` 时把 `outputs` 移到 `work/orphans/` 并给出重试入口。
3. **`~/.ai2050` 与 `D:\ai2050_native` 职责重叠。** 前者是客户端节点缺省目录，后者是服务端/脚本缺省目录（`server/*.py` 默认 `D:/ai2050_native`）。同名同结构、无任何交叉引用，靠人记。建议让节点也走 `AI2050_NATIVE_DIR`，只留一个根。
